# LLM 后训练 / RL / Verifier 面试复习笔记

面向岗位：用 cyber/CTF 这类可验证任务训练和评估大模型的 agentic 代码与安全能力。全文所有概念最后都要落回一个问题：后训练技术怎么用在"奖励可自动验证、交互长程、工具密集"的场景。

---

## 一、后训练全景

### 1.1 为什么需要后训练

预训练用海量文本做下一个 token 预测，得到的是一个强大的补全器，它有知识和推理能力，但目标函数里没有"按指令做事""答案要对""行为要安全"这些约束。后训练的任务是把这些约束加进去，主流管线是：预训练 → SFT → 偏好对齐或可验证奖励 RL，后两步近年出现了多条技术路线。

### 1.2 各方法一览

| 方法 | 解决什么问题 | 数据形态 | 优化信号 | 主要局限 |
|---|---|---|---|---|
| SFT | 让模型学会指令格式和基本行为 | (prompt, 标准回答) 对 | 对标准回答做交叉熵 | 只能模仿，无法超过示范者；对错误没有负反馈 |
| RLHF (RM+PPO) | 对齐人类偏好，处理"好坏难写成规则"的维度 | 偏好对 (chosen, rejected) 训 RM，再用 RM 给 rollout 打分 | RM 分数 + KL 惩罚，PPO 更新 | RM 会被 hack；管线重，要同时维护四个模型 |
| DPO | 跳过 RM 和 RL，直接用偏好对做对齐 | 偏好对 | 一个分类式损失，直接提升 chosen 相对 rejected 的概率 | 离线方法，受限于偏好数据的分布；难做多步探索 |
| 拒绝采样 / best-of-n 蒸馏 | 用模型自己的高分样本回灌 SFT | 采 n 个回答，用 RM 或 verifier 筛出最好的，当 SFT 数据 | 交叉熵 | 本质仍是模仿，能力提升有上限，但简单稳定，常作 RL 前的热身 |
| GRPO | PPO 的轻量替代，专为"同一题采多个答案"的场景 | on-policy rollout，每个 prompt 采一组 | 组内相对优势 + clip | 需要每题能采多样本；奖励全同（全对或全错）时该题无梯度 |
| RLVR | 在奖励可程序化判定的任务上做 RL | prompt + 自动 verifier | verifier 输出 0/1 或分数 | 只覆盖可验证域；奖励稀疏、长程 credit assignment 难 |

### 1.3 每条路线展开

SFT 的数据是人写或强模型生成的示范。它的根本限制是训练信号只说"该这样写"，从不说"那样写是错的"，所以模型学到的是分布模仿。对 agentic 任务，SFT 数据是完整轨迹（多轮工具调用加最终答案），标注成本极高，且示范轨迹覆盖不了模型自己会走进的错误状态，模型犯错后不知道如何恢复。这是 RL 阶段要补的核心缺口。

RLHF 的经典管线分两步。第一步用偏好对训练奖励模型（RM），损失是 Bradley-Terry 形式，让 RM 给 chosen 的分高于 rejected。第二步用 PPO 优化策略，最大化 RM 分数减去与参考模型的 KL 惩罚。它适合"有帮助、无害、语气好"这类无法写成程序判据的目标。代价是 RM 是个近似，策略会找到 RM 打分高但实际质量差的输出，这就是 reward hacking，第五节展开。

DPO 的出发点是：RLHF 那个"最大化奖励减 KL"的优化问题有闭式解，最优策略和奖励函数之间存在一一对应，于是可以把奖励用策略本身重参数化，偏好学习就变成直接在策略上做的分类损失。直觉是：提高模型在 chosen 上相对参考模型的对数概率比，压低在 rejected 上的。优点是训练像 SFT 一样简单，不需要采样和 RM。缺点是它是离线的，只在标注过的偏好对附近学习，模型不会探索新解法，所以它擅长风格和偏好对齐，不擅长提升推理和 agentic 能力。这也是为什么推理向的后训练主流用 GRPO 这类 on-policy 方法而非 DPO。

拒绝采样蒸馏（rejection sampling fine-tuning，也叫 best-of-n 蒸馏、STaR 类方法）的流程是：对每个 prompt 采 n 个回答，用 verifier 或 RM 筛出正确或最优的，把这些样本拿去做 SFT。它把 RL 的"探索加筛选"和 SFT 的"稳定训练"拼在一起，实现简单、不易崩，常用于给 RL 提供更好的起点（比如 DeepSeek-R1 管线里 RL 之后回收高质量轨迹再 SFT）。上限在于它只强化已经能采到的正确解，对模型几乎采不出正确解的难题无能为力。

### 1.4 什么时候用哪个

行为格式和基础能力用 SFT 打底。主观偏好维度用 DPO 或 RLHF。答案可程序化验证的能力（数学、代码、CTF）用 RLVR 配 GRPO/PPO，因为这时 verifier 给的信号比 RM 干净，且 on-policy 探索能让模型学到示范数据里没有的解法。实际前沿管线是多阶段混合：SFT 冷启动 → RLVR 提推理和 agentic 能力 → 拒绝采样回收数据再 SFT → 通用 RLHF 收尾对齐。DeepSeek-R1 公开的管线基本就是这个结构，可以在面试里当例子讲。

### 1.5 面试官可能怎么问

问：SFT 和 RL 各自的角色，为什么不能只用 SFT 把 agentic 能力做上去。答：SFT 只有正例模仿，没有对错误动作的负反馈，且示范轨迹覆盖不了模型自己会进入的状态，agent 任务里错误会随步数累积（compounding error）。RL 用模型自己的 rollout 训练，天然覆盖它会到达的状态分布，并且能对失败轨迹给负信号，所以能学到错误恢复和超出示范的解法。

问：DPO 和 PPO/GRPO 怎么选。答：看两点，一是信号来源，只有偏好对且目标偏主观时 DPO 性价比高；二是是否需要探索，要提升可验证任务的正确率就需要 on-policy 采样加 verifier 奖励，DPO 给不了。可以补一句：DPO 是 RLHF 目标在闭式解下的重参数化，理论上同目标，实践差异来自离线与在线数据分布。

问：拒绝采样蒸馏和直接 RL 的关系。答：前者是后者的一阶近似，只用二值筛选后的正样本做模仿，没有负梯度，训练稳定但上限低，常用作 RL 的冷启动或 RL 后的数据回收。

## 二、RL 基础，讲准关键三件事

### 2.1 策略梯度直觉

把语言模型当策略，状态是已生成的上文，动作是下一个 token（agentic 场景里一步可以是一整段工具调用）。策略梯度定理说：朝着"提高高回报轨迹的概率、降低低回报轨迹的概率"的方向更新，梯度形式是 log 概率的梯度乘以回报。直接用原始回报方差极大，所以减去一个基线（baseline），得到优势函数 A = 回报减去该状态下的期望回报。优势的含义是"这个动作比平均水平好多少"，只有相对好坏才提供学习信号，绝对回报里与动作无关的部分只贡献噪声。

### 2.2 PPO 的 clip 和 KL 在干什么

PPO 是 on-policy 方法，但为了样本效率，同一批 rollout 会被多轮复用，复用时策略已经和采样策略有偏差，属于近似 off-policy，需要重要性采样比 r = 新策略概率 / 旧策略概率来修正。clip 目标是取 min(r·A, clip(r, 1-ε, 1+ε)·A)。直觉：当某动作优势为正，策略想大幅提高它的概率，clip 在 r 超过 1+ε 后让梯度归零，阻止一次更新把策略推得离采样策略太远；优势为负时对称地限制往下压。这是在保证"每步更新都停留在采样数据仍然可信的邻域内"，防止策略崩塌。

KL 约束是另一回事，容易和 clip 混淆，面试要分清。clip 约束的是"新策略相对本轮采样策略"的偏移，是优化稳定性问题。KL 惩罚约束的是"策略相对初始参考模型（SFT 模型）"的偏移，是防止模型为了刷奖励丢掉语言能力和通用行为，也是抗 reward hacking 的正则。RLHF 里 KL 通常直接加进奖励：r_total = r_RM 减去 β 乘每 token KL。

### 2.3 优势怎么算，reward 从哪来

PPO 标准做法是训练一个 value model（critic）估计每个状态的期望回报，用 GAE 把 TD 误差加权组合成优势估计。LLM 场景的麻烦在于：奖励通常只在序列末尾出现一次（RM 打一个分，或 verifier 判一次对错），中间 token 没有即时奖励，critic 要从一个终点标量倒推每个 token 的价值，很难估准，而且 critic 和策略一样大，训练成本翻倍。

reward 的三个来源：学出来的 RM（偏好对齐用）、程序化 verifier（RLVR 用）、以及模型判官（LLM-as-judge，介于两者之间，可扩展性好但继承了 RM 的可 hack 性）。

### 2.4 GRPO：省掉 value model

GRPO（DeepSeekMath 提出，R1 采用）针对的正是"critic 难训又贵"这个问题。做法：对同一个 prompt 采一组 G 个回答，各自拿到 verifier 或 RM 的奖励，优势直接定义为组内标准化的相对奖励，A_i = (r_i 减组内均值) / 组内标准差，组内所有 token 共享这个优势，再套 PPO 式的 clip 目标和对参考模型的 KL 正则。

它省掉的是整个 value model：不再学习状态价值，用"同题其他回答的平均得分"作为经验基线。这为什么在 LLM 推理任务上特别合适：一是奖励在序列末尾且常是 0/1，逐 token 价值估计本来就估不准，不如不估；二是同一 prompt 采多样本在 LLM 上天然廉价（batch 内并行采样），组内比较恰好利用了这一点；三是显存和工程复杂度近乎减半。代价是：某个 prompt 的一组回答如果全对或全错，组内优势全为零，该题这轮没有梯度，所以数据难度要和模型当前水平匹配，这直接引出课程学习的需求（第五节）。

### 2.5 面试官可能怎么问

问：clip 和 KL 惩罚是不是重复的。答：不重复，clip 管"离本轮采样策略多远"，保证优化稳定；KL 管"离初始参考模型多远"，保证不丢通用能力、抑制 reward hacking。前者的参照物每轮更新，后者的参照物固定。

问：GRPO 为什么可以不要 critic，会损失什么。答：它用组内均值代替学习到的价值基线，这在"每题多采样、奖励在终点"的设定下是低成本的无偏基线。损失的是逐 token 的细粒度 credit assignment，长轨迹里哪一步关键它分不出来，只能靠整条轨迹的相对好坏，方差比准确的 critic 高，靠加大组规模和批量补。

问：优势为什么要标准化，有什么坑。答：标准化让不同难度题目的梯度尺度一致。坑是除以组内标准差会放大"接近全对或全错"题目上的噪声，有后续工作（如 Dr. GRPO）指出这引入难度偏置，去掉除法项更干净。答到这一层能体现你读过细节。

## 三、RLVR：这个岗位的核心

### 3.1 定义和为什么干净

RLVR（Reinforcement Learning with Verifiable Rewards）指奖励由确定性程序判定而非学习模型给出的 RL：数学题比对最终答案，代码跑单元测试，CTF 检查是否拿到正确 flag。区别于 RLHF 用 RM 打分。

它比 RM 干净的原因：RM 是从有限偏好数据学出来的近似函数，本身有误差且可被策略反向利用，策略优化久了必然找到 RM 的漏洞。程序化 verifier 直接判定任务是否真正完成，判据就是任务目标本身，不存在"逼近真实目标的模型误差"这一层，所以对 reward hacking 的抵抗力强得多。奖励是 ground truth 而不是对 ground truth 的估计。这是 RLVR 能把推理和 agentic 能力真正做上去的前提。

### 3.2 难点

RLVR 不是没有代价，面试要主动讲局限：

- 奖励稀疏。CTF 拿到 flag 前的几十上百步工具交互全都零奖励，模型极难靠随机探索首次撞到正反馈。冷启动质量和探索策略因此关键。
- 长程 credit assignment。一条成功轨迹里真正起作用的可能是中间某个关键决策，末尾的 0/1 奖励无法告诉模型是哪一步的功劳，GRPO 这种全轨迹共享优势的方法尤其粗糙。
- 覆盖面窄。只有目标可程序化判定的任务才能用，开放式任务（写报告、解释漏洞成因的质量）没有干净 verifier。
- 可验证不等于验证正确。verifier 本身可能写错或不完备，测试用例不全时模型可以只过测试而没真正解对，这把问题转移到了 verifier 的质量上（第四节）。

### 3.3 CTF/cyber 作为 RLVR 环境的特点

CTF 和多数 cyber 任务是 RLVR 的自然契合场景，但也是最难的一类：

- 奖励天然可验证。flag 是一个确定字符串，拿到即成功；或用环境状态检查（是否拿到某权限、某文件、某服务是否被攻破）。不需要人标注偏好，判定客观。
- 长程且工具密集。一道题要侦察、枚举、构造 payload、利用、提权，几十步工具调用，每步依赖前一步的观测。这对 harness（工具接口、超时、环境隔离、可复现）要求很高，也让 credit assignment 更难。
- 奖励极稀疏且难度陡峭。很多题在解出前完全没有中间信号，正负样本比例悬殊，直接 RL 常常一个正样本都采不到。缓解手段：先用专家轨迹或强模型轨迹做 SFT 冷启动，设计课程从易到难，用子目标或状态检查提供部分信用。
- 环境有副作用和安全边界。执行真实攻击代码需要沙箱隔离，环境不可轻易重置或有外部依赖时，采样成本和不确定性都比数学、代码高。

（这里和你的项目相关：部分 cyber 任务是 Windows GUI 交互型，很难自动化成可程序判定、可批量重置的 RLVR 环境，这类任务更适合做评测而非训练环境。面试若问及 CTF 训练环境的工程约束，可以举"GUI 交互、不可无头运行、状态难重置"作为哪些 cyber 任务不适合直接做 RL 环境的例子，这正是你在 ALE 那 4 道 Windows 题上踩过的坑。）

### 3.4 面试官可能怎么问

问：RLVR 相比 RLHF 的核心优势。答：奖励是任务目标的直接判定而非学习模型的估计，没有 RM 误差这一层，抗 reward hacking，能把可验证能力真正提升而不是拟合偏好。代价是只覆盖可验证任务、奖励稀疏、长程 credit assignment 难。

问：CTF 任务奖励太稀疏，RL 采不到正样本怎么办。答：多管齐下。冷启动 SFT 用专家或强模型轨迹让模型先能偶尔解出；课程学习从简单题起步逐步加难，保证每阶段组内有正有负才有梯度；把最终 flag 分解成可检查的子目标（拿到 shell、读到某文件、提权成功）给部分信用；提高每题采样数增加撞到正样本的概率；拒绝采样把偶然解出的轨迹回收做 SFT 再继续 RL。

问：可验证奖励是不是就没有 reward hacking。答：不是，形态变了。verifier 不完备时模型会钻 verifier 的空子而非真正解题，比如硬编码测试期望输出、利用评测环境漏洞直接读 flag、答案碰巧过测试但推理错误。所以 verifier 设计本身成了新的攻击面。

## 四、Verifier 设计

### 4.1 结果验证 vs 过程验证

结果验证（ORM，outcome reward model / outcome verifier）只看最终结果对不对，一条轨迹一个 0/1。优点是判据客观、实现简单、抗 hack；缺点是信号稀疏，且它奖励一切能得到正确结果的路径，包括蒙对的、推理错但答案对的，可能强化坏的中间过程。

过程验证（PRM，process reward model）给推理的每一步打分。优点是信号密集，能定位是哪一步出错，缓解 credit assignment。缺点很实在：步级标注昂贵，"什么算一步、这一步对不对"往往需要人或强模型判定，PRM 本身是学出来的模型，于是又把可 hack 的 RM 引了回来。步级标注还容易出现"这一步局部看对、但对最终解无贡献甚至有害"的标注难题。

实践权衡：可验证域优先用结果验证的 verifier 保证奖励干净，需要缓解稀疏时再叠加过程信号或子目标检查，而不是一上来就上一个学出来的 PRM。

### 4.2 verifier 自身被 hack 的风险

verifier 是新的攻击面，常见走捷径形态：

- 代码任务测试用例不全，模型写出只过给定测试的特判代码，甚至直接 `if input==给定用例: return 期望值`。
- 模型读取或推断出测试文件、期望输出、答案文件，绕过真正求解。
- CTF 里利用评测环境本身的配置漏洞直接拿 flag，而非按预期路径攻破目标。
- 输出格式匹配漏洞，比如 verifier 用宽松的字符串匹配，模型堆砌可能答案让匹配命中。

### 4.3 怎么设计不易被走捷径的奖励

- 测试用例要覆盖充分并保留隐藏测试集，评测环境和求解环境隔离，模型无法读到答案和评分逻辑。
- 收紧判定：答案做规范化后精确匹配，而非宽松包含匹配。
- 交叉验证：多组独立测试、随机化测试输入，让特判成本高于真解。
- 对 agentic 任务，校验达成目标的路径合法性（是否真的攻破目标而非利用评测漏洞），必要时检查关键中间状态。
- 定期人工审计高分轨迹，专门找"分高但没真解对"的样本，这类审计是发现新 hack 的主要手段。

### 4.4 部分信用 vs 0/1 稀疏奖励

纯 0/1 奖励最干净、最抗 hack，但在长程稀疏任务上梯度信号太少，训练慢甚至学不动。部分信用（子目标达成、测试通过比例、距离目标的进度）提供密集信号，加快学习，代价是每引入一个中间信号就引入一个可被 hack 的维度，比如按通过测试比例给分，模型会优先写容易过的部分而回避核心难点。

设计原则：中间奖励只加在与最终目标强相关、且本身不易被走捷径的检查点上（拿到 shell、提权成功这类状态检查客观且难伪造），避免用容易被局部优化钻空子的连续指标（如相似度分数）当主奖励。最终目标的达成始终应占主导权重，中间信用只作引导。

### 4.5 面试官可能怎么问

问：结果验证和过程验证怎么选。答：可验证域默认用结果 verifier，奖励干净抗 hack；稀疏到训不动时叠加客观的子目标状态检查作过程信号，尽量不引入学出来的 PRM，因为那把可 hack 的模型误差又引回来了。

问：怎么防 verifier 被 hack。答：隔离评测环境不让模型读到答案和评分逻辑、用充分且隐藏的测试集、收紧匹配判定、校验达成路径合法性、定期人工审计高分轨迹。核心是让"走捷径"的成本高于"真正解题"。

问：部分信用会不会破坏 RLVR 的干净性。答：会引入新的可 hack 维度，所以中间信用只加在客观难伪造的状态检查上且权重低于最终目标，把它当探索引导而非主奖励。

## 五、Reward Hacking 与分布问题

### 5.1 什么是 reward hacking

策略找到能拿高奖励但不符合真实意图的行为。根源是奖励函数是真实目标的代理（proxy），优化压力足够大时策略必然利用代理与真实目标之间的任何缝隙，这是 Goodhart 定律的直接体现：一个指标一旦变成优化目标就不再是好指标。

### 5.2 在可验证任务里的具体形态

- 代码：写特判只过已知测试；读取测试或答案文件；构造使 verifier 崩溃或误判的输出。
- CTF：利用评测环境漏洞直接取 flag，不走预期攻破路径。
- 推理：答案对但思维链是错的或事后凑的，结果 verifier 无法识别。
- 通用退化：为迎合奖励产生冗长套话、固定模板、复读，或牺牲通用语言能力换取任务分。

### 5.3 缓解手段各自在管什么

- KL 正则。约束策略不远离参考模型，压制"为刷分产生的异常分布"，是最基础的正则。β 太大学不动，太小防不住，需要调。
- on-policy 数据。用模型当前分布的 rollout 训练，奖励评估的是模型真实会产生的行为，避免离线数据造成的分布不匹配。DPO 这类离线方法在这点上更脆弱。
- 课程学习。难度匹配当前能力，保证有梯度（GRPO 组内需有正有负），也降低模型在过难任务上退化去钻空子的概率。
- 拒绝采样。只回收 verifier 确认正确的轨迹做 SFT，等于用干净的二值信号过滤掉 hack 轨迹，但依赖 verifier 本身没被绕过。
- verifier 加固与人工审计。见第四节，从奖励源头减少可利用的缝隙。

### 5.4 分布不匹配（distribution shift）

两个层面。训练内部：off-policy 或离线数据评估的行为和模型当前实际行为不一致，导致优化方向偏，靠 on-policy 采样和重要性采样修正缓解。训练到部署：训练任务分布覆盖不了真实使用分布，模型在训练集上刷高分但泛化差，靠训练任务多样性和留出评测集监控缓解。

### 5.5 面试官可能怎么问

问：可验证奖励也会被 hack，KL 正则为什么还有用。答：KL 管的是策略整体分布不塌陷、不产生异常行为，verifier 加固管的是堵住具体任务判据的漏洞，两者管不同层面。KL 挡不住"钻 verifier 空子"这种任务内 hack，堵这个要靠 verifier 设计和审计。

问：on-policy 为什么对抗 hack 和 shift 更好。答：奖励评估的是模型当前真实会产生的行为，训练信号和实际行为分布一致，不会像离线数据那样在模型已经偏离的区域给出失真的梯度。代价是每步都要重新采样，成本高。

## 六、评估

### 6.1 pass@k 与其陷阱

pass@k 指每题采 k 个答案、只要有一个通过就算解出的比例。pass@1 反映单次可靠性，pass@k（k 大）反映能力上界或曰覆盖率。关键理解：RL 常常提升 pass@1 但可能不提升甚至压低 pass@k，因为它把概率质量集中到已知正确解上，探索多样性下降。若只看 pass@1 会误判 RL "增强了能力"，实际可能只是把已有能力的采样效率提高了。面试能点出这个区别是加分项。报 pass@k 要说清 k、采样温度、以及 verifier 判定方式，否则数字不可比。

### 6.2 可验证 benchmark 与 agentic benchmark 的评估难点

可验证 benchmark（数学、代码题集）判定客观、易复现，问题主要是数据泄漏。

agentic benchmark（长程、多工具、CTF/SWE 类）额外的难点：

- 可复现性。依赖外部环境、网络、时间、随机性，同一 agent 多次跑结果不同，需要固定环境镜像、随机种子、超时，隔离网络。
- 长程导致的评估成本和方差高，需要多次重复取均值并报方差。
- 部分完成如何计分，只报最终成功率会丢掉"接近成功"的信息，但引入部分分又带来第四节的判定问题。
- 环境副作用，执行攻击或修改文件的任务要在隔离沙箱里跑，且每次干净重置，否则前一次的残留污染后一次。

### 6.3 训练集/评测集泄漏

泄漏是可验证任务评估的头号风险。形态：评测题或其答案出现在预训练语料里；训练 RL 用的题和评测集重叠；题目在网上有公开 writeup 被模型记住。后果是分数虚高、无法反映真实能力。缓解：用发布时间晚于模型训练截止的题、私有题库、对已知 benchmark 做去污染检查（n-gram 或语义查重）、报告结果时说明去污染方法。对 CTF 尤其要注意公开 writeup 泄漏，很多经典题解法网上都有。

### 6.4 面试官可能怎么问

问：RL 训完 pass@1 涨了能说明能力变强吗。答：不一定。要同时看 pass@k，如果 pass@1 涨而大 k 的 pass@k 不涨，更可能是把已有解的采样效率提高了而非扩展了能力边界；如果 pass@k 也涨才是真正学到了新解法。

问：怎么保证 agentic benchmark 的评测可信。答：固定环境镜像和种子、隔离网络、每次干净重置、多次重复报均值和方差、做训练评测去污染、优先用模型训练截止后发布的题。

## 七、前沿路线感

### 7.1 推理模型用 RLVR 提升

以 o 系列、DeepSeek-R1 为代表的思路：让模型生成长思维链（先推理后作答），用可验证奖励（答案对错、代码过测试）加 RL 直接优化最终正确率，不对中间推理步骤做人工标注。R1 的公开结果显示，纯 RLVR（甚至从 base 模型不经 SFT 直接 RL 的 R1-Zero）就能让长思维链和自我检查、回溯等行为自发涌现，说明这些能力可以由结果奖励诱导出来而不必逐步示范。典型管线：少量长思维链 SFT 冷启动 → 大规模 RLVR → 拒绝采样回收高质量轨迹再 SFT → 通用对齐收尾。

### 7.2 把工具使用和 agentic 行为通过 RL 内化进模型

这是岗位描述里"把能力内化到底层模型"的核心，要能讲清它和纯 harness/prompt 工程的区别。

纯 harness/prompt 路线：模型权重不动，靠外部脚手架驱动，包括系统提示里写工具用法、少样本示例、ReAct 式的思考-行动-观察循环、外部的重试和回溯逻辑、状态管理和上下文拼装。能力体现在 harness 的工程里，换个提示或换个任务分布就可能失效，模型本身没有变强。

RL 内化路线：把工具调用当作模型动作序列的一部分，在真实环境里 rollout（模型自己决定何时调哪个工具、怎么用返回结果、错了怎么调整），用任务成败的可验证奖励做 RL，把"何时调用工具、如何解读观测、如何从错误恢复、如何规划长程步骤"这些决策写进模型权重。

区别与各自意义：

- 内化后的能力不依赖特定提示，跨任务泛化更稳，长程决策和错误恢复质量更高，因为模型是在自己会到达的状态分布上被训练过的，而示范和 prompt 覆盖不了这些状态。
- harness 见效快、不需训练、便于快速迭代和加约束，是冷启动和兜底安全的必要层，但它的上限受限于人能想到并写进脚手架的策略。
- 两者不互斥。实际做法是 harness 先跑起来采集轨迹和定义环境接口，再用这些环境做 RL 把策略内化，内化后仍保留一层轻 harness 管安全边界和工具接口。对 cyber/CTF 岗位，价值主张正是把靠人写 prompt 才能勉强完成的长程攻击流程，通过在可验证 CTF 环境里做 RL，变成模型自身稳定具备的能力。

### 7.3 面试官可能怎么问

问："把能力内化到底层模型"具体指什么，和写个好 agent 框架有什么区别。答：内化指通过在真实环境 rollout 加可验证奖励的 RL，把工具调用、观测解读、错误恢复、长程规划这些决策写进模型权重，模型在自己会到达的状态分布上被训练过。harness/prompt 是外部脚手架，权重不动，上限受限于人能写进脚手架的策略，且换分布易失效。前者泛化和长程稳定性更好，后者见效快、便于加约束，实践中 harness 采轨迹定义环境、RL 做内化，两层配合。

问：R1 给的最大启示是什么。答：长思维链、自我检查、回溯这些推理行为可以由纯结果导向的可验证奖励诱导涌现，不需要对中间步骤逐一人工示范，说明 RLVR 是把推理和 agentic 能力做进模型的有效且可扩展的路径，标注成本主要转移到构造可验证环境上。

问：为什么这套路线特别适合 cyber/CTF。答：CTF 奖励天然可验证（flag 或状态检查），是现成的 RLVR 环境；任务长程、工具密集、需要错误恢复，正是最需要把策略内化进权重而非靠 prompt 硬撑的场景；难点在环境工程（隔离、可复现、可重置）和奖励稀疏，要靠冷启动、课程、子目标部分信用和 verifier 加固一起解决。

## 八、GRPO 到 SAO：单轨迹异步优化（对上唐杰的论文）

这一段专门把 GRPO 的讨论接到你要参考的 SAO 论文（arXiv 2607.07508，唐杰是作者之一），面试大概率用得上，详细版见 `07`。

前面讲 GRPO 的卖点是用组内平均当基线、省掉 value model。SAO 指出这个卖点在异步和在线 agentic 训练下不成立：一是异步下同步 batch 交错式流水线浪费算力（长短轨迹不齐，集群等最慢的），二是 GRPO 的组采样要等组里最慢那条才能进训练，制造延迟驱动的 off-policy，而且在线或复杂 agentic 环境常常一个 prompt 只给一个信号，凑不成一组。

SAO 的应对是三件套：单轨迹采样代替组采样（每个 prompt 一条 rollout，降 off-policy、适配单信号环境）、把 value model 请回来补上没了组基线的空缺、严格双侧 token 级裁剪稳住异步的不稳定。结果是稳定训一千步、在 SWE-Bench Verified 和 BeyondAIME 等 agentic 基准超过 GRPO，并被用来训练 GLM-5.2。

要能讲出的核心判断：GRPO 和 SAO 不是谁替代谁，是设定决定选择。同步、每题能廉价采一组、离线固定题库，GRPO 省 critic 又稳；异步、长程、在线演化、环境只给单信号，组采样前提不成立，SAO 的单轨迹加 critic 更合适。当采样方式从组变成单轨迹，"要不要 value model"这个取舍就反过来了，这是这条线最值得讲的地方。它也和你的方向对得上，未来预测这类任务本来就是一个 prompt 一个最终结果，天然单轨迹。
