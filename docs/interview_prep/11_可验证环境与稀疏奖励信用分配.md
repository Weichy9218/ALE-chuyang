# 可验证环境与稀疏奖励下的长程信用分配

这一篇是技术深度笔记，回答两个问题：前沿怎么造出大量可验证、可复现、防作弊的安全和 agentic 训练环境；以及怎么解决这类任务奖励极稀疏、长程信用分配难的问题。带公式、带案例、带分析。主线用安全举例，但方法是通用的，凡是通用结论我都标出来。

先把你那句直觉写严谨。安全任务的成败（拿到 flag、PoC 触发崩溃、补丁过测试）和部分关键过程（拿到 shell、提权成功、命中某分支）是确定性可验证的，所以它同时适合两件事：一是 RLVR，用确定性判定当奖励，不需要学一个奖励模型；二是 reward shaping，把那些可验证的中间里程碑做成密集的塑形奖励，缓解稀疏。这两点分别对应下面第三节和第四、五节。

---

## 一、可验证性给了 RLVR 两样别处没有的东西

RLVR 的奖励来自确定性程序而非学习出来的奖励模型（RM）。写成对比：

- RLHF：奖励 r = RM(x, y)，RM 是从偏好数据拟合的近似函数，本身有误差、可被策略反向利用。
- RLVR：奖励 r = Verify(x, y) ∈ {0, 1} 或按字段的连续分，Verify 是任务目标本身的程序化判定，没有"逼近真实目标的模型误差"这一层。

安全任务把可验证性推到比数学、代码更彻底的程度，因为它是执行即判定：不是比对一个答案字符串，而是真的运行 PoC 看 sanitizer 崩不崩、真的检查系统状态。CyberGym（UC Berkeley，arXiv 2506.02548，1507 个 OSS-Fuzz 真实漏洞）的判据是 PoC 必须在打补丁前触发崩溃、打补丁后正常运行，全程不用 LLM 裁判。这一条既是干净奖励，也是防作弊的地基（第六节）。

安全任务同时满足三个稀缺条件：可验证（奖励客观）、长程（多步工具交互）、强执行反馈。数学题可验证但不长程也不用工具，开放写作长程但不可验证。这个组合是它作为通用 agentic 训练信号性价比高的原因。

## 二、大规模可验证环境是怎么造出来的

核心矛盾：可验证 RL 要吃海量环境，而每个环境要能一键复现、自动判分、干净重置、还不能被污染。前沿的解法沿三条线走。

### 2.1 从真实工件里自动抽环境（软件工程这条线最成熟）

洞察：开源软件的演化史本身就是海量带 ground truth 的可验证信号。一个修 bug 的 PR 天然包含"改之前测试挂、改之后测试过"，这就是免费的判据，不用人标注。

判据形式化为两组测试：

```
Fail-to-Pass (F2P)：修复前失败、修复后通过的测试   →  证明真的修好了
Pass-to-Pass  (P2P)：修复前后都通过的测试          →  证明没引入回归
奖励 r = 1  当且仅当  所有 F2P 通过 且 所有 P2P 通过
```

代表工作按规模递进：

- SWE-bench（arXiv 2310.06770）从 12 个 Python 仓库、2294 个真实 issue-PR 抽取；SWE-bench Verified 是 OpenAI 人工筛出的 500 条干净子集（去掉描述不清、测试过严的）。
- SWE-Gym（arXiv 2412.21139）：第一个"可训练"的 SWE 环境，2.4K 真实任务、11 个仓库，核心是把环境加验证做成可反复执行的训练场并训 verifier。
- R2E-Gym（arXiv 2504.07164）：8.1K 任务，关键是 SWEGEN 管线不依赖人写 issue 和单测，而是直接从 commit 做测试生成加回译（back-translation）来合成可执行环境，再用执行式加无执行的混合验证器做 test-time scaling。
- SWE-smith（arXiv 2504.21798）：给任意 Python 仓库自动建环境，再通过扰动代码注入故障来合成任务，产出 50k 实例、128 个仓库，比前作大一个量级；用它训的 SWE-agent-LM-32B 在 SWE-bench Verified 上 Pass@1 达 40.2%。
- 工业规模：GLM-5 报告构建了跨三域上万个真实可验证环境；Qwen3-Coder 在阿里云上建了可并行运行两万个独立、完全可复现环境的系统，RL 算法用 GSPO（GRPO 的序列级变体），后续把编排系统命名为 MegaFlow。

一句话结论：环境工程就是能力工程，能造出多少可复现的可验证环境，直接决定 RL 能训到多强。SWEGEN 的回译、SWE-smith 的注入故障都说明趋势是从"人工写题"转向"从代码自动合成可验证任务"。这也是你 agent 和环境经验能立刻贡献产能的地方，不必先会调 loss。

### 2.2 安全/CTF 环境的容器化与自动生成

CTF-Dojo（Amazon Science，arXiv 2508.18370）把 658 道 CTF 题全部 Docker 容器化保证可复现，配一个叫 CTF-Forge 的管线把公开赛题几分钟内变成可执行环境，再筛出 486 条执行验证过的成功轨迹做训练。结果是训练后的开源模型在三个 CTF 基准 300+ 任务上达到开源 SOTA，相对强基线最高涨 11.6 个点。

程序化生成是规避污染的关键手段。加密类 CTF 的正确性可程序化验证、题目也可程序化生成，于是能造近乎无限、天然去污染的可验证训练集（Random-Crypto，arXiv 2506.02048，50 个算法族、5000+ 题）。通用类比：凡是"解可验证、题可生成"的任务族，都能用程序化生成把训练数据从有限稀缺变成无限且去污染。

### 2.3 让环境也进化（协同进化）

固定环境会被模型很快吃透、也难覆盖模型当前的能力前沿。前沿方向是让环境和策略一起进化，核心是让环境随 agent 能力边界动态出题，把难度始终维持在"可学"的区间：

- WebRL（THUDM，ICLR 2025，arXiv 2411.02337）：自进化在线课程 RL，三件套是从失败尝试生成新任务的自进化课程、outcome 监督奖励模型、抑制策略分布漂移的自适应 RL。效果 Llama-3.1-8B 在 WebArena-Lite 上 4.8% 提到 42.4%，70B 达 49.1%，超过 GPT-4-Turbo 的 17.6%。这是"稀疏奖励加任务稀缺"用课程自造来解的代表。
- EnvGen（COLM 2024，arXiv 2403.12014）：用 LLM 根据 agent 的薄弱技能生成并持续调整环境配置，亮点是全程只需约 4 次 LLM 调用就能让一个小 RL agent 超过 GPT-4 agent，说明"造对环境"比"堆模型"更省。
- SEAL（协同进化，arXiv 2605.24426）把失败轨迹诊断成 turn 级失败标签，同一信号既驱动环境适配也驱动策略更新，仅 400 条样本在三个 backbone 上涨 8 到 26 分。另一个同名但不同的 SEAL（Self-Adapting LMs，MIT，arXiv 2506.10943）是让模型自己生成微调数据和更新指令、用更新后的下游表现当奖励，属于"模型自造训练信号"这一支。

这一条直接接你 harness 背景：EvoTrainer（arXiv 2606.03108）把"训练侧诊断 harness"和策略一起进化，训练 harness 和 agent harness 是同一种工程能力。

## 三、Reward shaping 的理论根基：塑形不改变最优策略

你提到 reward shaping，它的严谨版本是 potential-based reward shaping（PBRS，Ng, Harada, Russell 1999），这是把"给中间步骤发奖励"这件事做得不跑偏的理论保证。

给一个势函数 Φ: S → R，把原奖励 R 换成塑形后的 R'：

```
R'(s, a, s') = R(s, a, s') + F(s, a, s')
其中  F(s, a, s') = γ · Φ(s') − Φ(s)
```

定理（policy invariance）：这种塑形下的最优策略和原奖励下的最优策略完全相同。直觉证明靠望远镜求和：一条轨迹上所有塑形项累加会坍缩成只和首末状态有关的项

```
Σ_t γ^t F(s_t, a_t, s_{t+1}) = γ^T Φ(s_T) − Φ(s_0)
```

它只依赖起点和终点，不改变不同策略之间的相对优劣排序（终止态势设为 0 时，对每条轨迹只加了一个常数 −Φ(s_0)）。

这个定理的实践意义很重要，也是面试能显深度的点：

- 只要把中间奖励写成 F = γΦ(s') − Φ(s) 的势差形式，你可以放心加密集引导信号，不会把模型带偏到去刷塑形奖励而不完成真任务。
- 反过来，不满足势差形式的中间奖励（比如直接按"通过测试比例"给分、按"和答案相似度"给分）没有这个保证，会引入新的可被 hack 的维度，模型会优先做容易涨分的部分而回避核心难点。这解释了为什么第六节说"中间信用只加在客观难伪造的状态检查上、且权重低于最终目标"。

在安全任务里的落地：把"拿到 shell、提权成功、命中目标分支、PoC 让某 sanitizer 报警"这些可验证的里程碑设计成势函数 Φ 的台阶，Φ 随攻击链推进单调上升，塑形项就把稀疏的最终 flag 奖励摊成沿链条的密集引导，同时理论上不改变"真正拿到 flag"这个最优目标。

局限要老实说：PBRS 保证最优策略不变，但塑形好不好直接影响学得快不快，设计一个好的 Φ 本身需要领域知识；而且它假设 Φ 只依赖状态，实际长程 agentic 任务的"状态"很难精确刻画。

## 四、稀疏奖励的工程解法（先让模型采得到正样本）

稀疏是 RLVR 最硬的问题。一道 pwn 题或一个真实漏洞，模型在拿到 flag 前几十上百步全是零奖励，随机探索几乎撞不到第一个正反馈。而且很多在线 RL 方法需要正负样本共存才有梯度，纯零奖励等于学不动。具体到 GRPO：

```
GRPO 优势  Â_i = ( r_i − mean(r_1..G) ) / std(r_1..G)
若一组 G 个回答全对或全错  →  mean=r_i，Â_i = 0  →  该 prompt 这轮无梯度
```

所以稀疏不仅是"信号少"，还是"整批白采"。解法是一套组合拳，目标都是让模型先能偶尔解出、且每批里有正有负：

1. 冷启动 SFT / 拒绝采样（专家迭代）。先用专家或强模型的成功轨迹做 SFT，让模型能偶尔解出；或采 n 个只保留 verifier 确认正确的做 SFT。CTF-Dojo 的 486 条执行验证轨迹就是干这个。它把 RL 的探索问题外包给了一次性的高质量数据。
2. 课程学习。难度匹配当前能力，从简单题起步逐步加难，保证每阶段组内有正有负才有梯度。上面那个"全对全错则零梯度"有个正式名字叫优势坍缩（advantage collapse），有工作（arXiv 2605.21125）给出诊断指标 Advantage Collapse Rate；DAPO 用 Dynamic Sampling 直接检测并重采零方差的组。所以课程的本质要求是把难度调到"当前策略下有一定但非满分成功率"的区间。GLM-5 报告按难度筛题（GLM-4.7 很少做对、更强模型稳定做对的题才要），WebRL 动态生成"刚好够得着"的任务，都是课程。
3. 子目标 / 里程碑部分奖励。把最终 flag 分解成可检查的子目标（发现注入点、拿到低权限、泄露地址、提权），用第三节的势函数形式发中间奖励，把稀疏摊密。
4. 提高每题采样数。单纯增大 G 提高至少撞到一个正样本的概率，简单但费算力。
5. 稠密可验证代理信号。用覆盖率、是否走到某段代码、距离目标的可测进度当中间信号，注意这些容易被 hack，要按第六节加固。
6. 维持探索。在奖励方差为零或早期没有正样本时，用 per-token 熵构造非零优势（如 RL-ZVP 一类），或加熵正则维持探索，避免过早坍缩到单一无效模式。

通用类比：稀疏奖励在机器人、游戏里也是老问题，经典解法就是这几类，reward shaping、课程、分层子目标、模仿学习冷启动，RLVR 只是把它们搬到了 LLM agent 上。

## 五、长程信用分配：奖励在终点，功劳在中间

一条成功轨迹几十步，只有末尾一个 0/1 奖励，真正起决定作用的可能是中间某一步，怎么把这个延迟信号正确摊派回去，这就是信用分配（credit assignment）。按方法从经典到 LLM 前沿排。

### 5.1 GAE：偏差方差的可调折中（PPO 的标配）

有 value model V 时，用时序差分误差加权组合出优势估计：

```
δ_t = r_t + γ V(s_{t+1}) − V(s_t)                  单步 TD 误差
Â_t^GAE(γ,λ) = Σ_{l≥0} (γλ)^l · δ_{t+l}            指数加权累加
```

λ 是旋钮：λ=0 时 Â_t = δ_t，方差小但偏差大（完全信任 V）；λ=1 时退化成蒙特卡洛回报减基线，偏差小但方差大。λ 在两者间调。GAE 的前提是有一个估得准的 V，这在 LLM 场景恰恰难，因为奖励只在序列末尾、逐 token 价值很难估。

### 5.2 return decomposition 与 hindsight：把延迟拆掉

RUDDER（Arjona-Medina 等，2019）：训一个网络预测整条轨迹的回报，用贡献分析把延迟的最终奖励重新分配到真正贡献的那些步上，等于把长延迟问题变成短延迟，让后续的信用分配好做。

Hindsight credit assignment（Harutyunyan 等，2019）：从结果反推，按"给定这个未来结果，当时采取该动作的概率"来分配信用，用事后（hindsight）分布替代前向估计。核心直觉是，一个动作是否重要，要看它在多大程度上决定了后来发生的事。

### 5.3 LLM agentic RL 里的信用分配（2024 到 2026）

问题在 LLM 上变了形。GRPO 用组内平均当基线，优势是序列级的，一条回答里所有 token 共享同一个 Â_i，等于承认"我分不清是哪一步、哪个 token 的功劳"。这在短推理题上还行，长程多轮 agent 上就太粗。前沿几条线：

- 把粒度从序列降到步/轮。GiGPO（arXiv 2505.10978）用两层组结构：episode 级对整条轨迹分组算宏观优势，step 级用锚状态分组（把多条轨迹里重复出现的相同环境状态聚成一组）回溯构造 step 级相对优势，仍保持无 critic、低显存，ALFWorld 涨 12%、WebShop 涨 9%。turn-level 这条线（MT-GRPO，arXiv 2505.11821）指出只在轨迹级合并奖励等于把任务当 bandit，缺乏细粒度归因，主张显式在每个 turn 上算优势。
- 利用树结构。Prefix-to-Tree（arXiv 2509.18314）把一组回答建成前缀树，用后代结果聚合出非参数的前缀价值：非分叉 token 上退化为 GRPO，分叉 token 上给精确的 token 级信用，不用学价值网络，还顺带在共享前缀上省 KV cache。
- 用 LLM 当事后 critic 做 hindsight 修正。HCAPO（arXiv 2603.08754）用 LLM 自身当 post-hoc critic，看到最终结果后回看轨迹精修每步的 Q 值，补 GRPO 在关键决策状态上价值基线错配的问题。这把经典 hindsight 思想用 LLM 重新实现。
- 把 value model 请回来（SAO 的选择）。SAO（arXiv 2607.07508，训 GLM-5.2）在异步单轨迹设定下，因为没有组内基线，重新训一个 value model 来估基线，配严格双侧 token 级裁剪稳住异步。因果很直接：单轨迹去掉了组基线，价值函数就成了唯一能给长程每步兜底信用的东西。这和 5.1 呼应，当你放弃组采样，一个估得准的 critic 又变得值得要。
- 过程奖励模型 PRM vs 结果奖励模型 ORM。ORM 只看最终对错，信号稀疏但客观、抗 hack；PRM 给每步打分，信号密集能定位错在哪、还能挡住"过程错但答案对"的假正确，但步级标注贵。缓解标注成本的路子是自动造步级标签：Math-Shepherd 用蒙特卡洛 rollout 估计每步能通向正确答案的概率当标签，FreePRM 用最终结果正确性做伪标签。实践权衡：可验证域优先用 ORM 保证奖励干净，需要缓解稀疏时再叠加客观的子目标状态检查，而不是一上来就上一个学出来的 PRM，因为 PRM 本身是模型又把可 hack 的 RM 引回来了。

一句能讲的总结：信用分配的谱系是"稀疏但干净的结果奖励"到"密集但可能失真的过程奖励"之间的取舍，安全任务的好处是它有大量确定性可验证的中间状态（拿到 shell、命中分支），可以用这些客观里程碑做过程信号，绕开学一个 PRM 带来的失真。

## 六、防作弊：verifier 是新的攻击面

可验证不等于不可作弊，形态从"骗奖励模型"变成"钻验证器的空子"。而且被训的对象本身就是一个专门找漏洞的智能体，它会用攻击者视角审你的打分脚本。这一节是设计安全训练环境最花心思的地方。

作弊的具体形态：

- 直接读答案：flag 明文在文件系统里，模型 `grep -r flag /` 而不解题。
- 猜 / 爆破：flag 格式固定就枚举提交。防法是 flag 主体高熵（16 个 hex 字符 = 64 bit 熵，猜中概率 2^-64）加限制提交次数。
- 打验证器本身：verifier 用子串匹配，模型把海量候选全打印命中；verifier 从可写文件读结果，模型直接改那个文件；状态检查只看端口有响应，模型随便起个服务占住。
- 钻测试的缺陷：测试用例不全，模型写只过给定测试的特判 `if input==用例: return 期望`。

这不是小概率，有一手数字。reward hacking 审计（arXiv 2606.16062，Auditing Reward Hackability in Code RL Training Environments）实测：SWE-bench Verified 抽样里约 28.5% 的任务测试弱到"一个在 Docker 里验证过的错误补丁也能通过"，R2E-Gym 上同管线约 25.0%；对 134 个前沿模型提交做随机效应元分析，在同一人评难度层内，被标记可作弊的任务把 Pass@1 系统性抬高约 14.14 个点（95% CI [11.80, 16.48]）。一个极端的直观例子：约十行的一个 conftest.py 就能让 SWE-bench Verified 全部 500 个实例"通过"。而想用 LLM 自动补测试来堵，本身也不可靠，该审计在 11 个坏任务上生成的 105 条决定性测试有 61.9% 在金标补丁上就失败。结论是：RLVR 的下一个战场是验证器质量本身，安全任务尤其如此，因为"漏洞是否真可利用"比一个单元测试更难判定。（另有二手转述说 OpenAI 披露 Verified 失败任务 59.4% 测试有缺陷，来源日期存疑，不引用，用上面这组可查数字。）

加固手段：

- 执行式判定优先于字符串匹配和 LLM 裁判，把奖励绑到真实程序行为上（CyberGym 拒用 LLM 裁判就是这个理由）。
- 隔离：verifier 与被测环境强隔离，模型碰不到答案和评分逻辑；flag 运行时随机生成注入到只有解出才能到的位置。
- 隐藏且充分的测试集，判定用精确匹配不用子串。
- 去污染：老基准解法进语料会让分数虚高（InterCode-CTF 约 14.1% 解法泄漏并趋于饱和），要用新题或程序化生成，配 n-gram/语义查重。
- 人工审计高分轨迹，专门找"分高但没真解对"的样本，这是发现新 hack 的主要手段。

用 Goodhart 一句话收：一个指标一旦变成优化目标就不再是好指标。优化压力足够大时，策略必然利用代理奖励和真实目标之间的任何缝隙。可验证性把缝隙缩小了，但没消灭，验证器设计要当成一个会被攻击的对象来做。

## 七、把这一篇讲成面试的三段

第一段，可验证是安全任务的根本优势，它同时喂 RLVR（干净奖励）和 reward shaping（可验证的中间里程碑做密集塑形），而 potential-based shaping 的势差形式 F=γΦ(s')−Φ(s) 保证加密集引导不改变最优策略，这是我敢在稀疏长程任务上做塑形的理论底气。

第二段，稀疏和长程是这类任务最硬的两个问题。稀疏我用冷启动 SFT、课程、子目标部分奖励让模型先采得到正样本，还要注意 GRPO 在一组全对全错时零梯度所以难度要匹配。长程信用分配是从 GAE 到 hindsight 到 SAO 把 value model 请回来这条谱系，安全任务的好处是有大量确定性中间状态可以当过程信号，绕开学一个会失真的 PRM。

第三段，造环境和防作弊是工程主战场，也是我 agent 和 harness 经验的落点。从真实工件用 Fail-to-Pass/Pass-to-Pass 自动抽环境、容器化保证可复现、程序化生成去污染、让环境和策略协同进化；而验证器是新的攻击面，审计实测 SWE-bench Verified 约 28.5% 任务可被错误补丁蒙混、可作弊任务 Pass@1 虚高约 14 个点，这说明验证器质量本身就是核心难题，被训的又是个专门找漏洞的 agent，所以打分脚本要用攻击者视角来加固。
