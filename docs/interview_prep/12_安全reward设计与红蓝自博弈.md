# 安全任务的 reward 与 verifier 设计：以 ALE 4 题为例，含红蓝自博弈

这一篇落到具体的 4 道安全题上，把结果奖励（outcome）和过程奖励（process）、以及 verifier 怎么设计讲透，再回答你的两个问题：这些题哪里能造过程奖励、是不是"拿到某权限某文件某服务被攻破"、有没有更 general 的设计；以及能不能类比 AlphaZero 做红蓝自博弈来缓解策略飘移和分布收缩。

先给一个贯穿全文的判断：你说的"拿到某权限、某文件、某服务被攻破"是一种过程奖励，但它只适配一类任务（利用和渗透），这 4 道题大多不是那类，所以过程奖励要换一种造法。搞清这个区别是设计的第一步。

---

## 一、先分任务类型，过程奖励长得不一样

安全任务粗分两类，过程奖励的形态完全不同：

- 利用 / 渗透型（pwn、提权、打靶机）。解题是让系统状态一步步跃迁：拿到低权限 shell → 提权到 root → 读到某文件 → 某服务被攻破。这里的过程奖励就是你说的那套状态检查，里程碑是状态跃迁，天然是一串台阶。
- 分析 / 逆向 / 取证型（这 4 题的主体）。解题不改变任何系统状态，是从一个静态对象（二进制、抓包）里推断出正确的事实。这里没有"拿到 shell"这种台阶，里程碑是中间分析结论正确：认出加壳方式、还原出密钥、定位到算法常量、从 DNS 认出恶意家族。

所以对这 4 题，过程奖励不是状态检查，而是中间产物正确性检查。硬套"权限/文件/服务"那套模板会错位。下面逐题拆。

---

## 二、逐题拆 outcome reward 与 process reward

记号：outcome 指最终判分的 verifier，process 指可插入的中间可验证检查点。

### 题 1 · ghidra_malware（提取 15 字段 C2 配置）

- Outcome reward：15 个字段和参考答案比对，匹配数达阈值算过。注意这个 outcome 本身就是字段分解的稠密奖励，不是一个 0/1，天然缓解了稀疏。写成公式：

```
r_outcome = ( Σ_i w_i · 1[field_i 正确] ) / ( Σ_i w_i )
```

- Process reward 候选（都是可验证的中间产物）：
  1. 正确判定加壳方式 UPX（可查：模型是否声明 packer=UPX，对齐 ground truth）。
  2. 脱壳成功（可查：脱壳后二进制的哈希对上参考脱壳产物，或熵显著下降到正常代码区间）。
  3. 还原出正确的 16 字节 XOR 密钥（可查：key == ground truth key）。这是这道题的题眼，拿到密钥后 15 个字段全部随之解出，所以它是一个高价值、单点的过程检查点。
- 判断：这道题的过程奖励不是状态检查，是"关键中间产物对不对"。而且 15 字段 outcome 已经很稠密，真正值得再加的过程检查只有一个，就是 XOR 密钥。这呼应一条通用原则：过程检查点要少而关键，加在题眼上，不要每步都发奖励。

### 题 2 · newyear_keygen2（还原 keygen 算法算 flag）

- Outcome reward：flag 和评测时刻算出的答案逐字符相等。这是最稀疏的形态，0/1，而且 flag 随时间片变（每 1800 秒），无法缓存、无法背。
- Process reward 候选：
  1. 定位到 TEA 变体的 DELTA 常量 0xB979379E（可查：轨迹里是否引用了正确常量）。这一步确认了算法族。
  2. 还原出算法本体，用可复算验证。这是最重要的一点，见下。
- 这道题引出最 general 的一个设计：可复算 / round-trip 奖励。你不用拿模型的输出去和一个隐藏 flag 比，而是拿模型还原出的算法，在一批已知的 (UID, 时间片) 输入上重新运行，和参考 keygen 的输出比对：

```
r_roundtrip = ( 1 / |T| ) · Σ_{(x,y)∈T} 1[ f_模型还原(x) == y ]      T 是留出的输入输出对
```

它的三个好处：一是稠密，每个测试点一分；二是抗作弊，模型没法靠猜某一个 flag 拿分，必须真的还原对算法才能在多个点上都对；三是它评的是中间产物（还原出的算法）而不只是最终答案，所以它既是过程奖励也是更强的 outcome。这就是逆向类任务里"PoC 必须真的能跑"的对应物。

### 题 3 · tris_crackme（改注册表让程序显示已注册）

- Outcome reward：状态检查。评测用 PowerShell 读注册表，当 `RegCode == generate_password(RegName)` 时给 1 分。这道题正是你问的那种状态检查型 outcome，它检查的是"注册表进入了某个状态"。
- Process reward 候选：
  1. 还原出 `generate_password` 算法，同样用可复算验证（对一批名字算注册码，和参考实现比对）。
  2. 状态里程碑：注册表键被创建（部分分）、值写正确（满分）。
- 判断：这道题的 outcome 是状态检查，你那套模板在这里直接适用。但即便如此，过程奖励里最有信息量的仍然是可复算检查算法对不对，因为写注册表只是最后一下机械操作，难点在还原算法。

### 题 4 · pcap_enterprise_triage（网络取证出报告）

- Outcome reward：report.json 按字段比对（受害主机、家族、感染链、C2、IOC），又是字段分解的稠密奖励。
- Process reward 候选：
  1. 正确定位受害主机 10.12.17.101（字段）。
  2. 从 DNS 挖出恶意域名（字段）。
  3. 从 geo.netsupportsoftware.com 认出家族 NetSupport RAT（字段）。
- 这道题引出另一个 general 设计：证据锚定 / provenance 奖励。不只奖励答案字段对，还要求模型给出支撑该字段的具体证据（哪个包、哪条 DNS 记录），verifier 去核对这条证据真的存在且支撑结论。它抗幻觉，也抗"蒙对"。而且它能救参考答案的错：这道题参考答案把域名写成 tactlat.xyz，抓包里实际是 taktlat.xyz，证据锚定奖励会认抓包里真实出现的那个，而不是错误的 reference，避免用错误 ground truth 惩罚正确输出。

## 三、四种更 general 的 reward 设计（超越临时里程碑）

把上面四题的做法抽象出来，得到四种可复用的设计，按优先级：

1. 字段分解奖励（schema-decomposed）。答案是结构化的（配置、报告）时，每个字段是一份部分奖励，稠密度免费得到。`r = Σ w_i·1[field_i 对] / Σ w_i`。适合配置提取、取证报告、结构化抽取。

2. 可复算 / round-trip 奖励。答案背后是一个可执行的过程（算法、脚本、补丁）时，用重新执行来评这个过程对不对，而不是拿最终答案和隐藏答案比。`r = (1/|T|) Σ 1[f_模型(x)==y]`。适合逆向、keygen、算法还原、代码修复。它是这四种里最抗作弊、最稠密的，因为它把"你是不是真的懂了"变成可执行的检验。

3. 状态里程碑 + 势塑形（potential-based）。利用和渗透型任务，用势函数 Φ 给状态排台阶（拿到 shell、提权、读到文件、服务被攻破），中间奖励写成势差形式保证不改变最优策略：`F(s,a,s')=γΦ(s')−Φ(s)`（见文档 11 第三节）。你问的"权限/文件/服务"就是这里的 Φ 台阶，但要写成势差形式才不会被刷。

4. 证据锚定 / provenance 奖励。答案必须绑定可验证的证据（包、偏移、指令、测试）才给分，verifier 核对证据存在且支撑。抗幻觉、抗蒙对、还能纠参考答案的错。适合取证、漏洞挖掘、代码审计。

一条元原则串起来：能用执行式判定（可复算、状态检查）就别用字符串匹配或模型裁判；过程检查点要少而关键，加在题眼上；中间奖励尽量写成势差形式以保最优不变；权重上让最终目标占主导，过程奖励只作引导。

## 四、AlphaZero 式红蓝自博弈：能做，但不是免费的 AlphaZero

你的想法方向对，而且是这个领域最被看好的路线之一。核心吸引力在于：安全攻防天然有一个可执行的裁判（漏洞利用成没成、补丁挡没挡住且没弄坏功能，都是程序能客观判的），这正是 AlphaZero 式自博弈需要的东西，不像开放辩论那样裁判可被说服。下面讲怎么设计、缓解什么、以及哪里会崩。

### 4.1 两种可落地的自博弈结构

结构 A，生成器对求解器（造题自博弈）。红方生成新题（比如程序化生成新的加壳样本加隐藏配置、新的加密 CTF、注入了漏洞的代码），蓝方去解。红方的奖励不是"让蓝方解不出"，而是最小化最大遗憾（minimax regret）：题要难到当前蓝方解不出、但一个参考解法能解出。

```
Regret = 参考解法的回报 − 当前求解器的回报
红方目标 = 最大化 Regret（既不出无解题，也不出太简单的题）
```

这就是 PAIRED（Dennis 等 2020，unsupervised environment design）的思想，它天然是自动课程：题目难度始终被拉到当前能力的边缘。你解的题里 Random-Crypto 程序化生成 5000+ 加密题就是这个的简化版（生成器不自适应），SEAL、EnvGen、WebRL 是让生成器自适应的版本。

结构 B，攻击者对修补者（攻防自博弈）。红方写利用，蓝方写补丁。可执行的博弈规则是：红方的利用要能打穿未打补丁的目标，蓝方的补丁要挡住这个利用且不弄坏原有测试。

```
红方得分：exploit 在未打补丁版本上触发漏洞
蓝方得分：patch 挡住该 exploit  且  原有测试全过（Pass-to-Pass 不回归）
```

这正是 DARPA AIxCC 那些系统在做的自动找漏洞加自动打补丁，也是 CTF 攻防赛制的形态。裁判全是执行式的。

### 4.2 为什么它能缓解策略飘移和分布收缩

这是你问的重点，逐条对上：

- 缓解策略飘移（分布偏移 / off-policy）。自博弈的数据是当前两个策略自己现打出来的，训练分布始终跟着当前策略走，不像用固定离线数据集那样越训越 off-policy。数据由策略自生成，这本身就是 on-policy。

- 缓解分布收缩（熵坍缩 / 模式塌缩）。这是自博弈相对单机 RL 最本质的优势。单机 RLVR 容易把概率质量集中到一两个解法上，pass@k 不再涨。自博弈里，一旦一方坍缩到单一策略，另一方会立刻学会针对它，逼原方必须变换和多样化。对抗压力持续惩罚坍缩，等于给多样性一个内生的、不用手调的激励。

- 自动课程避免优势坍缩。用 regret 当生成器奖励，题目难度被钉在"当前能解一部分但非满分"的区间，正好避开 GRPO 一组全对或全错时零梯度那个坑（文档 11 第四节的 advantage collapse）。

- 裁判可执行，抗 reward hacking。奖励绑在真实执行结果上（利用成没成、补丁过不过测试），比学一个奖励模型或用 LLM 裁判难被钻空子。

### 4.3 哪里会崩，必须老实讲（面试被追问就答这些）

AlphaZero 的干净来自几个安全场景不具备的前提，照搬会踩坑：

- 两个策略同时在动，非平稳，训练不稳。AlphaZero 用的是单一共享网络加 MCTS 加一个固定规则的对称游戏，天然稳。两个 LLM 互相追着训容易震荡甚至发散，是经典的多智能体不稳定问题。缓解要上种群和联赛机制：AlphaStar 的 league（主智能体加各种 exploiter 防遗忘和循环）、PSRO（在策略空间上求近似纳什）、fictitious self-play（对历史对手的平均最优反应）、以及用缓慢移动的对手池而不是让对手瞬时最优。

- 没有完美模拟器和便宜的前瞻搜索。AlphaZero 靠一个零成本的完美世界模型做百万局 MCTS。安全的"裁判"是一个真实、昂贵、可能不稳定（flaky）的执行沙箱，跑一局利用或一次编译测试都费时费钱，采样量级差好几个数量级。

- 裁判本身可被 hack，两方可能一起去打环境而不是打对方。如果沙箱有配置漏洞，红蓝都可能利用环境漏洞刷分，而不是真攻防。裁判要按文档 11 第六节当成会被攻击的对象来加固。

- 退化均衡与合谋。生成器可能出无解题或水题，攻防双方可能收敛到一个平凡不动点。regret 型生成器奖励和多样性激励（quality-diversity、种群）是防退化的关键。

- 攻防不是干净的零和对称博弈。补丁质量和利用不是对称的输赢，奖励要塑形，不能指望天然平衡。

- 双刃与治理。自博弈字面意义上就是在训练一个攻击者，必须全程沙箱隔离、设能力阈值、管好模型和数据释放。能力越强治理越要前置。

### 4.4 一句总判断

用可执行裁判的对抗自博弈，是目前在安全领域拿到 on-policy、自动课程、难被 hack 的信号的最有前景的路线之一，而且它在结构上正好对准你关心的两件事：数据自生成对付策略飘移，对手自适应对付分布收缩。但它不是免费的 AlphaZero，难点从"设计奖励"搬到了"裁判的保真度和成本、多智能体训练的稳定性、防退化均衡"。真正的可参照物不是 AlphaZero 本身，而是 PAIRED（造题自博弈）、AlphaStar 的 league、PSRO（防循环和不稳定）、以及 AIxCC（攻防执行裁判的工程化）。

## 五、面试话术（几句能直接说的）

第一，这 4 道题大多是分析型不是利用型，所以过程奖励不是"拿 shell、拿文件"那套状态检查，而是中间产物正确性检查，比如还原出的 XOR 密钥对不对、定位的算法常量对不对。状态检查只适配 tris 那道注册表状态题和一般的渗透题。

第二，比临时里程碑更 general 的设计我会优先用可复算奖励：把模型还原出的算法或补丁重新执行，在一批留出输入上验对错，稠密、抗作弊、评的是过程而非蒙对的最终答案。结构化答案用字段分解奖励，取证类用证据锚定奖励，利用类用势函数台阶加势塑形保最优不变。

第三，红蓝自博弈我认为方向对，它用可执行裁判、数据自生成对付策略飘移、对手自适应对付分布收缩，还能用 regret 生成器做自动课程避开优势坍缩。但它不是照搬 AlphaZero，安全没有便宜的完美模拟器，两个策略同时动会不稳，裁判本身可被 hack，得靠种群和联赛、regret 课程、裁判加固来兜，真正的参照是 PAIRED、AlphaStar league、PSRO 和 AIxCC。
