# 智谱 GLM 前沿与 SAO 论文

这一篇是为唐杰的提问准备的。他会从宏观和前沿切入，你要能复述智谱的模型线、他团队的研究路线、你要参考的 SAO 论文，并把它们和你自己的研究接上。

## 一、SAO 论文，逐条讲清（最重要）

论文：Single-Rollout Asynchronous Optimization for Agentic Reinforcement Learning，arXiv 2607.07508，2026 年 7 月。作者 Zhenyu Hou、Yujiang Li、唐杰、Yuxiao Dong，清华/智谱。唐杰是作者之一，所以这篇你必须能讲。

### 1.1 它要解决什么问题

背景是 LLM 的训练重心正从预训练转向后训练 RL，而给长程 agentic 任务做 RL 时，主流的同步、批次交错式流水线很浪费。原因：agentic 和代码任务的轨迹长度差异很大，短轨迹很快跑完，长轨迹成了掉队者，整个 GPU 集群要等最慢的那条轨迹才能进入训练，大量算力空转。

异步 RL 能缓解这个浪费，做法是轨迹一到就消费、就更新模型，不等整批。但异步引入两个新问题：

1. 稳定性。异步下，一条轨迹可能是由好几个版本的旧模型生成的，off-policy 程度更严重也更不可预测，训练容易不稳。已有的异步 RL 工作大多只顾吞吐效率，没解决这个有效性和稳定性问题。
2. GRPO 和异步不匹配。GRPO 要对每个 prompt 采一组回答，用组内平均做优势估计。这在异步下有两个麻烦：一组里要等最慢的那条采样完才能一起进训练，制造了延迟驱动的 off-policy；而且在线或复杂 agentic 环境里，环境往往对一个 prompt 只给一个信号，天然凑不成一组。

### 1.2 SAO 的三个改动

1. 单轨迹采样代替组采样。每个 prompt 只用一条 rollout，而不是一组。这降低了 off-policy 的严重程度，也提升泛化，还天然适配"环境只给单个信号"的在线 agentic 设定。
2. 把 value model 请回来。GRPO 之所以能不要 critic，是因为它用组内平均当基线。现在退回单轨迹，没有组内基线了，所以要重新训练一个 value model 来估计优势，论文给了一套让 value model 好训、能用的实用设计。这一点值得你在面试里点出，它和"GRPO 的卖点是去掉 value model"形成一个有意思的对照：当采样方式从组变成单轨迹，取舍就反过来了，一个好的 critic 又变得值得要。
3. 严格的双侧 token 级裁剪。在 token 粒度上对重要性采样比做上下双向的严格裁剪，压住异步带来的不稳定，让训练能稳定跑到一千步。

### 1.3 结果

在推理和代码的 agentic 基准上稳定超过 GRPO 及其变体：SWE-Bench Verified 从 GRPO 的 27.0 提到 29.8，BeyondAIME 从 54.8 提到 74.8，还有 IMOAnswerBench、AIME2025（97.3）、HMMT 等。四个推理基准是在"带 Python 工具的推理"设定下评的。更关键的一句：单轨迹 RL 在模拟的在线学习设定下特别有效，模型要适应不断变化、持续演化的环境。最后，SAO 被用在训练开源 GLM-5.2（750B-A40B）的 agentic RL 流水线里。

### 1.4 为什么这篇和你直接相关（面试要主动说）

那句"在演化环境里做在线学习特别有效"就是你的地盘。你的博士方向就是延迟反馈、任务漂移下的自进化，SAO 从训练系统和算法层面给出了一个在演化在线环境里稳定高效做 agentic RL 的方案。你可以这样接：SAO 解决的是"怎么在演化的在线环境里稳定高效地训"，而我关心的是"在没有即时标签时怎么把可学习的信号造出来、怎么把学到的能力沉淀成经验应对漂移"，我们在同一个大问题的上下游。单轨迹这个选择对我尤其亲切，因为未来预测这类任务本来就是一个 prompt 对一个最终结果，天然是单信号、单轨迹的，组采样在这里本来就不自然。

### 1.5 预判追问

问：SAO 用单轨迹会不会方差太大？答：会失去组内比较这个低成本基线，方差风险确实上升，所以它把 value model 请回来补上基线，再用严格双侧裁剪压不稳定。它的取舍是用一个训得好的 critic 换掉组采样，换来的是异步效率和对在线单信号环境的适配。

问：那 GRPO 和 SAO 到底谁好？答：不是谁替代谁，是设定不同选择不同。同步、每题能廉价采一组、离线固定题库，GRPO 省 critic 又稳，很合适。异步、长程、在线演化、环境只给单信号，组采样的前提就不成立，SAO 的单轨迹加 critic 更合适。选择取决于你的采样方式和环境是不是在线演化的。

## 二、智谱的模型线和研究路线

### 2.1 GLM 模型线（截至 2026 年年中）

- GLM-5 大约 2026 年 2 月发布，744B 总参数、约 44B 激活的 MoE，200K 上下文（用了 DeepSeek 那套稀疏注意力），在华为昇腾芯片上训练。定位不是聊天，而是 agentic engineering 和长程任务执行的引擎。国产硬件训练是一个被反复强调的点。
- GLM-5.2（750B-A40B）是 SAO 论文里被训练的那个模型，说明智谱把 agentic RL 直接用在了主力模型的后训练上。
- 更早的 GLM-4 系列、以及 AutoGLM 这类把 GLM 做成能操作手机和网页的自主 agent 的产品线，是智谱 agent 方向的延续。

要点判断（可以在面试表达）：智谱的模型定位明显在往 agentic 和长程执行上压，GLM-5 被称作 agentic engineering 引擎、GLM-5.2 用 agentic RL 训练，这条产品和研究的合流，正好是你这个方向的用武之地。

### 2.2 唐杰团队的研究路线

唐杰、董宇霄（Yuxiao Dong）这条线近年的主轴是把 RL 和 agentic 能力做进大模型：从 GLM 系列的后训练，到用可验证奖励和 RL 提升推理与代码能力，到 SAO 这种为长程 agentic 任务设计的 RL 系统，再到 AutoGLM 这类自主 agent。你要理解的大图景是：他们在系统性地把"靠外部脚手架才有的 agent 能力"变成"模型自身权重里的能力"，这和你简历里"内化进权重、去掉 harness 仍能自我增强"是同一句话。

### 2.3 2026 年 harness/agent 协同进化这一波

和你方向同名的一批 2026 arXiv 工作，知道它们存在并能说区别：EvoTrainer（协同进化策略和训练 harness）、SEAL（智能体和学习环境协同进化）、Evolving-RL（端到端优化经验驱动的自进化）、Skill1 和 FederatedSkill（agentic skill 的自进化）。共同趋势是让智能体、环境、harness 三者一起进化，而不是固定环境只训模型。你的位置见 `01` 第四节，不重复。

## 三、几个唐杰可能问的宏观问题和答题方向

这些没有标准答案，考的是你的判断和研究品味。给你方向，用你自己的话说。

问：你怎么看 agent 能力应该靠 harness/scaffold 还是内化进模型？答：两者是分工不是对立。harness 是冷启动和探索的脚手架，负责在模型还跑不出高质量轨迹时把它引导出来、负责加安全边界；内化负责把稳定下来的能力写进权重换取泛化和长程稳定。健康的路线是协同进化，harness 引导出可学习轨迹、训练把它内化、模型变强后 harness 退到更难的地方。终局是 harness 尽量薄，但不会为零，安全边界和工具接口这层留着。

问：自进化智能体的最大瓶颈是什么？答：不是模型不够聪明，是缺少可靠的、可扩展的监督信号。真实长程任务里即时标签稀缺、反馈延迟、还漂移，纯靠模型自评会积累自己的错误。所以核心难题是怎么在没有干净标签的地方造出可信的学习信号，可验证环境、跨时间弱监督、self-calibration 都是在解这个问题。这也是我从未来预测这种自带延迟结果的任务切入的原因，它给了我一个相对干净的信号来源做研究。

问：为什么选未来预测这个任务，它够不够重要？答：两个理由。一是方法上它是一个干净的载体，天然有"揭晓前的长过程加明确的最终结果"，让我能研究延迟和跨时间信号下的自我修正，而这个能力可以泛化到所有长程延迟反馈的 agent 任务。二是它本身有价值，动态未来预测是决策支持的核心能力。我不是为了预测而预测，是用它当研究自进化的抓手。

问：往下三年你打算怎么走？答：[给一个有阶段的规划。] 大致是先把未来预测上验证过的"跨时间弱监督做在线自我修正"做扎实并泛化到更一般的 agent 任务，再往协同进化的闭环走，研究 harness 引导的轨迹怎么高效内化、经验怎么跨任务复用应对漂移，最终目标是撤掉 harness 后模型仍能自我增强，并在可验证的长程环境（代码、cyber 这类）上验证。

问：你和智谱现在做的东西怎么结合？答：我的上游是造信号和沉淀经验，智谱有 SAO 这样成熟的 agentic RL 训练系统和 GLM 这样的强基座，正好是我方法落地需要的下游。我能贡献的是在延迟、漂移、无即时标签这些最难的设定下怎么把学习信号和经验积累做对，这是把 agentic RL 从可验证的静态题库推向真实演化环境要跨的一步。

## 三点五、一个用词准确的提醒

SAO 论文里训练的是 GLM-5.2（750B-A40B），不是首发的 GLM-5（744B-A44B，技术报告 arXiv 2602.15763）。被追问版本号时说"SAO 落地在 GLM-5.2"更稳。还有一个可以主动用的点：GLM-5 技术报告几乎不谈安全和对抗鲁棒，代码那块只讲测试通过式的正确性，这恰好是这个岗位要补的空白，你可以把它当成"我能带来的增量"来讲。

## 五、把智谱的 RL 栈串成一条线（能证明你看懂了他们在解什么）

智谱当前的后训练主线，用四层串起来讲最清楚：

1. GLM-5 技术报告（arXiv 2602.15763，副标题 from Vibe Coding to Agentic Engineering）。核心洞察是能力有先后依赖，所以用顺序式 RL：推理 RL 打底、agentic RL 叠自主规划、通用 RL 收口，最后加一步跨阶段 on-policy 蒸馏专门防前面的能力被后面训练训忘。推理阶段用 GRPO 加一个叫 IcePop 的技巧缓解训练和推理的不一致，还按难度筛题（GLM-4.7 很少做对、更强模型稳定做对的题才要）。agent 阶段构建了 9 种语言、上千仓库、超过一万个可验证环境，奖励来自真实测试执行（Fail-to-Pass 和 Pass-to-Pass）。
2. slime，他们的异步后训练基础设施。洞察是把 rollout server 用标准 HTTP API 暴露成和普通推理引擎一样的服务，外部 agent 框架不改底层就能接，生成和训练各跑各的。配 FP8 rollout、Prefill-Decode 分离压尾延迟、心跳容错。它是 SAO 这类算法能跑起来的前提。
3. SAO，在 slime 之上专门治异步带来的 off-policy 和不稳定（见第一节）。
4. AutoGLM 产品线背后的在线 RL：WebRL（arXiv 2411.02337）用自进化的在线课程，根据 agent 当前能力动态生成刚好够得着的新任务，把 GLM-4-9B 在 WebArena-Lite 从 6.1% 提到 43%，超过 GPT-4-Turbo；MobileRL 把这套搬到移动端；AgentRL（唐杰、董宇霄，AAAI 2026）把它抽象成多轮多任务的可扩展 agentic RL 框架。

能把 GLM-5 报告、slime、SAO 串起来讲，就证明你看懂了智谱在解决什么，而不是只记住一个论文名。

## 六、RLVR 这条大线的几块地基（唐杰系之外也要知道）

- DeepSeek-R1（arXiv 2501.12948，登了 Nature）。奠基发现是强推理不一定要人标的思维链，纯 RL 只给可验证的结果奖励，反思、验算、长思维链这些行为会自己涌现。这是 RLVR 范式的起点。
- SWE-RL（Meta）和 Agent-RLVR（arXiv 2506.11425）。洞察是开源软件的演化史（PR、issue、commit、测试）本身就是海量可验证信号，把 RLVR 从数学竞赛题带进真实软件工程。后来所有 code agent RL 都是这条路，包括 GLM-5 的一万环境、Qwen3-Coder 的两万并行环境。
- 可验证奖励的边界，这是面试能聊出深度的点。执行和测试当奖励的前提是测试本身对，但这个前提大面积不成立：一份 reward hacking 审计（arXiv 2606.16062）实测 SWE-bench Verified 抽样里约 28.5% 的任务测试弱到一个错误补丁也能过、R2E-Gym 上约 25%，对 134 个前沿模型做元分析发现被标记可作弊的任务把同难度 Pass@1 系统性虚高约 14.1 个点。结论是 RLVR 不是有验证器就万事大吉，验证器质量本身是核心工程问题，安全任务尤其如此，因为漏洞是否真可利用比一个单元测试更难判定。

## 七、2026 年 harness 和环境协同进化这一波（你的强项能接的地方）

这块和你 harness 背景直接接得上，值得重点聊。

| 工作 | 核心问题 | 关键洞察 |
|---|---|---|
| EvoTrainer（2606.03108） | 训练配方和诊断逻辑还靠人手调 | 让策略和训练侧的诊断 harness 一起进化，harness 去解读 rollout 证据、跨版本决定怎么干预 |
| SEAL（2605.24426） | 工具使用 agent 数据太少、环境太死 | 把失败 rollout 诊断成 turn 级失败标签，同一信号同时驱动环境适配和策略更新，400 条样本涨 8 到 26 分 |
| Evolving-RL（2605.10663） | 经验驱动的自进化散在流程各处 | 端到端优化 agent 内部的经验到自进化回路 |
| Skill1（2605.06130） | 技能检索、选择、解题、演化被拆成几个模块 | 单策略在一次 rollout 内统一做完这四件事 |

EvoTrainer 那句话对你是黄金：训练侧要有一个能读懂 rollout 证据、带持久记忆和可复用技能的诊断 harness，和策略双向进化。这说明训练 harness 和 agent harness 是同一种工程能力，你做 agent harness 的经验可以直接搬到训练器这一侧。面试要主动打这个桥。

## 八、长程 agentic RL 的系统与算法难点（能聊出深度）

- 异步和 off-policy。同步 RL 在长程任务上因长尾产生大量 GPU 空泡，异步解耦是主流（美团 DORA 报称超过三倍加速）。但异步引入 off-policy 和陈旧度（staleness），代价是稳定性，SAO 就是在治这个，还有专门研究陈旧度和学习率标度律的工作（arXiv 2607.01083）。
- credit assignment。长程稀疏奖励下，把整条轨迹的成败摊到某一步工具调用上没有共识解。有工作证明去 value 的 GRPO 在稀疏奖励下 step 级估计不准，转而用 LLM 当事后 critic 做 hindsight 修正（arXiv 2603.08754）。这也解释了 SAO 为什么把 value model 请回来。
- rollout 效率。瓶颈从能不能采到，变成采得快不快稳不稳，Qwen3-Coder 的两万并行环境本身就是护城河。
- 环境可复现。一万级可验证环境要跨语言跨仓库稳定复现测试结果，容器化、测试抽取、防 flaky 是脏活也是核心资产。这正是你 harness 和环境经验能立刻贡献产能的地方。

## 九、面试可用的判断（挑几条用自己的话讲）

1. harness 和后训练不是两件事，是同一种工程能力的两个位置。EvoTrainer 明确要训练侧的诊断 harness 和策略一起进化，我做 agent harness 的经验能搬到训练器这一侧。这是我最该打的桥。
2. GRPO 不是终点。SAO 敢在异步长程场景把被 GRPO 抛弃的 value model 请回来，说明去 critic 是特定假设下的简化，异步加稀疏奖励这两个条件一叠，critic 反而更稳更省，这和 credit assignment 那条线互相印证。
3. 可验证奖励的真正边界不是有没有验证器，而是验证器对不对。审计实测 SWE-bench Verified 约 28.5% 任务可被作弊、可作弊任务 Pass@1 虚高约 14 个点，RLVR 的下一个战场是验证器质量，安全任务尤其如此。
4. 代码和安全能力要内化进底层，靠的不是提示词或工具，而是海量可复现的可验证环境加执行奖励。GLM-5 的一万环境、Qwen3-Coder 的两万环境说明环境工程就是能力工程，这正是 agent 背景的人能立刻上手的地方，不必先会调 loss。
5. 智谱的 RL 栈主线清楚：顺序式 RL 加跨阶段蒸馏防遗忘，slime 异步基础设施，SAO 治异步 off-policy。能把 GLM-5 报告和 SAO 串起来讲就证明看懂了他们在解什么。

## 四、别踩的坑

- 不要把 SAO 讲错成"又一个 GRPO 变体，就是换了个采样数"。它的核心是异步和在线设定下的稳定性与匹配问题，单轨迹加 value model 加双侧裁剪是配套的一整套，别只记住单轨迹。
- 不要不懂装懂具体数字。记住量级和相对关系（SAO 稳定跑一千步、在 SWE-Bench Verified 和 BeyondAIME 上超 GRPO、训了 GLM-5.2）就够，记不清就说趋势。
- 不要贬低 GRPO 来抬 SAO。唐杰团队自己也大量用 GRPO，正确的说法是设定不同、选择不同。
- 不要把智谱的方向说成和你完全一样来讨好。讲清你的差异化切入点（时序、跨时间信用分配、延迟漂移下造信号），差异才是你被要的理由。
