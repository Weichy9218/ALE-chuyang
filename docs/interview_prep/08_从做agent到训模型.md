# 从做 agent 到训模型：补你的知识落差

你的落差很具体：你搭过 agent、调过 harness，但没独立训过大模型。这一篇把"训练一个模型到底在干什么"讲清楚，让你在被问到训练细节时不心虚，能承认没做过、但能讲清理解到哪一层。好消息是你做 agent 攒的东西正是训练的上游，这一篇末尾会讲怎么把两边接上。

## 一、先建立训练的整体图像

训练一个模型，本质是一个循环：喂数据、算模型的预测、算预测和目标差多少（loss）、反向传播算出每个参数该往哪调（梯度）、优化器按梯度更新参数。重复亿万次。这个循环你从 agent 视角没直接碰过，但每一步的概念都不难。

一次前向反向的五个环节：

1. 数据变成 token。文本经分词器切成 token id 序列。数据质量和配比是预训练成败的大头，比模型结构更影响最终能力。
2. 前向（forward）。模型吃进 token 序列，逐层算出对下一个 token 的概率分布。
3. 算 loss。预训练的 loss 是交叉熵，衡量模型预测的分布和真实下一个 token 差多少。后训练换成别的 loss（SFT 还是交叉熵，RL 是策略梯度目标），但位置一样。
4. 反向（backward）。用链式法则从 loss 一路求导到每个参数，得到梯度，梯度告诉你每个参数往哪个方向调一点点能让 loss 变小。
5. 优化器更新。用 AdamW 这类优化器，按梯度和学习率更新参数。学习率有 warmup 和衰减的调度。

几个你会被顺口问到的词：

- batch 和 microbatch。一次更新用多少样本叫 batch。显存装不下就把 batch 切成 microbatch 分几次前向反向、把梯度累加起来再更新，叫梯度累积。
- epoch 和 step。过一遍数据是一个 epoch，一次参数更新是一个 step。大模型预训练常常连一个 epoch 都不到就在海量数据上跑很多 step。
- checkpoint。训练中途把参数存盘，用于恢复、评测、或后续阶段接着训。
- 混合精度。用 bf16/fp16 存激活和算矩阵乘省显存提速度，关键的累加用 fp32 保精度。

## 二、预训练和后训练在训练机制上的区别

概念体系见 `02`，这里只讲机制上的不同，帮你区分岗位说的"训练"具体指哪块。

预训练：海量无标注文本，交叉熵，学的是语言和世界知识，最贵，通常不是实习生碰的部分。

后训练：在预训练好的模型上继续训，把能力对齐到人要的行为。这是这个岗位的主战场。分几种：

- SFT。数据是（提示，标准回答）对，loss 还是交叉熵，只在回答部分算。机制和预训练几乎一样，只是数据变成了示范。它只能模仿，给不了负反馈。
- RL 后训练（RLHF、GRPO、RLVR 这些）。机制和 SFT 很不一样，它不是拿现成答案做交叉熵，而是让模型自己生成（rollout）、对生成打分（reward）、按分数调整生成概率。下面第三节专讲这个循环，因为这才是岗位"把安全推理内化进模型"最可能用的手段。

一句你能说的话：把安全推理内化进模型，指的不是在 prompt 里教它、也不只是 SFT 喂题解，而是让模型在可验证的安全任务里自己解、用解没解出来当奖励做 RL，把解题的决策过程写进权重。这正好把这个岗位和你 agent 的经验接上了。

## 三、RL 训练循环的机制（重点，你要能讲）

这是你最该搞清楚的一段，因为它把你熟的 agent rollout 和你不熟的模型更新连了起来。一个 RL 后训练循环：

1. 采样（rollout）。当前模型在一批任务上生成回答或完整的 agent 轨迹。这一步就是你做 agent 时天天看的 rollout，只不过现在它的目的是产训练数据。
2. 打分（reward）。用 verifier 或奖励模型给每条 rollout 一个分。可验证任务里就是跑测试、比 flag、查状态，这是 RLVR，奖励干净。
3. 算优势（advantage）。把分数转成"这个动作比平均好多少"。PPO 用一个 value model 估基线，GRPO 用组内平均当基线，SAO 退回单轨迹又把 value model 请回来。
4. 更新策略。按优势做策略梯度更新，提高高分 rollout 里那些 token 的概率、压低低分的。配 PPO 的 clip 防更新过猛、KL 正则防偏离原模型太远。
5. 回到第一步，用更新后的模型再采样。

这个循环的系统难点，正是 SAO 那类工作在解的（见 `07`）：

- 采样和训练要不要同步。同步是采完一整批再训，简单但长短轨迹不齐、集群等最慢的空转。异步是轨迹一到就训，效率高但引入 off-policy 和不稳定。
- actor 和 learner 分离。生成（actor）和更新（learner）常跑在不同的机器上，中间要传模型权重和轨迹，怎么让 actor 用的权重不太旧是个工程问题。
- 奖励稀疏和长程 credit assignment。长任务只有最后有分，中间不知道哪步的功劳，这在安全任务里尤其严重（几十步才拿到 flag）。

你能说的话：我没实际训过这个循环，但我对循环的第一步 rollout 非常熟，我做 agent 就是在生产和分析这种轨迹，也踩过 harness 影响轨迹质量的坑。我理解 SAO 这类工作难在采样和更新的解耦、off-policy 稳定性、以及稀疏长程的信用分配。

## 四、分布式训练：为什么 750B 的模型必须切开训

GLM-5 这种 744B 参数的模型，一张卡装不下，必须切到很多卡上，这就是分布式训练。知道几种切法和它们各解决什么，就能接住话：

- 数据并行（Data Parallel）。每张卡放一份完整模型、吃不同的数据，各算各的梯度再同步平均。解决的是吞吐，不解决模型太大装不下。
- 张量并行（Tensor Parallel）。把单层里的大矩阵乘切到多张卡上一起算。解决单层太大的问题，但卡间通信频繁，通常在一台机器内部用。
- 流水线并行（Pipeline Parallel）。把模型按层切成几段放到不同卡上，像流水线一样让不同 microbatch 在不同段上同时跑。解决层数太多的问题。
- ZeRO / FSDP。把优化器状态、梯度、参数分片到各卡，不是每张卡都存一份完整的，大幅省显存。是现在训大模型的标配。
- MoE 的专家并行。GLM-5 是 MoE（744B 总参数、44B 激活），只激活一部分专家，专家可以分布到不同卡上，这叫专家并行。

一句你能说的话：训练 750B 的模型是数据、张量、流水线、专家几种并行叠着用，配 ZeRO 分片省显存。我没亲手配过这套并行，但我理解它们各自解决"装不下"还是"跑得慢"哪个问题。承认没配过、但说清每种并行解决什么，这个回答就是合格的。

## 五、底层算子优化是在优化什么

岗位提了底层算子优化，你不用会写 CUDA，但要知道这四个字在说什么，否则被问到会空。

算子（operator/kernel）指模型里一个具体的计算，比如矩阵乘、注意力、softmax、layernorm。底层算子优化就是让这些计算在 GPU 上跑得更快、更省显存。常见手段：

- 算子融合（kernel fusion）。把好几个小算子合成一个 kernel，减少反复读写显存的开销。大模型很多时候瓶颈不是算得慢，是数据在显存和计算单元之间搬来搬去慢（内存带宽瓶颈），融合就是少搬几次。
- FlashAttention 是最有名的例子。它把注意力的计算重排，避免把巨大的注意力矩阵完整写进显存，用分块和在片上内存里累加，既省显存又快。你只要能说清它解决的是注意力的显存和带宽问题就够。
- 量化（quantization）。把权重和激活从 16 位降到 8 位甚至更低，省显存和带宽、提速度，代价是精度损失，主要用于推理，训练里也有相关技术。
- 精度和数值稳定。bf16 训练、loss scaling、关键累加用 fp32，这些是让低精度训练不发散的工程细节。

一句你能说的话：底层算子优化的核心矛盾常常是内存带宽而不是算力，FlashAttention 这类工作就是通过减少显存读写把注意力做快做省，算子融合和量化也是一个思路。我没写过 kernel，但我理解优化的目标是打掉内存搬运和冗余计算。

## 六、把你的 agent 经验接到训练上（你的独特价值）

这一节最重要，因为它把你的落差翻转成互补。RL 后训练的每个部件，你都在 agent 侧碰过对应的东西：

| RL 训练部件 | 你在 agent 侧的对应 | 你能贡献什么 |
|---|---|---|
| rollout 采样 | 你天天在跑和分析 agent 轨迹 | 你知道怎么让轨迹质量高、可学习，怎么 debug 轨迹里的问题 |
| 环境 | 你搭过 harness、跑过 ALE 可验证任务 | 你知道怎么把任务做成可复现、可打分、能隔离的环境 |
| reward / verifier | 你手工对过安全题的参考答案 | 你知道哪些安全任务能自动打分、哪些是 GUI 交互难自动化、reward 怎么被作弊 |
| 把能力内化 | 你简历里就在做 harness 引导轨迹再内化 | 你理解 harness 和模型内化的分工和衔接 |

所以你的定位不是"一个不会训练的 agent 工程师",而是"一个懂可验证环境、轨迹质量和安全任务打分的人，正好站在训练最缺原料的上游"。这个项目要把安全推理内化进模型，第一步就得有大量可验证的安全训练环境和高质量轨迹，这恰恰是你能上手就干的。你要补的是把这些原料喂进 RL 循环、看着 loss 和指标调训练的那一段，而这一段你今晚已经建立了概念框架。

## 七、诚实回答训练问题的模板

被问到你没做过的训练细节时，别硬编，用这个结构：

一是承认边界。我没有独立训过这个，我的经验在 agent 和环境这一侧。

二是讲清你理解到哪一层。比如 RL 循环我理解是采样、打分、算优势、更新这四步，难点在异步下的 off-policy 和稀疏奖励的信用分配。

三是把它接到你会的东西。这个循环的采样和环境这两块我很熟，我做 agent 就是在生产这种轨迹、搭这种环境，我想补的是更新和调训练那一段。

这样的回答比假装会强得多。这个项目招实习生，要的是能快速上手、底子对、态度实的人，不是要你今天就是训练专家。
