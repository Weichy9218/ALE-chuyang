# ALE-Test 进展汇报（2026-07-13）

## 术语

pi 和 gpt_claw 是两套 agent harness。pi 是约 700 行薄包装，把主循环交给外部 pi 编码 CLI，只在 Linux 容器里用 bash 和读写文件工具，不带图形界面。gpt_claw 是仓库自带的重型框架（从 OpenClaw 改写）跑 gpt-5.6-sol，本轮起在无界面 Linux 题上一律关掉图形界面工具，只留 exec/read/write/edit，和 pi 同一起跑线。下文只报 pi 和 gpt_claw，不再区分内部迭代版本。

## 一句话现状

pi 与 gpt_claw 在 25 道 Linux CLI 题（computing_math + engineering）上用 gpt-5.6-sol 已经跑完一轮完整对跑，总分基本打平（pi 10.09，gpt_claw 9.97，各 15 题非零）；4 道真正的网络安全题因为要 Windows 桌面在本地跑不了官方评测，但其中 3 道已在纯 Linux 上手工做出并自评通过。下一步是把评测从 computing_math 扩到其他类别的 CLI 题，本次已备好清单和可直接启动的 gpt_claw 配置。

## 一、已完成的对跑（核心结果）

模型 gpt-5.6-sol，走 haoxiang 网关。任务集 `selected_tasks/gpt56_full.txt`，25 题 = 18 computing_math + 7 engineering，都是 Linux 无界面题，跑在本地 Docker 镜像 `ale-ubuntu22-docker` 里。

| harness | 完成情况 | 总分 | 非零题数 |
|---|---|---|---|
| pi | 20 完成 / 5 超时 | 10.09 | 15/25 |
| gpt_claw（无图形界面工具） | 25 全部完成 / 0 失败 | 9.97 | 15/25 |

三点读法：

1. **两套 harness 打平**。同一模型下 pi 10.09、gpt_claw 9.97，非零题数都是 15。在无界面代码题上，两套 harness 的能力差异不构成分数差异，成败主要归到模型本身。这印证了 [comp_pi_aleclaw.md](./comp_pi_aleclaw.md) 的判断：pi 的七件套工具面正好覆盖这类任务，gpt_claw 的图形界面、MCP、子 agent 在这里用不上，本轮已一律关掉。

2. **接线和框架问题要先排除，才谈能力**。gpt_claw 早期在 Linux 题上全 0，根因是 gpt-5.6-sol 匹配不到专用模型循环、掉进为 Qwen 写的兜底循环，一行正则修好；首轮还有 5 题崩在容器启动，是并发过高加就绪超时太短，降并发加重试后清零。这些都是工程性不兼容，和 [cybersecurity.md](./cybersecurity.md) 记录的路由 bug 同源：评估两套 harness 前必须先排除它们，否则会把框架 bug 误判成能力差。

3. **pi 的 5 个超时暴露了它没有步数护栏**。pi 在 clustered_cyclic、particle_filter、humanoid_wbc、mpc_control、sumo 五题上跑到墙钟耗尽被 kill。原因见 [pi-agent.md](./pi-agent.md)：pi 的主循环没有 max_steps、没有 token 预算，何时停完全交给模型，长任务会失控。gpt_claw 用 max_turns=30 兜住了，这五题都正常结束（虽然多数仍是 0 分）。这正是 pi 留出的可改造点，`shouldStopAfterTurn` 钩子就是加预算止损的位置。

两套都拿满分或接近满分的题：branch_bound_atsp、ising_post_measurement、k3_abelian_extensions、os_log_permission_guard、k8s_payment_api（0.90）、data_pipeline_etl（0.83）、paper_reproduction（0.8）。两套都 0 分的题：dit_pipeline、go_game、mp_checkpoint、particle_filter、ranking_node、aerospace、humanoid、mpc、sumo，这九题是模型本身的难点，不是 harness 的问题。

## 二、网络安全子领域现状

ALE 的 4 道 cybersecurity 题（ghidra_malware_config、tris_crackme、newyear_keygen2、pcap_enterprise_triage）都在 computing_math 目录下，但本质是 Windows 桌面图形界面题，通过 cua_bench 在装了 Ghidra、Wireshark 的 Windows 虚拟机上评测。

- **官方评测跑不了**，原因是硬性的：这台主机是 Docker 容器，拿不到 /dev/kvm，宿主 Docker 挂了授权插件挡死 `--device`/`--privileged`，Windows 镜像几百 GB 且下载源被代理挡，远程 Windows 开发 VM（34.134.146.181:5000）不可达。pi 从架构上也跑不了，它是 Linux 容器 bash，不接 Windows 桌面会话。详见 [cybersecurity.md](./cybersecurity.md)。
- **但题目做得了**。这 4 道题的输入文件和参考答案都在服务器本地，逆向和取证的对象是二进制和数据包本身，与操作系统无关。已在纯 Linux 上手工做出 3 道并自评：ghidra 恶意样本配置 15/15 字段全对，newyear keygen 算法还原并在二进制里验证到 TEA 的 DELTA 常量、算出 flag，pcap 取证定位到受害主机 10.12.17.101 和恶意家族 NetSupport RAT。tris 算法完整，只差最后写 Windows 注册表这一步。产出在 `docs/gpt_analysis/cybersecurity_solve/`，过程见 [cybersecurity_solve.md](./cybersecurity_solve.md)。
- 一个有价值的副产品：pcap 题参考答案把域名 taktlat.xyz 写成了 tactlat.xyz，差一个字母。参考答案会有错，做可验证评测时不能盲信 reference。
