当前设计如何工作

Prep 只处理一个方法 blocker。任务题面和 /input 始终高于报告，writer 负责复核并完成最终决策。

01公开任务表面

fresh session 读取题面、input 和 software，不读取 writer 轨迹。

02选择一个 blocker

普通阅读足够时 skip；禁止领域综述和最终答案。

03生成 bundle

1 至 3 个 observation 或文本 artifact，附边界、来源和 recheck。

04机械 gate

检查 schema、source、网络、路径、大小、hash 和 staging 完整性。

05Writer 复核

规划前读取；直接材料冲突时修改或丢弃。当前不做 solve 后报告维护。

权威顺序

  1. 任务题面和 /input
  2. writer 对任务材料的直接核验
  3. 已重新执行的 Prep artifact 或 observation
  4. 未复核的 Prep 报告
  5. 外部一般惯例

本轮测量分层

Report exposurewriter 是否读取报告。本轮 6/6。
Evidence use是否回查报告指向的任务材料。
Capability reuse是否执行附件代码。本轮 3/6。
Decision consequence报告如何改变字段、候选或算法选择。
Score最终结果；单次差值不等于因果效果。
当前实现仍有边界缺口

contract_checker 目前可以输出退出码和 unmatched_count。BPMN writer 将它当作局部完成目标。下一版应限制为诊断关系和 evidence，不提供总分、ok 或可追逐的 pass/fail；candidate index 也必须机械区分 candidate 与 selected。

这轮同步到设计中的 Insight

v13 已经解决 bundle 的生成、校验、归档和读取问题。下一步不应继续扩大研究，而应控制 Prep 信息如何改变 writer 行为。

局部 checker 会诱发 Goodhart

BPMN 的 2 到 0 finding 路径说明，不完整检查器如果输出 pass-like scalar，writer 会修改观测面。Prep artifact 应输出诊断关系，不输出完成证书。

Do not infer 不能机械执法

Digital 的 0 和 CRF 的 57 行都越过了文字边界。任何 handling policy、字段删除和 candidate selection 都需要独立 task-local rule。

价值来自不可替代能力

CRF 的跨 XML/PDF resolver 最接近高边际价值；SSE grep 和 PDE schema check 容易由 writer 完成。Value gate 应允许更多 skip。
