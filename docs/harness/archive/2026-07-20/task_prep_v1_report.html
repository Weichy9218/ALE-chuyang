1. 实验口径

  • 运行三个新臂：skills、prep、skills_prep，每臂 26 题，并发 3，cleanup_mode: delete。

3. Prep 机制是否真的升级

prep instances5249 completed / 3 failed
real research sessions4210 cache hits
prep input tokens9.76Muncached median 180,922
tool calls629527 exec / 69 web

这次 prep 不再是“一次 completion + 五个文件头”。42 次实际 research session 使用了 527 次 exec、18 次 read、35 次 web search、34 次 web fetch 和 15 次 image analysis。 它完整解析 XML/PDF/CSV/JSONL，检查安装包源码和版本，也运行了 synthetic probe。这个能力升级是真实的。

代价也很高：共 9,763,850 input tokens、179,478 output tokens，注入 notes 共 170,190 字符；所有 52 个实例都产生了 notes，NO_TASK_SPECIFIC_PREP 一次也没有触发。 三次 context compaction 恰好对应三次 prep protocol failure，错误都是孤立 tool result； solver 随后无 prep 降级继续。实验后已修复 compaction 的 tool-call 配对边界。

4. 关键题目 Forensics

CT Geometry：feedback 有了，search policy 没有

题目明确把 input/reference_image.npy 作为 ground truth，要求主 agent 用它计算 SSIM/MSE 并迭代。这是公开 oracle，不是 evaluator 泄露。input reference 与 evaluator-owned reference 的 SHA-256 都是 c12f859a...，但所有提交数组 hash 均不同，且 np.array_equal=false。

阈值是 SSIM ≥ 0.95 且 MSE ≤ 4e-6。三个新臂都运行真实指标闭环，skills 和 prep 的 MSE 甚至已过，但都没有测试总角跨度略小于 360 的离散边界。历史 base 的扫描显示 359.90→SSIM 0.9436、359.92→0.9615、359.98→0.9942、360.001→0.9033，存在明显 LEAP weighting 分支。组合臂还把会话中更好的候选丢掉，最终落盘只剩 0.8486。

prep 找到了 Q1 的直接段落，并把“存在收费机制”与“具体数额可确定”分开，输出 No / Unknown / No，得 1.0。skills 和 combined 都把缺失具体数额错误标成 No。 实验后只精修一条通用规则：requested fact 无法由材料确定时用 Unknown，No 只用于命题被反证。

Variant：更专业的上游语义反而违反 task-local 规则

skills-only 得 0.999；prep 与 combined 使用同一缓存 findings，均得 0.793。post-hoc scorer 显示 gene 50/50、consequence 50/50、reportable flag 50/50，只有 3 个 AF 和 1 个 ClinVar 不同，却让 exact reportable 子表整块 20 分归零。

prep 建议用 VEP normalized allele 的 - 频率，并按 clin_sig_allele 选 submitted allele；这在领域语义上有依据，但题目的 source_manifest.json 明确规定了本题自己的 ALT/priority 解释。prep 不应重解释它。 实验后加入的是 precedence 边界，不是新的 verifier：task-local convention 控制实现， upstream 只报告冲突。

CRF4 与 TCGA：task-specific research 的正确形态

CRF4 的 prep 完整解析 XML/PDF 后发现：真正的 AE/SUPPAE metadata 在 sdtm_define.xml，名为 supp_define.xml 的文件其实是 ADaM define； 它还定位了 aCRF 11–12 页、8 个 SUPPAE QNAM 及其中仅 5 个来自 AE form。分数从历史 base 0.450 提到 prep 0.615、combined 0.646。

TCGA 的 prep 查清了实时 GDC 的重复 file/sample、versioned KRAS ID，以及安装版 TCGAbiolinks 2.38.0 的 assay 实名是 tpm_unstrand 而不是源 TSV 的 tpm_unstranded。prep 得 0.985、skills 得 1.0；combined 却回到 0.84。 这两题证明 prep 的价值来自模型原本拿不到的输入/API/版本事实，不来自重述题目。

BPMN Category：行为更深入，但公开约束本身冲突

三个新臂仍为 0。post-hoc criterion 审计显示它们都缺 A23/A24 的两类 coordination userTask，此外各自还差少量 A25/A37/A42/D03。问题不只是“不认真”：公开 a23/a24 要求新增 coordination tasks，公开 a50 又要求每个 userTask 出现在 scenario task_outputs 或固定 exemption； 60 个 scenarios 没有这两项输出，exemption 也没有它们。prep 正确识别了该冲突，solver 一度创建任务后又为满足 a50 删除。

这说明 harness 不能通过猜 grader 来解决公开规格不一致。数据集和评分方式保持不变； 当前能做的只有让 agent 显式选择 task-local precedence 并记录不可同时满足处，但不能保证全有或全无评分给分。

Legal M&A：四个实质冲突都找到了，仍漏一个错字

三个新臂仍为 0。它们都报告了 146,660,323/332 的 9 元差、45%/40%、自有资金/银行借款、 执行事务合伙人身份等实质冲突，却都漏掉公告第一页的 空股股东 应为 控股股东。评分是目标集合全覆盖，因此一项 lexical anomaly 足以归零。

prep 在这类 closed-book audit 中事实上接近第二个 solver：完整读输入就不可避免地开始解题， 但 58 万以上 prompt tokens 仍未保证抓到稀有错字。lexical scan 可以作为此类文本一致性任务的 条件策略，不应升级为所有任务强制执行的通用主干。

5. 对系统设计的回答

  1. General prep 已删除；task-specific prep 默认开启。四臂实验仍显式写 on/off，能够保留对照。当前结果没有证明默认开启普遍提分，因此开关必须保留。
  2. Skills 继续只属于 main agent。prep 不加载 skills，也不构建 evaluator。TCGA/SAP 的组合回落和 Variant 的 precedence 回归说明再合并只会扩大干扰面。
  3. Feedback 由 main agent 针对公开材料建立。有公开 oracle 就复算真实指标；只有 schema/invariant 就承认部分验证；语义判断不能伪装成确定性 PASS。
  4. 不要再增加 contract/ledger 文件。实验后只做四个小修：compaction 配对、task-local precedence、Unknown/No 语义、最终落盘验证与平台期离散枚举。
  5. 纯文档审计是 prep 边界最模糊的类型。若 prep 没有 parser/格式/来源方面的新增事实，理想行为是空输出；否则它只是高成本的第二次作答。v1 的 0 empty 表明这点仍未校准。

6. 下一步计划

  1. 先部署并回归已定位的 compaction tool-call 配对修复；它对应本轮全部 3 次 prep failure。
  2. 用 post-run 精修后的同一版本做小规模 canary：CT、SSE、Variant、Legal、CRF4、TCGA。检查的是机制断点是否消失，不先追全量均分。
  3. 下一次正式实验先预热并冻结 task-prep cache，确保 prep 与 combined 注入完全同一 findings；同轮补 base，至少 k=3。
  4. 按 headroom 与机制分层报告：环境/API research、closed-book audit、数值反馈、all-or-nothing 构造题。不要再用一个总均分遮住相反机制。
  5. 保持 dataset、task、input、reference、runner 和 evaluator 不变；所有 post-hoc grader 审计只用于研究报告，不反馈给运行中的 agent。
