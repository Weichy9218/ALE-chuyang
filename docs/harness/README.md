# ALE Harness 文档入口

系统有两个可选的辅助 agent。**Prep** 默认开启，在 writer 之前、同一沙箱里跑通题目的运行时，
亲自跑一遍核心机械步骤并报告断点，补上题面缺失的精确外部事实。**Verifier** 默认关闭，是系统
里唯一的契约一致性所有者：题目自带机器可读规格的部分由代码机械生成校验器，只有散文里的义务
才由 builder 编译，全部在 writer 开始前冻结，writer 全程可用 `verify` 对自己的草稿运行。

契约与 schema 检查过去由 Prep 和 Verifier 各做一份，实测证明是同一张清单编译了两遍，现已整体
归 Verifier。Prep 不再编译清单、不再生成自检脚本。

## 当前结论

**分数收益未被证明，且聚合均值不是可用的统计量。** 四轮实测配对均差：Prep 是 −0.007、+0.016、
−0.004、+0.005；Verifier 是 +0.021、+0.0005、+0.007、+0.0116。唯一一次显著（t 2.57）没有复现，
而那两轮之间只加了 fail-open 方向的兜底，解释不了落差。

更关键的是效应按题变号。14 题 k=3 的 sd（Prep 0.090、Verifier 0.047）**高于**单轮 26 题，因为
剔除恒零题后残差主要是题间真实异质性，重复次数解决不了它。26 题里 12 题在所有历史运行中只有
一个分值，5 题只有两个分值。**不存在一个可估的"Prep 效应"或"Verifier 效应"。**

**机制侧是通的。** 交付链修复后，25/26 的 writer 在首轮就读了报告，凡交付了工具的 24/24 都跑了。
冻结成功率从 0/6 提升到 26/26。"东西没送到 agent"这个假设已被排除。

**已定位的两个真实副作用。** 一是清单定向优化：writer 会读检查器源码并优化到它，拿到"0 failed"
就停，而分数长在检查器覆盖不到的维度上。二是删减到通过：面对机械检查，删内容永远是最便宜的
通过路径。前者的对策是让检查永不报全清，后者的对策是 `output_shrank` 读数而不是新 gate。

因此迭代依据统一改为机制读数，分数只在机制门通过后用预先定好的剔除清单加多轮配对验证。详见
[ARCHITECTURE.md](ARCHITECTURE.md) 末节。

## 协议标识

**不使用手工递增的版本号。** 运行时对 prompt 与 schema 计算内容哈希，连同 git commit 写进
`task_prep_meta.json` 与 `verifier_meta.json` 的 `protocol_digest`。版本号会随改动膨胀且无法
反查真实内容，哈希不会。

## 目录规则

`docs/harness/` 顶层只放当前设计。逐轮机器结果与可复核案例进入 `results/`，旧 run 与旧分析进入
`archive/`。历史文件保留原名，避免丢失实验依据。版本演化日志已废止，其中的持久教训按有价值与
死路两类归入 [FABLE.md](FABLE.md)。
