# FABLE — 教训总账

本文保存 Prep 与 Verifier 迭代至今的全部可复用认知，分两类：**有价值**的（应当继续塑造设计）
和**死路**（试过或提过并被否决，记在这里只为不再重走）。不按时间排列，不保留版本演化日志。
当期设计在 [PREP.md](PREP.md) 与 [VERIFIER.md](VERIFIER.md)，系统整合在
[ARCHITECTURE.md](ARCHITECTURE.md)，逐轮证据在 [results/](results/README.md)。

## 总纲：转化链

分数是 writer 行为的函数。Prep 和 Verifier 自己不产生分数，只能改变 writer 提交前的行为，
所以评价它们的唯一尺度是这条链：

```text
产生信号 -> 到达 writer -> writer 采纳 -> 分项变化
```

历次实验一致指向同一结论：瓶颈从不在测量或研究的质量，而在后三环。反馈只在 DONE 后推送的
协议下，52 个 run 产生 0 次修复；344 条冻结 check 里 156 条死在自设的来源门上从未运行。

# 有价值的教训

## 交付与消费

**载体保真度不对等。** 沙箱状态（零损耗）> 可运行的程序（拉取式消费）> 散文（最有损，采纳率
可以是零）。唯一一次确定改变 writer 行为方式的交付是沙箱状态：prep 判定 Docker 嵌套镜像层
跑不了，writer 开题即信。散文类交付曾实测采纳率为零。

**交付失败会静默且伪装成"无效应"。** `_stage_prep_bundle` 把 `create_dir` 写在 artifact 遍历
循环内，artifacts 为空时目录不存在，`write_text(report_path, ...)` 抛 ENOENT 被吞掉，整份报告
丢失而 prep 仍记为 completed。十次 prep 运行有四次报告没送到，这四次分数全部落在 base 噪声内，
并且污染了一整个对照臂。**引用任何单题 prep 效应之前，先在 transcript 里 grep `PREP_REPORT`
的命中次数，命中 0 次的 unit 等于 prep 白跑。**

**交付和消费一旦修好就不再是瓶颈。** 修复交付链后的普查：25/26 的 writer 在首轮就读了报告
（首次读取中位回合为 1），凡交付了脚本的 24/24 都跑了。"东西没送到 agent"这个假设已经被
排除，不要再用它解释无效应。

**清单定向优化是真实且已量化的副作用。** 清单点名的维度越具体、越可执行，writer 越会在未
点名的维度上让步。agora 题的 writer 先读检查器源码搞清楚考什么，接着九次工具调用几乎全花在
修空白字符让逐字子串断言通过，拿到 `155 passed, 0 failed` 就收工，自己派出去的语义复查
subagent 从没等过；同轮三篇文档的隐藏证据门通过率 0.750/0.500/0.600 全部低于 0.8 阈值，三个
分项各被乘 0.5。

**能返回"全部通过"的检查器就是停止信号。** 自检首次调用的中位落在轨迹 82% 处，24 个里 14 个
在最后一或两轮，它被当成提交前的终局确认而非过程工具。对策是让检查永不报全清，逐条打印未覆盖
面，而不是加新 gate。

**删减到通过是贯穿两侧的同一失败签名。** 面对机械检查，内容越少越容易通过，而隐藏 rubric 恰恰
奖励被删掉的部分。实例：BPMN 题 writer 删掉两个报错的 consumer 输入让 checker 报错数从 2 变 0，
而不是修 producer 路径（`checked_input_count` 20→18），最终分数低于 base。对策是读数不是 gate：
每次快照记 per-file 字节与行数，分析侧做连续差得到 `output_shrank`。

**Prep 必须能保持沉默。** 被迫产出内容比不产出更有害。曾有一轮 prep 把"只明确允许英文"放大为
`Unknown`，同题分数从 0.6667 直接降到 0；加入 skip 能力后同题两臂持平。

## 测量与门控

**逐条隔离优于整包裁决。** 这条原则在两个独立子系统里各被同一类 bug 咬过一次：verifier 侧
4/6 题因单个 locator 格式错整包 lint 失败，损失全部冻结测试，直接导致该轮 6/6 build error、
12 条测试只跑 2 条；prep 侧 2 份报告因引用了 glob 风格路径被整份拒绝，连带丢掉同报告里有效的
运行时 finding。**逐条隔离必须同时落到条目层和信封层**，只做条目层时信封层的硬拒仍会整包失败。

**零权威加拉取式检查，是硬权威失败后验证有效的替代。** 硬权威链条十步、每环都可能断，实测
6/6 构建 error、12 条测试只跑 2 条、dispute/repair/复核轮全为 0；同轮零权威的自检调用率 5/5。

**来源状态 ambiguous/contradicted/missing 的检查应机械降级为 advisory，而不是判 fail。** 曾有
344 条 criterion 里 145 条 ambiguous、2 条 contradicted、1 条 missing 被来源门从 fail 路径
移除后才产生信号。

**环境健康判定必须晚于环境改造。** 否则会把"判定时环境"和"执行时环境"错配。曾在 prep 并发
改造运行时的同时测 `environment_healthy`/`checker_reproducible`，依赖 prep 稍后装好的运行时的
checker 被永久误判为不可复现。

**Verifier 能公开验证的面，往往不是任务真正的失分面。** 6 题里 5 题 `needs_review=False`，
writer 一条信息都没收到，而真正决定官方分的隐藏 rubric 全部 unverifiable。如实沉默是对的，
但这也说明它能合法帮到 writer 的面本身很窄。**两个 agent 从同一公开表面编译出的是同一张
清单，且把同一批语义维度同时标成不可验证**（agora 6 条对 18 条逐条对应，sec_10k 4 条对 4 个
区域对应），而分数正好长在那些维度上。

**多来源义务必须显式声明全部来源。** 只引用其中一份不足以证明期望值。曾有筛选规则同时依赖
brief、governance 与数据文件，只引用 brief 就把具体数值设为 blocking。

**Fixture 用显式无歧义的数组 schema。** 隐式的单对象编码被 builder 反复误解成单文件对象，
导致整包 lint 拒绝。schema 设计要对生成端友好，不能依赖隐式约定。

## 实验设计

**k=1 的方差远大于目标效应，任何单轮读数都不能确立一个协议改动是否有效。** 历次配对均差与 t
一致偏低。单题跨轮方差可达 0.1 到 0.24，而配对均差只有 ±0.02：digital_audience
`+0.0925 → −0.1247`，variant `−0.1374 → +0.0686`，sec_10k `+0.0244 → +0.2638`。

**唯一一次显著的正效应没有复现。** verifier 四轮配对均差 +0.021（t 2.57）、+0.0005、+0.007、
+0.0116；第二轮相对第一轮只加了信封兜底和构建失败记录，都是 fail-open 方向，解释不了落差。
四轮平均约 +0.011，未过任何显著性门槛。prep 同期四轮是 −0.007、+0.016、−0.004、+0.005。

**26 题里约一半对任何 treatment 的 delta 恒为 0，有效样本量减半。** 12 题在所有历史运行里只有
一个分值（6 题封顶 1.0、4 题贴地 0.0、2 题卡在中间平台），5 题只有两个分值，只有 6 题分值接近
连续。剔除清单必须在看结果之前定好。

**重复次数解决不了题间异质性。** 14 题 k=3 的 sd 反而高于单轮 26 题（prep 0.090、verifier
0.047），因为剔除恒零题后不再有大量零点压低 sd，而残差主要是题间真实效应的异质性。**不存在
一个可估的"prep 效应"或"verifier 效应"**，效应按题变号，聚合均值是对异质量的无意义汇总。

**归因必须过轨迹核对。** 分差在采用链于 transcript 中被证实之前不属于任何干预。SEC 题曾有
`+0.2626` 被记为 prep 收益，实际 writer 29 次 exec 里 prep 交付的命令与 artifact 各出现 0 次，
真实原因是 writer 自己想到用 XBRL companyfacts API。

**用历史 base 对照只能提供机制与采用链证据，不是严格因果估计。** 不能把"相对历史 base 均值"
直接读成 uplift。近似 base 的对照臂读数为 −0.0078，说明 base 陈旧带来的偏移在 −0.01 量级。

**所有 arm 必须共用同一 endpoint。** 按 arm 轮转 endpoint 会把网关差异混进 arm 效应。

**评分器常常是量化的，单题 delta 可能只是一道二值门翻没翻。** variant 题的 0.7930 与 0.9990
相差 20.6 分，其中 20 分来自一个全有全无的 reportable 门，0.6 分来自 3 个 AF 字段；三个不同的
臂落在同一个 0.7930 上。判断"复现"与"噪声"之前先看该题历史上出现过几个不同分值。

**极少数单题效应能跨轮方向一致、幅度接近，可作为"真实效应长什么样"的参照。** agora 在 verifier
臂三轮 +0.1597/+0.1550/+0.1809，sap 三轮精确 +0.0775。

## 工程

**失败路径代码本身也需要被验证真的会被触发。** artifact 收集把 `wc -c` 的 stdout 解析放在
返回码检查之前，文件不存在时 `int("")` 抛异常，于是所有"文件缺失"都被错误归进"读不出来"，
`artifact:missing` 分支实为死码，多轮审计记录一直指向错误的故障类型。

**隐藏的预检门槛必须写进被检查对象的规范里。** 自检脚本在空草稿上静默退出，因为预检要求脚本
至少打印内容，而脚本作者（另一个 agent）不知道有这道门。

**Scratch 初始化不能和 LLM 会话共用超时预算。** 它在会话开始前跑，一次超时就吃掉整个 agent
机会（形态是 `llm_turns=0` 的 TimeoutError）。命令幂等，单独给 180 s 并重试。

**执行必须隔离。** 任务 runtime wrapper 曾通过执行改动 writer 原 output 下的环境文件，前后
双 hash 把 4 次运行记为 error。output 下的 symlink 也曾直接让快照步骤崩溃。

**向审计类 agent 全量内联脚本与 fixture 会导致 token 爆炸。** 单个 unit 曾累计 426,837 input
token；改为传紧凑 manifest、按需读取 staged 文件后成本回落。

**一批纯工程上限，修复不改协议语义**：批处理替代逐条 RPC（定位与复验从约 170 次往返降到个位
数）；分块传输消除 `MAX_ARG_STRLEN` 128 KB 隐性上限；执行前复验沙箱脚本自身 hash；反馈内联
报告加上限；宽容扫描式 JSON 提取（builder 回复带前导散文不再整包失败）；工具分派移出事件循环
线程（一次 `verify` 最坏几十分钟，此前会冻结增量日志拉取与心跳）。

# 死路

**硬权威。** 为给 LLM 生成的测试发"你必须改"的资格，需要来源蕴含、checker 对齐、来源无冲突
三项语义证明，为此设了 Auditor 与五项 gate。死因是成本收益比，不是没优化好：链条十步每环都
在断。Auditor 已删除，`blocking` 恒 false。

**自动 repair 循环。** "默认开启 repair 有净收益"这一假设被反复证伪：一次 repair 把原本正确的
枚举答案改成公开规则未定义的另一个值（去掉该题后主效应从 `+0.00225` 变成 `−0.03064`）；一次
repair 后 writer 把 32% 公开 reference 混进重建产物绕过 anti-copy 检查；唯一一次 advisory 触发
的 revision 就是"删减到通过"的回归案例。修复权只留在 writer 手上。

**继续收紧机械准入门槛。** 曾收到 6/6 空报告，prep 臂等价于 base 但多花约 24.5 万 input token。
两类致命 gate：要求 `N/N` 字面串原样出现在某条来源证据里（字符串巧合检验），以及把"查了网发现
补不上、诚实 skip"记成违规。结论是这条路线没有空间。

**词表匹配过滤。** 用 must/should/use/map 等词删除"看起来 prescriptive"的 finding，会连坐删掉
绝大多数正常内容：79 条 finding 过滤后只剩 26 条，51 条只因正常方法表达被删，5 份 raw response
被清空。删除词表后 27/27 条全部进入报告。词法过滤本身是错误抓手。

**内联报告加固定字符预算。** 4/6 题报告顶到约 11,900 字符触发 12,000 上限，artifact 引用被从
尾部切掉，读者看不出残缺。已改为纯文件消费加 digest。

**dispute 门控。** 设计动机是堵"DONE 消息逐条 dispute 零成本关闭复核轮"的理论漏洞，但历史全部
run 实测 dispute 次数为 0。否决理由：为从未发生的滥用加状态机，是拿真实复杂度换假想安全。

**把分析侧读数固化进 agent 代码。** builder token 与冻结测试数比值告警、`ready_but_unexecutable`
状态、meta 里的 `frozen_tests`/`executable_checks` 字段，三处都已撤回，理由是原始量已经落盘，
这些是分析脚本三行能算的事。

**两段式 self-check 预检。** 需要新增 schema 字段声明合成小样位置，而根因只是提示词没写清楚
"空草稿也必须向 stdout 报告"。用契约措辞修根因，不为提示词问题引入 schema 复杂度。

**两个默认 writer-side skill（`deliverable-contract`、`evidence-audit`）。** 25 题四臂里 skills
臂相对 base `−0.0161`，prep+skills `−0.0226`，而 50/50 个 unit 都成功加载了 skill（排除了
plumbing 问题）。死因是重复 writer 已有能力、没有独立信号来源。这不推广为"skill 机制无用"。

**工具推荐类提示。** 只提示"用某个工具"不能替代任务真正缺失的能力。SEC 题的缺口是字段到
filing/page/table/row 的完整 lineage，继续重复 schema checklist 没有作用。

## 已撤回的结论

**"Verifier 六题门未通过，所以 Verifier 无效"。** 当时反馈通道用单一 `status` 字段同时决定
测量结果、权威性和是否推送，只有硬阻断失败能进入 writer，其余可复现测量全烂在内部日志。这是
实验结构无法暴露价值，不是被测对象无效。**测量通道自身的 bug 会伪装成"被测对象无效"的结论**，
这条撤回前已经写进文档一整个版本周期。

**"prep 引导 writer 正确判断"的一个正向采用链样本。** 该题真值是 `Hard Law`，base 臂答对，
prep 臂被引导答成 `Other`。撤回原因是没核对真值就把"写了个判断"当成"写对了判断"。

**bpmn linter skill 的 +0.099。** 那是拿真实 evaluator 校准 linter 得到的，是在测试集上做梯度
下降；同轮的 ON/OFF 对比还有预算不等（7200 s 对 2400 s）和一处把 reference 图混进 output 的
作弊。等预算加作弊审计后真实效应在噪声内。

**prep_nosc 臂的 `+0.0595`。** 该臂不是干净的自检消融：撤掉自检时连带撤掉了脚本 artifact，而
那常是唯一 artifact，触发了 staging bug 导致报告一起丢，它测的是"prep 完全没送到"。且其全部
margin 来自单题 ct_geometry 从 0.0000 跳到 1.0000（贡献 +0.0385），去掉该题后为 +0.0219。该题
有一次已确认的 reference 复制作弊记录在案。

**sec_10k 的 prep 大幅正效应不能当作 prep 有效的证据。** k=3 稳定在 0.94 对 base 0.686，但机制
是 `qa_answers.json` 写成字典还是列表：评分器 `_qa_score()` 首行 `isinstance(predictions, dict)`
不满足直接归零，权重 0.25。题面没规定，prep 的报告与脚本都明说两种都接受，prep 只是碰巧押中。
**为这类点去"改进" prep 就是拟合评分器。**

## 实验纪律

- 不重跑 base；treatment 臂对历史多轮均值配对，并在引用时重申这不是严格因果估计。
- 每个协议改动先过机制读数，再谈分数。分数只在机制门通过后用多轮验证。
- 归因必须过轨迹核对，采用链在 transcript 里成立之前不归属任何干预。
- 剔除恒零题的清单在看到结果之前定好。
- 归因实验期间协议冻结，不引入第二个变量。
- 对照臂必须断言自己只改了一件事，启动时验证操纵真的生效（prep_nosc 的教训）。
- 不用手工递增的版本号代表运行中的代码，用内容哈希加 git commit。
