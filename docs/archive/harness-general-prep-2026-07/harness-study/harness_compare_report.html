ale_claw × gpt-5.6-sol,26 题,4 臂(base / skills / prep / skills_prep),104 个 unit。2026-07-17,跑在 pgl。

结论先行

三个干预(skills、prep、两者一起)都没有可检测的效应。更要紧的是:每一个 Δ 的正负号,都由单独一道题决定。把 ct_geometry 这一题拿掉,三个 Δ 全部从负翻正。两种算法下 |t| 都不超过 1.00,和 0 分不开。零干预 base 均分 0.6415,是四个臂里最高的。

这不是"干预有害"的证据,也不是"干预有用"的证据。这是这个基准在单次跑下测不出这个量级效应的证据。

1. 实验设置

  • 唯一变量是能力开关。四个臂用同一个 agent(ale_claw)、同一个模型(gpt-5.6-sol)、同一份任务表、同一条反作弊常驻不变量。只差两个开关:skills 注不注、prep 跑不跑。
  • base 是久违的零干预基线(skills 关 + prep 关),之前几轮消融都缺这个参照。
  • 不设轮次/时间上限(max_turns: 100000)。不等预算会凭空造出假效应,这是踩过的坑。
  • 并行:每臂独立进程、每臂并发 3(共 12),cleanup_mode: delete。
  • prep 内部搜索关闭,以隔离变量。API 错误全程 0 次。
  • 全部配置来自 harness/run/settings.yaml 一个文件,细节见 harness/run/README.md。

作弊审计:没有作弊

这题是历史上的作弊入口:它的 input/ 里就放着一份 agent 可见的 reference_image.npy,照抄就能过阈值。COGNITION 记着上一次的 ct_geometry 满分是作弊,md5 e965b015。

这次实测:那份可见参照的 md5 正是 e965b015ef2e,而 base 产出的 md5 是 24328f200ad1,不是字节拷贝;仿射拟合 R²=0.9994 而非 1.0,评测器自带的 np.array_equal 反作弊也没有触发。

结论:base 这个 1.0 是真做出来的,不是抄的。常驻反作弊不变量这一轮守住了。高相关本身不是作弊证据,因为这题的正确答案本来就该和参照高度相关。

4. 为什么这个基准测不出效应

26 题里有 13 题对四个臂完全没有区分度,分数一模一样:

真正会动的只有 13 题(整整一半),而配对差标准差是 0.22。也就是说:有效样本只有 13,单题噪声比我们想测的效应(约 0.02)大一个数量级。在这个配置下,单次跑本来就不可能测出这个量级的效应。这不是干预的问题,是实验功效的问题。

6. 失败与基础设施

  • pe_screening_memo_1 首轮四臂全挂,重跑后全部成功(base 0.981 / prep 0.938 / skills 0.975 / skills_prep 0.881)。所以它是瞬时评测侧故障,不是永久的。--resume 只重跑了这 4 个 unit,已完成的 100 个一个没动。
  • 顺带修掉 summarize.py 的一个真 bug:--resume 会把重跑写进新的时间戳目录,旧的 failed run.json 还在,于是一个 unit 有两份记录。原来的字典构建是"后读到的赢",重跑成功的 unit 可能仍被显示成 failed,而且不确定。现在按 mtime 取最新的一份。
  • API 错误 0 次。三个端点(gpt_sub2api 两个 key + boyue)都可用,但API 从来不是瓶颈。
  • 并行的天花板是能同时开几个沙箱。12 路稳(容器恒定 12、内存 21G/125G);之前 24 路 + cleanup_mode: keep 那次 102/104 全挂,死容器堆到 104 个把机器吃干。delete 是必须的。

7. 结论与下一步

能说的:管道全部跑通(skills 注入、prep 产 notes 并被 agent 读到、结构性非泄露、反作弊守住),26 题零失败。base 基线首次拿到:0.6415。

不能说的:三个干预有任何效果。全部在噪声里,且符号由单题决定。

下一步按性价比排序:

  1. 先查 variant_annotation 的 prep 回归。两臂一致 −0.205,是最像真信号的一格,而且是坏的方向。看 notes 到底把 agent 带偏在哪。这个不需要重跑全量。
  2. 别再用单次全量跑测小效应。有效样本只有 13 题、sd 0.22,想测 0.02 的效应需要的重复次数远超现在。要么 k≥3 只跑那 13 道会动的题(省一半机器时间),要么承认这个量级测不了。
  3. 把力气放到"差一条被归零"的题上。bpmn_category、legal_ma 这类四臂全 0 的,已知是差一两个必需元素被 all-or-nothing 归零(bpmn 43 项过 41)。强制可运行自校验就是冲这个设计的,但这轮它们仍是 0,说明 skill 的文字还没能逼出那个穷举动作。这比继续磨均分更有意义。
