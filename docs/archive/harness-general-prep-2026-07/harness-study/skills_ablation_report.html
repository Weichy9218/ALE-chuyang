5. 两个 skill:原文 + 中文解释

deliverable-contract(构造题)

Use ONLY when a task asks you to PRODUCE
artifacts with checkable structure — named
output files, a schema/format, exact counts
or fields, code, or a model/workflow.

1 Enumerate the contract: every required
  artifact + every hard requirement (schema,
  counts, fields, naming). Quote the source.
2 Turn checkable requirements into checks;
  run any shipped runtime for real.
3 Build in dependency order; verify each part
  before moving on.
4 Converge: every requirement met + artifacts
  mutually consistent; re-scan for anything
  uncovered.
Boundaries: from the task's own materials
only; no grader scripts / reference answers.
中文:交付契约纪律。把题面要求当契约,先枚举每个必交产物和每条硬约束(schema/数量/字段/命名)并引原文,能机械校验的就写检查跑一遍,按依赖顺序分片实现、逐块验证,直到全部满足且文件互相一致。只用可见材料,不读评测脚本/参考答案。

evidence-audit(判断/审计题)

Use ONLY when a task asks you to review,
audit, compare, or judge documents/data and
report findings. Work = comprehension +
evidence, not building a checker.

1 Read sources closely before concluding.
2 Anchor every finding to quoted evidence;
  no unanchored finding goes in.
3 Be skeptical of references and of yourself;
  catch small textual/numeric discrepancies.
4 Cross-check consistency; state which source
  governs on conflict.
5 Report faithfully in the required form
  (incl. bilingual / per-field rules).
Boundaries: task's own materials only; do not
infer a hidden count/category/convention.
中文:证据审计纪律。判断题考的是理解和证据,不是写校验脚本。逐条为每个结论配精确引文,对参考和自身假设存疑、抓细小出入,交叉核一致性,按题面格式(含中英混合)如实交。不臆测题面没说的数量/类别。
设计来自 harness/skills/*/SKILL.md。frontmatter 的 name+description 常驻(约 20 token)当触发信号,正文按需拉取(渐进式披露)。

6. 轨迹里 skills 怎么被用(实测,非推测)

pi · sse(判断题,+0.33):pi 读了 deliverable-contract 共 15 次(没读 evidence-audit)。原话:"I'm writing the single required JSON file now. Each evidence [anchor…]"。也就是说 sse 虽是判断题,但要交结构化 JSON,pi 把它当契约:枚举字段、逐条锚证据。提分来自契约纪律,不是"证据审计"那个 skill。
ale_claw · tcga(构造题,+0.16 → 1.00):整局 memory_get 调用 579 次,拉 method-deliverable-contract 153 次、method-evidence-audit 76 次。重度依赖契约 playbook 把生存分析的交付物做全,拿到满分。
pi · bpmn_supply(构造题,双方涨):读 deliverable-contract 54 次,用契约纪律拆 BPMN 结构与三份 JSON。
共同现象:两个 agent 压倒性地拉 deliverable-contract,连 sse 这种判断题也当契约做;evidence-audit 触发少、独立作用不明显。因为 ALE 多数题最终都要交结构化产物,"构造 vs 判断"的边界在实际中被模糊了。ale_claw 的 memory_get 高达 579 次,有过度检索之嫌。

7. skills 还该怎么优化

  • deliverable-contract 是被证实的主力,继续打磨;evidence-audit 触发少、效果不明,先单独在纯判断题上验证它是否真有独立价值,不成立就并入 contract(多数判断题也交结构化产物)。
  • 治 ale_claw 的过度检索(memory_get 579 次):首次拉到 method 后缓存进上下文,别每步都搜;或把索引直接写进常驻 prompt(像 pi 那样),省掉反复检索。
  • 查回归、加护栏:moodle(pi −0.13)、digital_audience(claw −0.22)在带 skills 后掉分,疑似契约纪律让本已简单的题被过度约束。给 skill 加一句"任务已简单直接时不要强加流程"。
  • 压噪声:单次跑,均分 Δ(pi +0.034、claw +0.026)和多数逐题变动都在噪声底内(pi sd≈0.09、claw≈0.20)。对大变动题(sse、tcga、variant、digital_audience、moodle)做 k≥3 重复,才能分清真效应与随机。
  • 补裁判 API:pe_screening 四臂全挂,把裁判指向 boyue(gpt-4o-mini 缺失,用 gpt-5-mini 替代)才能让这题进对比。
