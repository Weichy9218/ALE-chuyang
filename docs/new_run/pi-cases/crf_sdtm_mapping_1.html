题目本身

在 Linux 上为研究 C4591001 编写字段级 CRF→SDTM 映射规格；base 变体针对合并用药（Concomitant Medications，CM 主域 / SUPPCM 补充域）。需读取样例 CRF、注释 CRF（aCRF）两个 PDF 及 sdtm_define.xml / adam_supp_define.xml，识别每个采集字段到 SDTM 目标变量的映射，产出唯一 CSV output/cm_mapping.csv。属于"复现人工金标准映射表"类任务。

要求

保存唯一文件 output/cm_mapping.csv，表头必须精确等于 11 列（crf_form, crf_field_label, crf_item_or_placeholder, sdtm_dataset, sdtm_variable, role, origin, mapping_rule, controlled_terms_or_expected_values, goes_to_suppqual, notes）。每行对应一个"CRF 采集字段→SDTM 变量"，不得添加派生/协议级/结构性 SUPPQUAL 行；crf_form 用带简码的完整表单名；crf_field_label 与 placeholder 须逐字照抄、不带方括号或自造后缀；mapping_rule 与 notes 须字段特定并点名目标变量。参考答案 37 行（source_manifest.json: "reference_row_count": 37）。

评测方法

main.py 仅做存在性检查后调用 scripts/score_crf_sdtm_mapping.py 的 score_mapping_csv，返回 [float(result.score)]。该函数是二值评分，末行 "score=1.0 if passed else 0.0"。流程：(1) _parse_csv 要求表头精确等于 11 列 OUTPUT_COLUMNS，否则 errors→立即 return 0.0；(2) _index_rows 逐行校验（sdtm_dataset 必须∈{CM,SUPPCM}；goes_to_suppqual∈{YES,NO} 且与域一致；mapping_rule 非空且用正则点名 sdtm_variable；notes 非空；复合键唯一），任一 error→立即 return 0.0；(3) 以 KEY_COLUMNS=(crf_form, crf_field_label, crf_item_or_placeholder, sdtm_dataset, sdtm_variable) 建索引，算 missing_keys=参考−agent、extra_keys=agent−参考；(4) 对交集键逐列比较 EXACT_MATCH_COLUMNS（除 mapping_rule/notes 外的 9 列，normalize 空白后精确相等）；(5) passed = 无 missing 且 无 extra 且 无 mismatch。全程没有任何部分分路径。对照：_4（域为 Adverse Events/Demography）的同名脚本在 strict 不过后追加 relaxed 层——按 (sdtm_dataset, sdtm_variable) 匹配，score=row_coverage×avg_column_accuracy，docstring 明言 "giving partial credit for identifying the right variable set even when formatting differs"。这正是 _1=0 与 _4≈0.60 的根因（exact-string vs coverage）。

模型执行过程（逐帧）

OFF（35 步，bash×21/read×2/write×1）：读 task_brief.md、output_contract.json；pdfinfo+pdftotext 抽 aCRF 第 15/16/76/110 页；rg 在 sdtm_define.xml 查 IT.CM.*（CMDOSE/CMROUTE/CMENDTC 等）与 CodeList（CMCAT/UNIT/FREQ/ROUTE/ENRTPT）；xmllint 不存在（127）后改用 rg/python 解析；试 apply_patch（command not found）后改用 write 写出 13273 字节 CSV；步 31–34 自查："rows 32"、11 列、复合键唯一、"all_target_variables_present_in_define True"。ON（21 步，bash×9/read×2/write×1）流程相同但更短：写出 10182 字节、24 数据行，步 19–20 自查 "validated: 24 data rows, 11 columns, unique composite keys / non-empty"。两跑都验证了文件存在与 schema，但都无法比对隐藏参考（reference 在 reference_dir，不在 input，模型看不到金标准的确切标签/取值）。

哪里做错了

用真实评分器复跑（远端直接执行 score_crf_sdtm_mapping.py）：OFF score=0.0，missing_keys=30/37、extra_keys=25、mismatches=7、errors=0；ON score=0.0，missing=34、extra=21、mismatch=3、errors=0。errors=0 证明产物本身合法（notes 非空、mapping_rule 点名变量、域/supp 一致、无重复键），0 分完全来自键集不匹配 + 二值悬崖。具体偏差：(a) crf_field_label 带冒号——模型写 "Category:"/"Dose:"/"Medication:"/"Route:"/"Start Date:"/"Dose Frequency:"/"Dose Unit:"/"Date:"，参考为无冒号的 "Category"/"Dose"/"Medication"…，而 crf_field_label 是复合键的一部分，于是每个这样的行同时成为一个 extra_key 与一个 missing_key；(b) 多写了参考没有的 CMDOSTXT 行（参考在 notes 明说 "free-text dose detail is separately not submitted as CMDOSTXT"）；(c) 少数键确实对上的行上 controlled_terms_or_expected_values 仍失配：CMSPID 参考为空串、模型填 "Sponsor-defined identifier (text, maximum length 2 per define.xml)"；某 Y/N 派生变量参考直接写 "ONGOING"/"LAST SUBJECT ENCOUNTER"，模型写 "YES -> ONGOING; NO -> null"；(d) origin 分歧，如 CMCAT 参考 origin=CRF、模型=Assigned。(c)(d) 属参考里"未公开的编辑取舍"，从 PDF/define.xml 无法可靠反推。把同一 OFF 产物用覆盖式算法（按 dataset+variable 匹配）估分：matched=28/37、row_coverage=0.757、avg_col_acc=0.565、乘积≈0.428；ON≈0.317——即内容质量本可拿到与 _4 同量级的部分分，只因 _1 用二值器而被归零。

怎样才能做对

在 _1 的二值评分下拿分只有一条路：逐字节复现 37 行金标准——crf_field_label 去掉冒号（与参考一致）、不额外加 CMDOSTXT、把 controlled_terms 的编码或留空、origin（CRF vs Assigned/Derived）、role 名称以及恰好 37 行的取舍全部猜中。其中冒号与 CMDOSTXT 属指令遵循（"逐字照抄"处参考恰好去了冒号并排除 CMDOSTXT），模型本可对齐、能挽回若干 missing/extra 键；但 controlled_terms 空/满、origin、role 等属金标准的主观编辑取舍，仅凭可见 PDF/define.xml 无法确定性反推，因此在二值器下本题对任何 agent 都近乎不可通关——这是评分器问题而非能力问题。真正的修复应在评分侧：把 _1 换成与 _4 相同的 relaxed 覆盖式给分（score=row_coverage×avg_column_accuracy），届时该模型产物约得 0.4+。

harness（ON）的效应

OFF 与 ON 分数都是 0.0，harness 对分数零效果。机制：ON（mirror）只重述预算/交付物/防抖提醒；OFF 下模型本就已写出文件并自查（步 31–34 验证行数/列数/键唯一/目标变量齐全），故 M1（先写必需文件）、M2（交付物存在且非空）冗余；M3（对照 input 内参考迭代自查）根本未触发，因为参考在隐藏的 reference_dir 而非 input，且评分为隐藏精确匹配，模型看不到金标准；M4 与本题无关。ON 反而更短（21 vs 35 步、24 vs 32 行、覆盖估分 0.317 vs 0.428），是运行方差导致产出更薄，但因二值悬崖两跑同为 0，harness 未改变分数。结论：失分点在评分器的精确匹配悬崖，mirror 类提醒无从触及。
