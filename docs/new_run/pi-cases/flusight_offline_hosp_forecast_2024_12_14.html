模型产出了合理的州级流感住院预测（平均 WIS 101.0、压到朴素基线的 26%，得 0.7408），但点预测系统性单向低估这轮真实激增——208 个计分行里 32 行观测值突破了自身的 95% 上界（反方向 0 行）触发 40× 惩罚、占 30% 的 WIS；离满分 1.0 的差距主要是预测本身不可约的不确定性加这段低估偏差。

题目本身

在离线 Linux VM 上，基于截至 2024-12-14 的冻结历史周度住院快照，做 FluSight 式流感住院预测：为 53 个辖区（含 US）× 4 个未来目标周（2024-12-21、12-28、2025-01-04、01-11）各给出点估计与 95% 区间 [lower_95, upper_95]，写出恰好 212 行的 output/submission.csv。禁止联网与外部文件。评分用类 WIS 指标，把提交与隐藏的真实未来观测值逐行比较。

要求

唯一交付物 output/submission.csv，8 列固定顺序 (reference_date, location, location_name, horizon, target_end_date, point, lower_95, upper_95)；reference_date 恒为 2024-12-14；horizon∈{1,2,3,4} 且 target_end_date=参考日+7*horizon 天；point/lower_95/upper_95 为非负整数且需满足 lower_95≤point≤upper_95；恰好 212 行、键 (location,target_end_date) 与隐藏真值一一对应、location_name 需与真值一致。evaluate_submission.py 对列名/行数/键/整数/区间序做硬校验，任一不符直接抛异常，evaluate() 返回 [0.0]。

评测方法

评测在 evaluate_submission.py 逐行算 WIS（ALPHA=0.05）：interval_score=(u−l)，若 y<l 再加 (2/ALPHA)(l−y)=40(l−y)，若 y>u 再加 40(y−u)；wis=(0.5·|y−m| + (ALPHA/2)·interval_score)/(1+0.5)，即 |y−m|/3 + IS/60。主指标 primary_metric_mean_wis_95_excluding_us = 排除 US 的 208 行平均 WIS（US 行只进 diagnostics）。score_outputs.py 归一化：score = clamp(1 − candidate_wis / 389.80288461538464, 0, 1)，分母是 scoring_baseline.json 里朴素基线（最近观测值平推、零宽区间）的平均 WIS——此时 coverage=0、WIS 退化成 MAE（389.803）。满分要求 candidate_wis=0，即每行 point=lower_95=upper_95=观测值（完美预知未来），故 1.0 实际上不可达。

模型执行过程（逐帧）

OFF 与 ON 两个 run 方法同源：读 task_prompt/output_contract/schema/template/locations/历史 CSV（OFF step3-11），构造『全国季节性轨迹 × 州级分配 + 分位残差区间』。OFF（40 步）先用裸 python3 解析历史 CSV 报 ValueError（step14-15，字段非数值），改用 software/python_with_task_deps.sh 建 venv 跑 pandas（step20 起），做 pooled 回测按州规模分组（small/medium/large/xlarge）标定区间宽度（step27-31），step34-35 写 submission，step36-39 自检 schema/212 行/整数/区间序（『PASS: schema, 212 unique template keys...』）。ON（29 步）流程相同，但用『历史 kNN 轨迹段』拼接（step15），全国轨迹外推明显更激进（US 点 h1..h4=13000/19500/24000/23000，OFF=12926/17146/18641/19784），上界更宽（US upper95 h3=52800 vs OFF 30761），step27-28 自检通过收尾。两者都在结束前验证了输出文件与 schema，没有无效重复读写。

哪里做错了

失分核心是点预测系统性、单向地低估这轮加速的真实激增。OFF 平均绝对误差 MAE=239.07，占 WIS 的 78.9%；且 208 个计分行里有 32 行观测值 y 超出它自己的 95% 上界 u（反方向 y<lower_95 为 0 行），触发 40× 惩罚，这 32 行贡献了 30.2% 的总 WIS、coverage 只有 0.8462。峰值周（horizon 3, 2025-01-04）尤其惨：New York 观测 2594／点 858／上界 2153，Pennsylvania 2031／598／1684，Ohio 1302／356／1006，Missouri 827／177／578，Illinois 1595／481／1356——点估计低估 2-3 倍且 95% 上界都没盖住。调用者给的 Alabama 例（点 [302,388,454,448] vs 观测 [432,661,684,473]）也确系点低估，只是 Alabama 上界 [563,899,1281,1490] 恰好盖住，损失走中位误差项而非 40× 惩罚。根因是全国轨迹过早走平（h3→h4 仅 18641→19784，+6%），没跟上季节中段的加速。

怎样才能做对

要点是在季节早升段给激增留更大的右尾、并让点预测跟上加速：(1) 全国/州轨迹改用更激进的指数/增长外推——识别当前处于上升段、按历史相似季的加速率外推，而不是均值回归走平；(2) 95% 上界显著加宽并右偏，历史激增季 h3/h4 的上分位应能覆盖 2-3 倍于点估计的值。ON 正是这么做的：把 coverage 从 84.6% 提到 96.2%、突破 40× 惩罚的行从 32 降到 8、突破占 WIS 从 30.2% 降到 5.2%，score 由 0.7408 升到 0.7736。但需诚实说明：满分 1.0 要求 point=lower=upper=观测值（精确预知未来 4 周），任何真实预测都不可能达到；0.7408 已把 WIS 压到朴素基线的 26%，残差里很大一块是不可约的预测不确定性，真正可改善的只有『低估偏差 + 过窄上尾』这部分，故此损失不是评分器缺陷、也非 harness 可解。

harness（ON）的效应

ON 相对 OFF：行为上换成 kNN 轨迹拼接、全国峰值外推更高、区间更宽；分数 0.7408→0.7736（+0.0328），coverage 0.8462→0.9615，突破上界的行 32→8，突破行占 WIS 30.2%→5.2%。但这不能归功于镜像 harness：真值藏在 reference_dir（不在 input 目录），M3『对照输入内参考重算直到达标』因此没有任何可见参考对应到计分量（WIS），镜像对预测精度零信息、纯冗余（两 run 本就都自检了 schema/文件存在，M2/M4 也无额外增益）。所以 OFF→ON 的提升本质是同一类方法在不同 run 上『恰好把增长外推得更激进 + 上尾更宽』的抽样波动，正巧撞上真实激增而占便宜，并非 harness 注入了未来信号——即调用者所说 delta 在噪声范围内。
