题目本身

在 Linux VM 上复现一份“公开合成数据的医疗算法偏见审计”（Obermeyer 式 cost-vs-need 分析）。要求先按 bias.yml 里锁定的包版本搭好 Python 与 R 环境，再把 input 里既有的工作流脚本（code/model/main.py、code/table2.py、code/figure1/figure1b.R、code/table3.R）按依赖顺序原样跑一遍，生成 5 个结果 CSV；据此填 audit_answers.json（16 个字段）并写一份面向临床分析负责人的 audit_memo.md，且必须用本次公开合成复现的数值、区别于论文私有数据的 17.7%→46.5%/59%。

要求

output/ 下必须且只能有 7 个交付物：results/{model_lasso_predictors.csv, model_r2.csv, table2_concentration_metric.csv, figure1b.csv, table3.csv}、audit_answers.json、audit_memo.md。约束：不得修改暂存数据集；不得把 race 加进模型特征；不得替换供给的分析流水线；不得用论文私有的 17.7%→46.5% 或 59% 作为作答值；临时文件须清理，只留这 7 个交付物。

评测方法

两层硬闸，全有或全无。(1) main.py evaluate：`observed_files = find output -type f`，若 `observed_files != set(REQUIRED_OUTPUT_FILES)`（严格 7 个文件，多一少一都算）→ `return [0.0]`。(2) scripts/score_outputs.py 的 score_output_bundle：`NUMERIC_TOLERANCE = 1e-6`，按 REQUIRED_OUTPUT_FILES 顺序（figure1b→model_lasso_predictors→model_r2→table2→table3）对每个 CSV 调 `_compare_csv`——表头必须完全相同、行数必须相同、每个单元格 `math.isclose(candidate, reference, rel_tol=0.0, abs_tol=1e-6)`，任一格不符即 `_hard_fail("<name>: value_mismatch")` 直接 0 分；再 `_compare_json`（3 个字符串字段精确匹配、其余数值 1e-6）、`_check_memo`（若干关键词 + 数值锚点）。只有全部通过才 `ScoreResult(1.0, True, "passed", ...)`。因此任何一格差异都会一票否决。

模型执行过程（逐帧）

OFF 与 ON 两条轨迹几乎一致（59/58 步，工具直方图 read~15、bash~22、write 2）。步 5–19：读 task_note.txt/bias.yml 与四个脚本、data_dictionary，探测到 Python 3.14.3 与系统 R 4.5.3、有 micromamba。随后用 conda-forge 建定制 Python 环境（OFF 走路径环境 .pyenv 并降到 scikit-learn 0.24；ON 建命名环境 bias-public-replication，python3.10 + numpy1.23.5/pandas1.5.3/sklearn1.1.3），把 input/code+data 拷到 output/work，cd 进去按序跑 model/main.py、table2.py（Python）与 figure1b.R、table3.R（R）。关键点：R 一律用系统 R 4.5.3，两次都没有按 bias.yml 去装 r-base=3.5.1。跑完读回 5 个 CSV，抽取数值写 audit_answers.json 与 audit_memo.md，把 results/ 拷回 output/。两次都做了“Validated 13 numeric answers against generated CSVs”式自检（OFF 步 56、ON 步 57），并清理临时文件（OFF 步 57 rm -rf work/.pyenv 等）。最终 output/ 恰好留 7 个交付物（output_gather_done files=7）。两条轨迹产出的 table3.csv 完全一致，随机行 frac_black 都是 0.115。

哪里做错了

评分器按 CSV 顺序比到最后一个 results/table3.csv 时，第 2 数据行“Random, in predicted cost bin”的 frac_black：候选 0.115 ≠ 参考 0.177（|差|=0.062 ≫ 1e-6）→ 硬失败，score=0。该行是 table3.R 里 `set.seed(12345)` 之后用 `sample(seq_len(nrow(df_bin)), size=samp_size)` 在每个预测成本分箱内随机抽样得到的“随机基线”，而它并不在需要上报的 4 个 table3 字段内（上报的是 g0/g2/g3/g4：Observed=0.224、Predicted-health=0.308、Highest-cost=0.218、Worst-health=0.367，全部与参考逐格精确命中）。根因是 RNG 跨 R 大版本不可复现：参考答案由 bias.yml 锁定的 r-base=3.5.1 生成，VM 却是 R 4.5.3；R 3.6.0 改了 sample() 的默认离散均匀采样器（sample.kind 由旧的 Rounding 改为 Rejection），同一 seed 抽出的下标不同 → 随机行三列（frac_black/frac_cost/frac_health = 0.115/0.026/0.022 vs 参考 0.177/0.028/0.023）都不同。证据闭合：g0/g2/g3/g4 用的是确定性 `order()` 排序、不涉随机，且与参考逐格相同，说明候选的 model_lasso_predictors.csv 对这些计算与参考等价，唯一发散点只能来自 sample() 的 RNG；OFF、ON 两次都精确得到 0.115，说明是 R 4.5.3 下的确定性结果而非偶发。此外 figure1b/model_lasso_predictors/model_r2/table2 四个 CSV 与整份 audit_answers.json（含 model_r2_gagne_on_gagne_hat=0.7326520763970079 等）其实都已通过 1e-6 比对——距离满分只差这一随机行。

怎样才能做对

要拿满分必须复现参考的 RNG。正确做法是把 bias.yml 里 `r-base=3.5.1` 的锁定当真：用 conda-forge 装 R 3.5.1 来跑 table3.R——3.5.1 属 R 3.6.0 之前，sample() 用旧的 Rounding 采样，set.seed(12345) 的抽样与参考一致，g1 会回到 0.177，全表即可 1e-6 命中。等价兜底是在 table3.R 的 set.seed 前插 `RNGkind(sample.kind="Rounding")`（但这算改脚本，与“不得替换供给的流水线”存在张力，且需要模型主动意识到该问题）。模型可改进之处：不要把“满足版本约束（或功能等价版本）”一律理解为“系统自带的新版就行”——对确定性数值分析 R 4.5.3 确实等价，但对“带 seed 的 sample() 且要逐格复现参考”的场景，跨过 R 3.6.0 就不再等价；bias.yml 明确钉死了 r-base=3.5.1，这是本可执行且被忽略的杠杆。另一面这也确是评测脆弱性：把一行既不在上报清单、又跨 RNG 版本不可复现的随机基线纳入 1e-6 硬比对，本身容易误杀（更稳健的评分应对该行放宽容差或直接排除随机基线）。因此属于 mixed：可由 agent 修（钉 R 3.5.1），但触发条件是相当隐蔽的 RNG 复现细节，且被题面“功能等价版本”的措辞与评分器的过严设计共同放大。

harness（ON）的效应

ON 与 OFF 的行为和分数完全一致（都 0.0，两次 table3.csv 逐字节相同、随机行都 0.115）。M1–M4 只是镜像式提醒，这里全冗余：模型本就验证了交付物存在/非空、对自己生成的 CSV 做了数值自检、清理了临时文件、没有无谓重复失败命令。尤其 M3（“对着 input 里暂存的参考自查、迭代到达标”）根本无从发力——input 里的 audit_answers.json 是占位模板（figure1b_percentile_97_before=0.0），并无真实目标，也没有参考版 table3.csv；模型只能对自己的输出自查，而自查恰会通过（上报值确实忠实反映了自己那份 R 4.5.3 生成的 CSV）。真正的失败点是隐藏参考在一个不上报的随机行上的 RNG 差异，任何镜像提示都看不见、也纠不了。ON 唯一实质差别是改用命名 conda 环境、output 下少了些环境目录要清理，但对最终评分无影响。
