模型 gpt-5.6-sol，pi harness，haoxiang 网关，100 轮上限。每题拆到题目、要求、评测方法、模型执行、哪里做错、怎么做对。OFF 为无 harness 基线，ON 为加了提醒类 harness（M1 预算 / M2 交付文件 / M3 指标自检 / M4 防打转）。

满分只有 8 题，零分 6 题，其余多数卡在 0.5 到 0.85 的部分分。均分被大量"部分对"的题拉在 0.59。这条分布本身说明：这批题对 gpt-5.6-sol 不是"会不会做"的二元问题，而是"能做到多准、多合规"的连续问题。

但这个 0.593 低估了模型的真实能力。逐题查下来，相当一部分失分不是模型做错，而是评测器本身的脆：精确字符串匹配自由文本、隐藏的 JSON 键名/列名白名单、全有或全无的打分悬崖、跨版本不可复现的随机行，甚至一次评审 API 崩溃。把这些"评测扣分"按合理评测还原，模型的真实水平明显更高：

二、harness 的价值：现阶段的提醒类 harness 没有价值

把 harness 从关到开，均分 0.593 → 0.588，几乎不动，且方向朝下。提醒模型"检查交付文件是否写全"（M2）、"注意题目里的指标阈值"（M3）、"别重复失败命令"（M4），在这 26 题上没有带来可测量的提分。逐题查下来原因很一致：这些提醒说的事，模型本来就在自己做。它交付前会自己 ls / cat / 跑校验，有量化目标时会自己反复算指标，几乎不做无意义重复。镜子把模型已经在做的事又说了一遍，自然不产生新信息。
更要紧的是，提醒类 harness 有反作用的风险。在唯一能触发 M3 的 ct_geometry 上，"对着 input 里的参照一直迭代到达标"这条提醒，把模型逼成了作弊：它把参照图逐字节拷成了自己的输出（md5 与参照完全一致），假报 SSIM=1.0，只被评测器的反作弊挡下判 0。把参照指给模型看，本身就危险。详见 ct_geometry 逐题页。

唯一一处 harness 做成了它设计要做的事，是 bpmn_category：OFF 跑到最后一步才开始写、output 目录空着、被"必需文件"门槛判 0；ON 在 M1/M2 提醒下写全了 5 个交付文件、还自查了一遍。但分数仍是 0，因为这题的评测是全有或全无，缺的是模型给不出的正确 BPMN 拓扑和角色。所以提醒能把"空输出"变成"有输出"，却换不来分——空输出只在旧的 30 轮上限下才是主要失分点，100 轮上限已经基本消除了它，剩下的是内容对不对，而内容不是提醒能解决的。

分类说明：模型能力指真能力天花板（亚像素配准、真实流感高峰预测、生命周期判定）；评测artifact指数值/实质对、只因评测器脆而失分；模型执行指语义理解或指令跟随的偏差；混合指一处真实内容错、又被评测器的全有或全无门槛放大（多数部分分题属此类，其中"被放大"那半通常也是评测脆）；满分指两条件都 1.0、没有空间。

模型能力和评测artifact两类都不是提醒类 harness 能碰的。模型能力那类要靠更强的模型；评测 artifact 那类（精确字符串匹配自由文本、隐藏的 JSON 键名白名单、全有或全无的打分悬崖）要靠出题方改 scorer，给出来就等于泄露答案。典型如 tcga：统计量全对，只因 ph_test 的 JSON 写成 {method,results} 而非评测器认的顶层键 dict，就被从 1.0 压到 0.84。
