题目本身

在 Linux 上为研究 C4591001 编写字段级 CRF→SDTM 不良事件（AE）映射规范。给定 sample_crf.pdf、annotated_crf.pdf、sdtm_define.xml、supp_define.xml，需识别每个 CRF 表单字段对应的 SDTM 目标变量（AE 主域或 SUPPAE 补充限定符），并按 output_contract.json 规定的 11 列顺序输出唯一一个 CSV（output/ae_mapping.csv）。只做映射规范，不产生受试者级记录或 XPT 数据集。

要求

输出唯一文件 output/ae_mapping.csv，列顺序严格为 crf_form,crf_field_label,crf_item_or_placeholder,sdtm_dataset,sdtm_variable,role,origin,mapping_rule,controlled_terms_or_expected_values,goes_to_suppqual,notes。约束：sdtm_dataset 只能是 AE 或 SUPPAE；goes_to_suppqual 对 AE 行须为 NO、对 SUPPAE 行须为 YES；(crf_item_or_placeholder,sdtm_dataset,sdtm_variable) 复合键不得为空或重复。参考答案 ae_mapping.csv 共 38 行（reference_row_count=38），存放在 reference_dir，agent 看不到。

评测方法

main.py 的 evaluate() 读入 agent 与 reference 两份 CSV，调用 scripts/score_crf_sdtm_mapping.py 的 score_mapping_csv()。两层评分：(1) 严格层——复合键 (crf_item_or_placeholder,sdtm_dataset,sdtm_variable) 上逐行逐列全等才 strict_score=1.0，任何一格不符即 strict=0（`strict_passed = not missing_keys and not extra_keys and not strict_mismatches`）。(2) 松弛层——strict 失败后启用：只把“行的配对”放松为按 (sdtm_dataset,sdtm_variable) 匹配（SUPP 行还有 QVAL 子串回退），但配对成功后 `_compare_columns` 对全部 11 列用 `normalize_cell`（仅 strip+压缩空白后的字符串全等）逐列比较；最终 `score = row_coverage * avg_column_accuracy`。关键：11 列全部是精确字符串匹配，没有任何一列做语义判定；松弛的只是行配对，不是单元格比较。full-credit（strict=1.0）需要每格逐字符命中参考，缺参考文件时不可能达到。

模型执行过程（逐帧）

OFF（52 步，read×21/bash×15/write×1）：读 task_brief 与 output_contract；用 pdftotext 抽 annotated/sample CRF 文本、rg/lxml 解析 sdtm_define.xml 与 supp_define.xml 枚举 AE/SUPPAE 变量、CodeList、Method；步[45] 一次性写出 40 行 CSV；步[48-51] 自建 Python 校验：确认 rows=40 AE=35 SUPPAE=5、unique_composite_keys=40、`AE targets absent from define: none`、`SUPPAE QNAMs absent from define value metadata: none`、文件类型与行数——即未经 harness 已充分自检输出。ON（30 步，read×5/bash×14/write×1）走法几乎相同，步[26] 写出 39 行，步[28-29] 做了一次较轻的 PASS 自检。两次都正确识别出与参考完全一致的 38 个目标变量集合。重跑评分器：OFF row_coverage=1.0、avg_column_accuracy=0.6053、strict_score=0.0、compared_rows=38；ON row_coverage=1.0、avg_column_accuracy=0.5981、strict_score=0.0——分数完全等于列精度，行覆盖满分。

哪里做错了

丢分不在‘映射对不对’，而在‘措辞是否与参考逐字符一致’。重算 38 行的逐列命中：结构性列全对——crf_form 38/38、sdtm_dataset 38/38、sdtm_variable 38/38、goes_to_suppqual 38/38（即数据集归属、目标变量、补充限定符标志全部正确）。丢分集中在：mapping_rule 0/38、controlled_terms_or_expected_values 6/38、role 7/38、notes 7/38(ON 3/38)、origin 20/38、crf_item_or_placeholder 29/38、crf_field_label 32/38。共 418 格错 165 格，最大贡献者：mapping_rule 错 38、controlled_terms 错 32、role 错 31、notes 错 31、origin 错 18。典型 0 分成因全是‘合理但措辞不同’：mapping_rule 参考 'Map sponsor-defined AE identifier directly.' vs 模型 'Map the sponsor-defined AE identifier directly.'（仅多一个 the）、参考 'If ongoing=NO, convert collected end date/time to ISO 8601 character datetime; otherwise leave null.' vs 模型 'If the event is not ongoing, combine the collected end date and time and represent in ISO 8601 format; otherwise leave null.'；controlled_terms 参考 'Free text / sponsor-defined identifier'、'ONGOING when YES' vs 模型 'Sponsor-defined identifier'、'ONGOING or blank'；notes 参考写具体页码 'aCRF page 11 shows AECAT; sample CRF page 2 shows Category=ADVERSE EVENT.'（且 38 行中 20 行 notes 为空），逐字符不可复现。role 与 origin 还叠加了参考键的武断收窄：role 参考用完整 CDISC 分类（Synonym Qualifier×12、Record Qualifier×7、Result Qualifier×6、Supplemental Qualifier×5、Timing×4、Topic×2、Identifier×2，无一个是裸 'Qualifier'），模型对约 31 个限定符行统一写 'Qualifier'，只命中 Timing/Identifier/Topic 这 7 行；origin 参考只用 {CRF/aCRF×21, aCRF×17} 两个值，模型对常量/派生变量给出更标准的 'Assigned'/'Derived' 反被判错（20/38）。

怎样才能做对

对本评分器‘做对’＝逐字符复刻隐藏参考的每一格，缺参考文件时结构上不可达（strict=1.0 需 418 格全中）。可由 agent 改善的只有小片：(a) role 改用严格 CDISC 角色分类（MedDRA 编码派生变量=Synonym Qualifier、AEOUT/AEACN/AETOXGR=Result Qualifier、SUPPAE 行=Supplemental Qualifier、NY/严重性等=Record Qualifier）可把 7/38 升到 ~30/38，但参考把 AECAT 记作 'Topic' 等特异写法仍会扣分；(b) origin 若模仿参考只用 aCRF/CRF-aCRF 两值可多命中，但这要求逐页读 annotated CRF 且放弃更规范的 Assigned/Derived。即便 role/origin 全对，分数上限也只约 (253+31+18)/418=0.72，因为 mapping_rule(0/38，纯散文)、notes(含逐字页码引用)、controlled_terms 这些自由文本列在没有参考时无法逐字符命中。结论：约 116/165 丢分格是纯精确匹配伪影、不可由 agent 修复；正确修法在评分器一侧——对 mapping_rule/notes/controlled_terms 等自由文本列改用语义/LLM 判分或规范化受控词表，而非 strip 后字符串全等。

harness（ON）的效应

ON 比 OFF 低 0.0072（0.5981 vs 0.6053），二者都 completed。两次产出的映射在实质上完全相同：11 列中有 9 列逐列命中数字节一致，整个差距只来自自由文本 notes 列（OFF 命中 7/38，ON 命中 3/38），被 crf_field_label(+1) 部分抵消，净差 −3 格/418=−0.0072。机制：ON 在 notes 列写得更满（仅 5 个空单元格 vs OFF 的 11 个），而参考 38 行里有 20 行 notes 为空，ON 与这些空白单元格对齐得更少，精确匹配数反降——纯粹是自由文本抽签噪声，不是 mirror 带来的行为改进或退化。mirror 提示在此冗余：M3（对照参考反复自检）无法触发，因为参考 CSV 在 reference_dir、input_dir 里根本不可见；而 OFF 在无 harness 下已自建校验（步[48-51] 证实行数、复合键唯一、全部 AE 目标与 SUPPAE QNAM 都在 define.xml 中：'AE targets absent from define: none'），M1/M2/M4 未增益。不存在任何 mirror 可达的提分路径，因为丢分是对隐藏参考自由文本的逐字符匹配。
