题目本身

任务要求在 Linux VM 上扮演财报抽取分析师，从 Apple FY2024 10-K（PDF 与 SEC EDGAR HTML 两份原件）中重建截至 2024-09-28 的合并资产负债表（Consolidated Balance Sheet），输出为结构化 JSON。需按 input/output_schema.json 的嵌套结构填写资产/负债/股东权益三大块及各级小计，单位为百万美元、数值须与申报口径完全一致。最终写入 output/balance_sheet.json，且不得修改 input/ 下的文件。

要求

交付物是单个文件 output/balance_sheet.json，采用与参考件同款的三级嵌套 schema：consolidated_balance_sheet 下含 assets（current_assets / non_current_assets）、liabilities（current / non_current）、shareholders_equity，以及顶层 total_liabilities_and_shareholders_equity，合计 30 个数值叶子（与 reference/expected_numeric_paths.json 列出的 30 条 dotted path 一一对应）。另需 metadata 段（company / ticker / period_of_report / currency / unit）。硬约束：currency 必须 ∈ {USD, USD_millions}，unit 必须 ∈ {millions, USD_millions}，且 company / ticker / period_of_report 须与参考件精确相等。

评测方法

评分脚本是 scripts/score_outputs.py（main.py 只负责把它写到 /tmp/agenthle_eval 并以 --output/--reference 运行，取 report['score']）。它先做 metadata_checks：company/ticker/period_of_report 须与参考件相等、currency/unit 须落在白名单，任一不符即进 errors。核心分是『数值叶子命中率』：numeric_leaves() 递归抽取参考件 consolidated_balance_sheet 的全部数值叶子（实测共 30 个），对每条 path 用 Decimal 精确相等比较，accuracy = correct/total。两行决定性代码：`accuracy = correct / total` 与 `"score": float(accuracy) if not errors else 0.0`——即分数是命中比例，但只要 metadata 有任一 error 就硬清零。另有 `pass_fail = not errors and totals_correct and accuracy >= 0.95`（三个顶层小计 total_assets/total_liabilities/total_shareholders_equity 须全对、命中率≥0.95）。因为用 Decimal 比较，1e-05 与 0.00001 视为相等，逗号与字符串数字也会被规整。

哪里做错了

没有失分。OFF 与 ON 都命中全部 30 个数值叶子（accuracy=30/30=1.0），metadata 五项全部合规，因而 errors 为空、totals_correct 为真、accuracy≥0.95，pass_fail 亦为真。抽取无误：total_assets 364980、total_liabilities 308030、total_shareholders_equity 56950，且 308030+56950=364980 自洽；易错项也都对——负值 accumulated_deficit -19154 与 accumulated_other_comprehensive_loss -7172、千股口径 shares_issued_and_outstanding_thousands 15116786、par value 0.00001。分数稳健：模型的自校验覆盖了 schema、各级小计与会计恒等式，等于把评分脚本关心的『小计对、恒等式平』这类内部一致性在提交前就验过一遍。唯一理论脆弱点是 metadata 的硬门槛（若把 currency 写成 'US Dollars' 之类会被清零），但模型写的是 'USD'/'millions'，稳妥命中。

怎样才能做对

本任务已满分，正确做法即模型所为：(1) 用 pdftotext -layout（或 grep/rg 先定位）从 10-K 的 CONSOLIDATED BALANCE SHEETS 页精确抄录 30 个行项，注意 vendor non-trade receivables、accumulated deficit（带负号）、par value 0.00001、授权/已发行股数（千股口径）等易错项；(2) 严格按 output_schema.json 的三级嵌套填 assets/liabilities/shareholders_equity 及各 total_ 小计；(3) metadata 用白名单字面量 currency='USD'、unit='millions'，company/ticker/period_of_report 抄参考口径以过硬门槛；(4) 提交前自验：JSON 可解析、schema 形状齐全、三组小计等于各自明细之和、且 total_liabilities+total_equity==total_assets。模型在无 harness 时即完成了第 (4) 步，这正是拿满分的关键护栏。
