题目本身

扮演政策分析师,读取 task_spec、脱敏 taxonomy 和三份缓存文档全文(AGORA ID 768 Anthropic RSP、1293 TAKE IT DOWN 法案、2047 圣何塞市 AI 政策),按三个维度分类:立法状态(Hard/Soft/Other 三选一)、技术范围(10 个布尔标签)、AI 生命周期阶段(6 个布尔标签)。每个判为 TRUE 的标签要给出文档里的逐字证据引文;再产出一个跨文档矩阵和 150-300 词的差距分析。最终写入 output/agent_output.json。

要求

唯一交付物 output/agent_output.json:documents 下每个 doc 含 legislative_status(label+evidence)、technical_scope(10 键,每键 value+evidence)、lifecycle_stages(6 键);顶层还要 cross_document_matrix(三个维度、按标签/键 × 文档 ID 的布尔矩阵)与 gap_analysis(150-300 词)。约束:证据须为文档逐字子串;矩阵键要用与打分器一致的标签名(立法维度需 'Hard Law'/'Soft Law'/'Other',而非 snake_case);不得修改 input/。

评测方法

打分器 scripts/score_outputs.py 的 score_output:每文档三维度分——legislative=exact_match(agent 标签==真值→1 否则 0)、technical_scope=10 键 binary_f1、lifecycle=6 键 binary_f1;每维度分再乘一个 evidence_gate:`evidence_gate = 1.0 if pass_rate >= 0.8 else 0.5`(证据须逐字子串+≥MIN_EVIDENCE_WORDS=5 词+命中该标签的隐藏关键词表 EVIDENCE_KEYWORDS)。三文档取平均后 `classification_score = leg_avg*0.2 + scope_avg*0.4 + lifecycle_avg*0.4`。随后是全有或全无的门:gap 无效→min(_,0.9);`if not matrix_ok: min(_,0.95)`;`if classification>=0.70 and multilabel_precision<0.55: min(_,0.69)`;最关键的 `if not gap_ok or not matrix_ok: min(_, REQUIRED_ARTIFACT_CAP=0.69)`。matrix_valid 逐格比对矩阵单元格==该文档 per-doc 预测(不看真值,是纯自洽检查),立法段用 `for label in ['Hard Law','Soft Law','Other']: row=leg_matrix.get(label); if not isinstance(row,dict): return False`。

模型执行过程（逐帧）

两轮流程几乎相同:第 3 步并行读 task_spec/taxonomy/index 并列目录;第 8 步分块读三份文档;第 16 步一次性 write 出 agent_output.json;随后用 input 里可选的 software/python 自写校验脚本自查并 edit 修引文。OFF(34 步):自查在第 19 步报 '1293 legislative quote missing'、'2047 legislative quote missing',于是用 `rg -F` 定位精确子串并 edit 修好 3 处引文,第 33 步终检打印 `exact_quotes=true matrix_consistent=true`——OFF 自己验证了矩阵自洽,矩阵键用了正确的 'Hard Law'/'Soft Law'/'Other'。ON(29 步):自查脚本先在第 19 步 bash 语法报错,重写后第 21 步报 quote_errors,第 25 步一次 edit 修了 6 块,第 28 步终检打印 `validation_errors=[] deliverable=exists_nonempty`——但这次自查没有按打分器要求的标签键核对立法矩阵,ON 把矩阵立法键写成了 snake_case。分类判断上 ON 比 OFF 好:2047 立法从 Other 翻成正确的 Hard Law、768 技术范围多命中 1 个、1293 技术范围去掉了假阳性,classification 0.6024→0.7015。

哪里做错了

主损失是分类判断本身,两轮共有、与 harness 无关:(1) 1293(TAKE IT DOWN 刑事法案)的 lifecycle 三个真值 build_and_use_model/deploy/operate_and_monitor 全被判 false → lifecycle_f1=0.0(两轮都是),这是最大单点丢分(占 lifecycle 权重 0.4 的 1/3);(2) 1293 的 evidence_gate 恒为 0.5,把它的立法与范围分都对半砍——OFF 因 task_specific_ai 假阳性引文不含关键词而失败(pass 2/3=0.667),ON 因 generative_ai 引文 'computer-generated or technological means' 只有 4 词<5 而失败(pass 1/2=0.5);(3) 768 技术范围漏判 general_purpose_ai(两轮)和 open_weight_open_source(仅 OFF)为假阴性,lifecycle 把 plan_and_design/collect_and_process_data 判成假阳性;(4) 2047 立法状态 OFF 误判为 Other(真值 Hard Law,该维度得 0),ON 判对——这是 run-variance 的判断翻转,是 OFF→ON 的主因。此外 ON 独有一处 instruction-following 失误:cross_document_matrix.legislative_status 键写成 hard_law/soft_law/other,而打分器 `leg_matrix.get('Hard Law')` 取到 None → matrix_valid=False → 由 0.7015 被砍到 0.69(矩阵数值其实是对且自洽的,只是键大小写不对)。

怎样才能做对

分类正确性需要更强的领域判断,而非 harness 能给:1293 要认出刑事 deepfake 法虽不含'AI 生命周期'字样,但对深伪的'创建'映射 build_and_use_model、'披露/发布'映射 deploy、'下架/移除/上报'映射 operate_and_monitor(真值三项皆 true);768 要把 'general-purpose'、开放权重相关表述判为 true;并给每个 TRUE 标签配 ≥5 词、逐字子串、且含隐藏关键词表词的引文,才能把 1293 的 evidence_gate 从 0.5 抬到 1.0(注意 1293 证据太短是硬伤)。关于矩阵:一个非泄漏的'矩阵键自洽检查'确实能回收一小部分——即用 taxonomy 里给定的标签名('Hard Law'/'Soft Law'/'Other' 及各技术/生命周期键名,均非答案)作为矩阵键,并逐格核对矩阵==per-doc 预测;这能抓住 ON 的 snake_case 键错并修好,使 matrix_valid=True、从 0.69 恢复到 0.7015(+0.0115)。但它只对 ON 有效(OFF 矩阵本就自洽,回收 0),且完全不触及占绝大多数丢分的分类误判。

harness（ON）的效应

行为上 ON 的 mirror 提示(M2 校验交付物存在/非空、M3 对照自查脚本反复重算)在这里是冗余的:OFF 在没有 harness 时就已自写 software/python 校验脚本、反复重跑、并显式打印 matrix_consistent=true。分数上 0.6024→0.69(+0.088)并非 harness 造成:真正驱动是一次与 harness 无关的 run-variance 判断翻转(2047 立法 Other→Hard Law,单这一项 classification +0.099),而 ON 又因矩阵键 snake_case 触发 0.69 上限自砍回 -0.0115,两相抵后净得 0.69。mirror 只能复述 agent 自己的状态,无法泄漏'立法矩阵键必须是 Hard Law/Soft Law/Other'这种打分器隐藏细节,所以它既没帮 ON 避开矩阵门,也没制造分类提升——正如已知结论:OFF→ON 的差异基本是 run-variance。
