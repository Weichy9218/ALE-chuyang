题目本身

题目要求在 Linux VM 上做一份数字营销 A/B 测试分析（个性化邮件主题行）。需读入 experiment_results_raw.csv、historical_metrics.csv 等输入，对全量原始结果（明确不套用排除规则）计算：随机化配平的样本比失衡(SRM)卡方检验、四个指标(opened/clicked/converted/unsubscribed_rate)的率/绝对与相对提升/95%CI/z 统计量/p 值、对三个次要指标做 Benjamini-Hochberg 校正，并基于历史指标的功效分析给出每臂所需样本量，最后写一份含 ship/hold 建议的 Markdown 报告。

要求

在 output/ 下写恰好三个文件。(1) randomization_assignment.csv，列 metric,value，含 6 行 n_control/n_treatment/ratio/srm_chi2/srm_pvalue/srm_pass，SRM 在全量 raw 上算。(2) experiment_results.tsv，制表符分隔，恰 4 行(opened/clicked/converted/unsubscribed_rate)，14 列(metric,is_primary,control_rate,treatment_rate,absolute_lift,relative_lift_pct,ci_lower_95,ci_upper_95,z_statistic,p_value_raw,significant_at_05,bh_rank,bh_threshold,bh_significant)，BH 三列只对次要指标填、主指标必须留空；率按 delivered==1 的全量 raw 计算。(3) experiment_report.md，含功效分析每臂样本量、含 ship 或 hold 的 Recommendation 段、主指标绝对提升(3.4pp)。

评测方法

main.py 只把打分委托给 scripts/verify_ab_test_outputs.py 并返回 payload['score']（`return [float(payload.get('score', 0.0))]`）。该脚本从 raw.csv 现场重算 expected_stats、从 historical_metrics 现场重算 required_n，再跑三个布尔校验 validate_assignment_csv / validate_results_tsv / validate_report_md。得分是硬二值悬崖：`if assignment_ok and results_ok and report_ok: payload['score'] = 1.0`，否则 0.0，无部分分，任一字段越界即归零。数值容差：率/提升/CI/p 值/BH 阈值 tol=0.001，z 统计量 tol=0.01；样本量允许 [required_n-2, required_n]（POWER_SAMPLE_SIZE_LOWER_TOLERANCE=2，即接受集 {3118,3119,3120}）；assignment 需 ratio≈1.0、srm_pvalue>0.01、srm_pass=True，且 6 个 key 必须完全匹配。关键点：脚本也算了 reference_match（与参考文件 strip 后逐字节比对）并写进 payload，但它根本不参与打分门槛——即输出无需与参考文件逐字相同，只需重算值落在容差内。

模型执行过程（逐帧）

OFF(26 步, read5/bash9/write3)：第[3]步并行读 brief/historical/raw/pyproject/exclusion 并 wc；第[10-14]步跑 uv 做功效分析，先遇 `/home/user/.cache/uv` 缓存目录创建失败，随即改设 UV_CACHE_DIR=/tmp/uv-cache 解决，得非加权基线均值 0.218575 → ceil(3119.54)=3120；第[18]步一次算出 SRM(4409/4409, ratio 1.0, chi2 0.0, p 1.0)与四指标(opened 0.2225→0.2565, lift 0.034021)；第[19]步写三文件；第[23-25]步再解析回读写好的文件自检 schema，打印 'validated outputs: [...]' 并 wc 行数确认后收尾。ON(26 步, read4/bash9/write3)：流程几乎同构，第[16-19]步显式用非合并 SE 现算 CI（如 0.016220/0.051823），第[24-25]步自检打印 'PASS: exact output file set / PASS: assignment schema and 6 required rows / PASS: results schema, 4 metric ...'。两者都在收尾前主动验证了产物。

哪里做错了

没做错——OFF/ON 三项校验全过、均 1.0。数值部分(assignment、TSV)完全稳健：重算是确定性的、值都在容差内（如 primary CI 0.016220 vs 参考 0.016205 差 1.5e-5，远小于 0.001）。一个值得记录的语义细节：参考报告的落地建议是 SHIP（主指标显著且护栏通过时机械结论为 ship），而两个模型都基于「treatment 点击率为 0、疑似埋点/事件管线损坏」的领域判断给出了 HOLD——与参考建议相反，却仍满分。原因是 validate_report_md 只做子串在场判断：它要求 lower 文本里出现 expected_recommendation='ship'，而两份报告都因写了 'shipping'/'shipment' 而含子串 'ship'，同时也含 'hold' 与 'recommendation'，于是全过。也就是说报告校验对『实际结论到底是 ship 还是 hold』近乎失效，这是评分器弱点而非本例失分点；本例 1.0 对数值文件稳健，报告项则部分靠子串巧合通过。

怎样才能做对

正确做法（两模型均已达到）：SRM 用全量 raw 每臂计数做卡方（此处 4409:4409 完全平衡 → chi2=0, p=1.0, pass）；四指标只在 delivered==1 行上算率；假设检验用合并(pooled) SE 的双比例 z 检验得 z 与 p（主指标 z=3.7428, p=0.000182），而 95%CI 用非合并(unpooled) SE（主指标 [0.016205,0.051837]）——这一『检验用 pooled、CI 用 unpooled』的分工是关键，两模型都做对了；BH 只对 3 个次要指标、按 p 升序排 rank、阈值 idx/m*0.05（clicked rank1 阈0.01667 显著、unsub rank2 阈0.03333 显著、converted rank3 阈0.05 不显著），主指标 BH 三列留空；功效分析用 open_rate 的非加权均值 0.218575 作基线、MDE=0.03、alpha=0.05、power=0.8 的闭式公式 → n=3120；报告需含每臂样本量(3118-3120 任一)、'3.4'、Recommendation 段及 ship/hold 词。

harness（ON）的效应

零增益、零 headroom。分数上限已是 1.0，ON 无从提升。行为上 ON 与 OFF 几乎同构：OFF 无需 harness 就已在第[23-25]步主动回读并自检三个产物（M2 冗余）；本题 input_dir 里没有暴露给 agent 的参考/自检文件，故 M3（需同时存在数值目标与输入可见参考才触发）根本不会触发；两次都是 26 步、无预算压力(M1 无用)、也没有重复同一失败命令的抖动（OFF 的 uv 缓存报错仅一次后即改 UV_CACHE_DIR 修好，非 M4 抖动）。唯一差异是 ON 因附加了镜像提示块，输入 token 从 16808 涨到 29738、时长 221s→301s，分数不变。结论：镜像提示在本题完全冗余。
