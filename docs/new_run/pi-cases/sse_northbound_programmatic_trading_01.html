题目本身

扮演沪股通程序化交易报告合规顾问，闭卷（仅用 input_dir 下已暂存材料、禁止外部检索）回答三个客户问题并写入一个 JSON（output/research_answers.json）：q1 同一 LEI 下的多个沪股通账户是否须经每家券商分别报告杠杆规模；q2 所给规则是否给出 流量费/撤单费 的具体数值金额；q3 一家法国公司能否仅用外文原名报告其自研软件名称。每题需给出 conclusion(仅 Yes/No/Unknown)、citation_document(所依据的简体中文文档名)、evidence_snippet(从暂存源文件精确摘录的简体中文原文)、answer_text(英文简述)。

要求

恰好写一个文件 remote_output_dir/research_answers.json，含三个顶层键 q1_multi_broker_reporting / q2_hft_cost_calculation / q3_software_naming；每键四字段：conclusion 归一化后须恰为 Yes/No/Unknown 之一并等于答案键 expected_conclusion；citation_document 归一化后须∈答案键 accepted_citations（文档正式名或 1-2/1-3 等别名）；evidence_snippet 须包含该题全部 evidence_anchors 且归一化后是被引文档(doc_id)正文的精确子串；answer_text 须像英文解释(≥20 字符且≥3 个英文词)。答案键与源文档在 reference_dir，输入侧不可见。

评测方法

main.py 先确认 output_file 存在，再从 reference_dir 拷入 answer_key.json / evaluator_documents.json / document_manifest.json，调 score_research_answers.score_submission。缺任一顶层键直接 score=0。每题满分 1，_score_question 采用四道顺序 all-or-nothing 闸门：① _normalize_conclusion(value).lower() 须 == str(expected_conclusion).lower()，否则记 note 'conclusion does not match the canonical answer' 并 return（本题 0）；② citation_document 归一化后须∈accepted_citations；③ evidence_snippet 须含全部 evidence_anchors 且归一化后是被引 doc 文本子串；④ answer_text 须像英文解释。总分=Σ(题分)/len(answer_key)=Σ/3。关键：结论闸门在最前，一旦不匹配，后面 citation/evidence/answer_text 即便全对也一律不计。

模型执行过程（逐帧）

两版执行路径几乎相同、且都做了充分自检。OFF 共 29 步(read8/bash11/write1)：step3 并行读 task_brief、question_set、output_contract、document_manifest 并 rg --files 列出 extracted_text；step9/13 用 rg 检索『杠杆资金规模/LEI/多个账户』『流量费/撤单费/20000/高频/收费』『软件名称/中文名称/外文/英文』等词，精准定位三条依据；step19 mkdir output；step21 一次 write 成型；step23-28 还用 jq -e 校验键集与四字段、find 校验只有一个文件、并对三条 evidence_snippet 逐条 rg -F -x 验证是源文件精确子串。ON 共 22 步(read8/bash5/write1)，流程相同但检索更省(bash 5 次)，step18 write、step20 一次 set -euo pipefail 校验存在+文件数即收尾。两版最终 JSON 实质一致：q1/q2/q3 结论均为 No/No/No，citation 与 evidence 摘录完全相同(仅 answer_text 措辞略异)。

哪里做错了

失分的三分之一是 q2_hft_cost_calculation。answer_key 的 expected_conclusion 为 "Unknown"，模型两版都答 "No"，在第一道结论闸门即判 0(note: 'conclusion does not match the canonical answer')。需强调：模型对 q2 的实质分析完全正确——它引 doc_08《上海证券交易所程序化交易管理实施细则》第三十七条『…加收流量费和撤单费等费用。具体收费标准由本所另行规定。』，含 anchor『具体收费标准由本所另行规定』，经核验该 snippet 归一化后确是 doc_08 正文的精确子串，②③闸门本可通过；answer_text 也明说『provide no numerical amounts; the specific fee standards are to be prescribed separately』。即除结论 token 外全部正确，唯独把『金额未给/未知』这一正确发现标注成 "No" 而非 "Unknown"。q1(No，引《…信息报告表》填报说明，三 anchor 齐全)与 q3(No，引『…报告信息填报注意事项』，含 anchor『程序化交易软件名称等，可以填写英文』)四闸门全过各得 1，故 (1+0+1)/3=0.6666666666666666。

怎样才能做对

只需把 q2.conclusion 由 "No" 改为 "Unknown"(citation/evidence/answer_text 已合规，可原样保留)，本题即由 0 变 1，总分升至 3/3=1.0。判据：question_set.json 的 q2 是 wh 型问题『what are the specific numerical amounts of the flow fee and cancellation fee』，规则只授权收费并称『具体收费标准由本所另行规定』——金额无法从材料确定，故 canonical 结论是『未知/Unknown』而非『否/No』；模型自身的 answer_text 已承认金额未给出，本可据此选 Unknown。注意题面陷阱：main.py task_description 把 q2 转述为『whether the staged rules provide specific numerical amounts』(是/否框架，天然导向 No)，与 answer_key 要的 Unknown 冲突；这是真实的题面不一致，故不是纯模型过失。q1/q3 已满分，无需改动；OFF 的评分稳健(三条 evidence 均经 rg -F -x 自证为源文精确子串)。

harness（ON）的效应

ON 相比 OFF 步数与检索更省(22 vs 29 步、bash 5 vs 11、cache_read 164352 vs 259584)，但结论、引用、证据摘录与最终得分完全一致(均 0.6666666666666666, status completed)。ON 追加的 M1–M4 镜像提示对决定性错误无效：失分不是文件缺失/为空，也不是重复劳动——OFF 无提示时本就自查了输出存在、JSON 键集/四字段、单文件、乃至逐条 rg -F -x 验证 evidence 是源文精确子串(比 ON 更严)，故 M2 交付校验冗余；M3 验收提示不触发(本题无 numeric target，且 answer_key 在 reference_dir 而非 input_dir，输入侧无参照可 recompute)，镜像也无从告知 canonical 结论是 Unknown。镜像只复述模型自身状态，无法纠正『No→Unknown』这类语义标注选择，因此 ON 既未改善也未恶化得分。
