哪里做错了

两种失败模式不同。OFF：把整段预算耗在读输入上，最后一步才起写、且没写完，output 目录空 → 触发 main.py 必需文件门槛 return [0.0]，根本没进真正的 scorer。ON：文件齐全、XML 合法、B 段静态过关，但我用 ON 真实产物复跑评测得 score=0.0、overall_pass=False、sections_summary={A:false, B:true, C:false, D:false, E:true}，共 6 项硬检查未过，全有或全无下任一即致 0：① A 段 47/50，a23_merchant_coordination_task、a24_campaign_coordination_task 均 False（discover 找不到独立的 merchant/campaign 协调 userTask——ON 把协调塌缩进单个 coordination_lane/compliance_signal_check）；② a42_split_branch_requires_user_task False，分支计数 {'peer_readiness_check':1, 'gw_parallel_review_join':0}——因把 5 个标准化 peer 任务合并成 1 个 peer_readiness_check，导致并行 split 有一条空分支直连 join；③ C 段虽 structural_coverage=1.0、rules_coverage=1.0（JSON 列全了 18 修改/26 规则），但 c07_modification_to_bpmn_binding False（modification_1 的 elements_added=['coordination_lane','temporary_governance_lane','peer_category_owner_lane'] 无一命中真实 BPMN 元素 ID，reason=no_existing_bpmn_id_referenced）；④ c11_design_decisions_audit False，18 个修改全部 no_chosen_approach——ON 用 '**chosen_approach:**' 蛇形键，而审计正则期望 'chosen' 与 'approach' 之间为空白（参考解用 '**Chosen approach:**'），下划线令其全部匹配失败（rejected_alternatives、rationale 同样因蛇形/措辞不符而不合格）；⑤ D 段 d03_senior_escalation_ratio_le_30 False，senior_ratio=0.333（9/27 条决策流路由到/近路可达高管升级）>0.30。根因是 ON 主动选了『novel_compact_committee』紧凑变体（design_decisions 明写『a compact committee variant, not a claim of reference fingerprint A』、modification_4『one scenario-exempt peer task covers all five canonical standardized topics only』），把 rubric 要求的多个必须彼此独立的元素塌缩成单节点。注意：ON 无法部署 Flowable 并非扣分主因，B 段用自报 60/60 已过。

怎样才能做对

对照参考 Solution A 精确复刻，而非塌缩：① 保留 5 个独立的标准化 peer userTask（ad_ratio、ab_test、free_trial、new_merchant、review_based_promotion），各挂并行 split 的一条分支，确保每条分支至少经 1 个 userTask（过 a42）；② 保留独立的 merchant_readiness_coordination 与 campaign_cadence_coordination 两个协调任务（过 a23/a24）；③ structural_changes.json 的每个 modification（尤其 modification_1）在 elements_added 里填真实存在的 BPMN 元素 ID 而非车道别名（过 c07）；④ 让路由到高管升级的决策流占比 ≤30%（当前 9/27=0.333，需减少至少一条近路，过 d03）；⑤ design_decisions.md 严格按审计格式写 18 小节：'## Modification N'、'Chosen approach:'、'Rejected alternatives:'（≥2 条且不同于 chosen）、'Rationale cites rules: rule_X'、'Trade-off:'，避免蛇形键与改写措辞（过 c11）。B 段无需真跑 Flowable，自报自洽的 60/60 即可。因是全有或全无，上述须同时全部满足；这需要很强的 BPMN 建模与逐条对齐能力，harness 的提示无法替代。其中 c11 正则对蛇形键偏脆，但参考格式明确、可复刻，仍算格式保真问题。
