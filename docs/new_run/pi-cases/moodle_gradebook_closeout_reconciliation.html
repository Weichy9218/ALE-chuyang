题目本身

在一个导出的 Moodle 课程备份（.mbz）上做期末成绩册收尾对账：把缺失/空成绩按规则处理、重算各类别与总评，并把重建后的成绩册与策略写回备份结构。

要求

在 .mbz 的 gradebook 结构里写出对账后的成绩与一份 policy.json（含空成绩处理策略、类别聚合方式等），使重建结果与标准答案一致。

评测方法

评测器对重建的成绩册和 policy 做精确比对。其中 canonical_policy() 对 empty_grade_behavior 这个字段做字面量字符串相等判断，要求恰好是 "zero"；成绩单元格逐格比对。总分按各项加权，满分 1.0。

模型执行过程（逐帧）

OFF 与 ON 的行为一致：都正确解析了 .mbz、把空成绩当作 0 计入、重算了类别与总评，所有下游成绩单元格都与标准答案吻合。两条运行在收尾前都自查了文件结构。唯一分歧点不在计算，而在一个策略字段的取值写法。

哪里做错了

把 empty_grade_behavior 写成了语义正确但字面不符的 count_as_zero，而评测器的 canonical_policy() 只接受字面量 zero。空成绩确实被按 0 处理了（下游全对），所以这是纯粹的 token 不匹配，不是逻辑错。OFF 和 ON 犯的是同一个错，扣掉同样的 0.05。

怎样才能做对

要拿满这 0.05，得恰好写出评测器认的 canonical token zero。但这个字面量并不在 agent 可见的输入里明确声明，属于评测器私有约定；模型写的 count_as_zero 是完全合理的同义表达。真正该修的是评测器放宽到接受同义值，而不是要求模型去猜一个未公开的字符串。所以这 0.05 是评测严苛，不是能力问题。

harness（ON）的效应

无影响。OFF/ON 同分同错。提醒类 harness 帮不上：模型本来就自查了文件与成绩，M3 也无法触发（标准答案不在 input 里），没有任何提醒能让模型猜到评测器要的那个字面量。

证据

  • OFF=0.95, ON=0.95，两条运行 policy.json 里都是 empty_grade_behavior="count_as_zero"
  • 评测器 canonical_policy() 要求字面量 "zero"，做精确字符串相等
  • 所有成绩单元格与标准答案一致（空成绩确实被按 0 处理）
  • 扣分点仅此一个字段的字面写法，属评测器私有约定、输入里未声明
  • M3 无法触发：标准答案在评测器侧，不在 agent 的 input 目录
