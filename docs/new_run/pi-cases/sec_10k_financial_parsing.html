题目本身

在装有 100 份 SEC 10-K PDF 的 Linux VM 上，按给定 schema 解析每一份文件：(1) 每份产出一个标准化抽取 JSON（5 个元数据字段 + 10 个财务字段）；(2) 每份产出一个原始文本 txt；(3) 回答 3 个分析型问答写入 qa_answers.json；(4) 对 input/validation/ 的 5 份子集做第二次确定性重跑写入 run2_extractions。货币字段用原始 USD 整数、EPS 用 2 位小数。

要求

交付物：output/extractions/*.json（100 份，键 company_name/ticker/cik/filing_date/fiscal_year_end/financials；financials 含 revenue、cost_of_revenue、operating_income、net_income、total_assets、total_liabilities、stockholders_equity、cash_and_equivalents、eps_basic、eps_diluted 共 10 字段，货币为整数、eps 为浮点，允许 null）；output/raw_extractions/*.txt（100 份原始文本）；output/qa_answers.json（Q1/Q2/Q3 答案）；output/run2_extractions/*.json（5 份 validation 重跑，须与首跑逐字节一致）。约束：不得写 output/ 之外、不得改 input/。评分器 passing_threshold=0.75。

评测方法

score_outputs.py 按 8 项加权（WEIGHTS）：financial_accuracy 0.30、analytical_qa 0.25、anls_verification 0.10、cross_validation 0.10、determinism 0.10、schema_compliance 0.05、metadata_accuracy 0.05、completeness 0.05。financial：逐字段比对，货币相对误差 relative_error<=0.005 判对、eps round(x,2) 相等判对、pred 与 GT 同为 None 也判对（共 100 份 x 10 字段 = 1000 个字段格）。analytical_qa：_qa_score 先 `if not isinstance(predictions, dict): return 0.0`，再 `predictions.get("Q1")` 直接取 ticker/pct_increase（Q1 pct 容差 0.15；Q2 年份精确、margin 容差 0.05；Q3 用 Kendall τ 归一化）。关键悬崖：任一 filing 若 raw 文本 ANLS<0.6，则该 filing 的 schema/metadata/financial/cross_validation 全部清零（zeroed 逻辑）——本次 ANLS 0.9962、anls_failures=0，未触发。

模型执行过程（逐帧）

两次运行都写了一个正则/启发式抽取脚本（OFF 为 extract_filings.py，ON 为 extract_workflow.py），反复迭代各公司损益表/资产负债表行的正则（trajectory 中大量 rg 搜索 + edit 改正则，如 OFF [98][106][120] 反复调 net_income/equity/liabilities 匹配，ON [85][97][107][125] 同类）。OFF 在 [124-130] 做了充分自检：jsonschema 校验 105 份 0 error、文件计数 pdf=raw=extractions=100/run2=5、run2 逐字节一致(validation_rerun=byte-identical)、eps_precision_errors=0、balance_identity_audit=complete，最终 'wrote 100 extractions, 3 QA answers, and 5 validation reruns'。ON 行为几乎相同、也做了 schema 校验(validated 105 schema_errors 0)与计数核对(run2_mismatches=0)。两次都把 qa_answers.json 写成列表结构——恰好照抄了输入 questions.json 本身的 list 形态。

哪里做错了

1) 决定性(-0.25)：qa_answers.json 顶层是列表 [{"id":"Q1","answer":{ticker,pct_increase}},...]，而评分器要求字典 {"Q1":{ticker,pct_increase},...}。isinstance(predictions,dict)=False → analytical_qa 直接 0.0。而内容其实近乎全对：Q1 MSFT/161.9 与 GT 完全一致；Q2 WMT/2023/3.34 vs GT 3.37（|Δ|=0.03<=0.05 容差，判对）；Q3 排名仅 MSFT 与 XOM 相邻互换，Kendall τ 归一化 0.978。实测把该文件改写成字典后重算：analytical_qa 0.0→0.9926，总分 0.6669→0.9151（远超 0.75）。反之，即便 financial 与 cross_validation 都满分而 QA=0，上限也只有约 0.749，仍不及格——QA 格式是唯一的及格闸门。2) financial_accuracy=0.827（827/1000 字段对）。最差字段：stockholders_equity 65/100（27 个取值错，典型 CVX 取母公司口径 'Total Chevron Corporation stockholders equity'，比 GT 含少数股东权益口径系统性少约 1,170M，如 152,716 vs 153,886）；cash_and_equivalents 69/100（18 个多填——银行 BAC 等 GT 为 None、模型却填了 380,463M 之类）；revenue 72/100（20 个错——CVX 取 'Total revenues and other income' 166,339 vs GT 'total revenues' 158,902）；cost_of_revenue 75/100（25 个漏，CVX 全年 None）。最差公司：PFE 54/100（net_income/eps 全年 None，损益表块未识别）、WMT 60、CVX 67、XOM 77、UNH 84；干净的：AAPL/JNJ/MSFT 各 100、BAC 95、JPM 90。3) cross_validation=0.7，30 个错全部落在 CVX/PFE/XOM（各 10 份），完全是上述财务抽取错漏的下游（equity 错或字段缺 → 资产=负债+权益 恒等式的判定与预期 check_passed 不符）。

怎样才能做对

1) QA（最高杠杆、约 +0.248，且是及格闸门）：把 qa_answers.json 从列表改为以问题 id 为键、答案值内联（去掉自造的 'answer' 包裹层）的字典：{"Q1":{"ticker":"MSFT","pct_increase":161.9},"Q2":{...},"Q3":{...}}。内容本已达标，纯属输出容器格式——但该容器形态在可见材料里从未规定，见下 harness_effect。2) financial（约 +0.05）：按 GT 口径修正标签选择——CVX 权益取含少数股东权益的 'Total equity' 而非母公司口径；CVX 收入取 'Total revenues'（sales+other operating revenues，排除 other income 与权益法收益）；补齐 CVX 的 cost_of_revenue、补齐 PFE 整张损益表（PFE 版式导致块检测失败）；银行(BAC 等)的 cash_and_equivalents 应留空以匹配 GT 的 None。这些是真实抽取能力问题，需要更稳健的按公司/版式的表格解析，而非脆弱的逐行正则。3) cross_validation 会随 financial 修正自动回升（同一批 CVX/PFE/XOM 修好即得分）。

harness（ON）的效应

ON=0.6642 比 OFF=0.6669 略低。逐项：ON financial 0.819 vs OFF 0.827（ON 多做的正则改动反而略降）、QA 同为 0.0（ON 也写成列表）、其余组件相同。OFF 在无 harness 下就已自行完成 M2 类自检（jsonschema、文件计数、run2 逐字节、eps 精度、balance 审计，见 [124-130]），故 M2 '确认输出文件非空' 冗余。M3 '对照 input 内可见参考反复重算直至达标' 无法作用于本任务的致命点：qa_ground_truth 是 hidden 资产（stage1_manifest 的 removed_from_input 含 evaluation/qa_ground_truth.json 与 evaluation/ground_truth/*），input 里没有可见答案键；mirror 只复述模型自身状态，无法注入 'QA 必须是字典' 这一未文档化的评分器契约。因此 harness 对唯一及格闸门不可寻址，反而因提示 '反复迭代' 诱发更多抽取微调，令 financial 微降、总分微跌。
