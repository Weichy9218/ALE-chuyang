临床数据与生物统计

ALE 逐题轨迹分析。pi 与 gpt_claw 同模型 gpt-5.6-sol、同环境跑同一批题，看两套 harness 各做了什么、为什么是这个分。红色步是报错的工具调用。
总览文档审计与分类结构化财务抽取临床数据与生物统计数值计算与复现
这批运行时 gpt_claw 的交互轮数被限制在 30 轮，事后看太低也不公平：它的多数空输出失分直接来自这个上限，何况它还要花轮次在委派子 agent 和脚本拼装上。已把上限改到 100。之后的 ALE 任务模型走 boyue 网关（apirx.boyuerichdata.com）。本页分析基于 30 轮上限的运行结果。

三题都是领域知识密集、有精确契约的临床数据工作：CRF 到 SDTM 的字段映射、组序贯试验的统计分析计划、按规则的变异注释。评分很严：映射是二元全对才算，统计计划按窄容差，变异注释按可报告规则的精确实现。三题的产出两套都写全了，失分都在专业正确性。

这一组题的 harness 优化方向

  • 这三题的失分是专业正确性，不是产出完整性，harness 换不出来。SDTM 映射要把 CRF 字段对到正确的 SDTM 变量，组序贯边界要按特定方法算，可报告规则要精确实现，靠的是模型的领域能力。
  • harness 唯一能做的是契约的结构部分校验。crf_sdtm 有精确的列名和顺序契约，healthcare_sap 要八个非空文件。afterToolCall 可以核对列名是否齐全、文件是否都在，把结构缺口反射回去，但数值和映射的正确性只能靠模型。
  • healthcare_variant 值得单独记：gpt_claw 的 exec 报错 14 次仍拿满分，pi 报错少反而因规则偏差扣了 0.2。这说明报错数不预测成败，harness 不要用报错次数做干预信号，要看最终产出对不对。
