结构化财务抽取

ALE 逐题轨迹分析。pi 与 gpt_claw 同模型 gpt-5.6-sol、同环境跑同一批题，看两套 harness 各做了什么、为什么是这个分。红色步是报错的工具调用。
总览文档审计与分类结构化财务抽取临床数据与生物统计数值计算与复现
这批运行时 gpt_claw 的交互轮数被限制在 30 轮，事后看太低也不公平：它的多数空输出失分直接来自这个上限，何况它还要花轮次在委派子 agent 和脚本拼装上。已把上限改到 100。之后的 ALE 任务模型走 boyue 网关（apirx.boyuerichdata.com）。本页分析基于 30 轮上限的运行结果。

两题都是按明确 schema 从文件里抽取结构化数据。区别在规模：一题是单份 10-K 的资产负债表，一题是 100 份 10-K 批量。单份的两套都轻松满分，批量的差别就出来了。

这一组题的 harness 优化方向

  • 单文档、schema 明确、数值精确比对的抽取题（financial_stmt），两套都满分，不需要任何干预。这类有唯一正确答案的题，模型能稳定做对。
  • 批量题（sec_10k 100 份）上，30 轮上限是硬伤：pi 不封步数磨了 60 步、跑两轮抽取，比封在 30 轮的 gpt_claw 高 0.09。这题直接说明步数上限对可增量改进的批量任务有线性影响。取消或提高上限让 agent 覆盖更多文档，是这类题最直接的提分手段。
