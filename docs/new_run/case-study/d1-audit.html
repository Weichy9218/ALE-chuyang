这一组题的 harness 优化方向

  • gpt_claw 的空输出直接来自 30 轮上限。三题里它都在委派子 agent 和用脚本拼装输出上耗掉了轮次，没留时间写交付文件。把上限提到 100 能救回这些空输出，agora 上 pi 没有上限就写出了文件。
  • 更有价值的干预是交付契约校验。这三题的硬门槛是纯结构性的：文件是否存在、有没有必需的顶层标题、有没有明确结论、有没有四条发现。harness 可以在 agent 收尾前用一个不含答案的检查器核对这些结构项，把缺口作为客观事实反射回去，比如提示 audit_report.md 只找到两条发现、少两条。这只注入客观事实，不碰答案。pe_screening 的 pi 就是漏了模板标题触发硬门槛，这类失分本可用契约校验救回。
  • pi 在 pe_screening 上读了 20 次，属于过度读取。beforeToolCall 可以拦截对同一文件的重复读取，提示已经读过。
