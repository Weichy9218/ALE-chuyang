三、失败原因分析

7 道 0 分题,agent 都真的跑了(29-31 步,接近 max_turns 30),分两种失败模式:

模式 A:空输出 —— 跑满轮次但没写出交付文件(4 题)

legal_ma_consistency_audit_01, pe_screening_memo_1, ct_geometry_calibration_catphan, agora_governance_classify_instance_1。这几题 output 目录为空:agent 在 30 轮 / 长墙钟(ct_geometry 跑了 2111s)里一直在探索、装依赖、试错,但始终没产出评测要的文件。这正是 harness 缺止损与"先交付再优化"引导的典型症状——是最值得用 pi 钩子改进的靶子。

模式 B:错误输出 —— 产出了文件但内容判 0(3 题)

bpmn_category_governance_restructuring_l3, crf_sdtm_mapping_1, healthcare_bias_audit_27a_public_replication_v1。这几题写出了文件,但数值/格式/规格与参考不符。属于模型能力/题目难度问题(复杂统计复现、BPMN 规格、SDTM 映射),harness 帮不上太多。
