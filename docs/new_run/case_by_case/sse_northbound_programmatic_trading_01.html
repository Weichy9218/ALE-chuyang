上交所沪股通程序化交易报告：闭卷合规研究

taskId：business_finance/sse_northbound_programmatic_trading_01

读上交所沪股通程序化交易报告的十份中文原始文件，回答三个客户咨询，产出一份 JSON 备忘录。每个问题要给 Yes/No/Unknown 结论、中文引用文件名、原文照抄的中文证据片段、一段英文解释。程序化脚本逐题判分，三题平均，满分 1.0。

题目做什么

agent 扮演沪股通程序化交易报告的合规顾问，在闭卷条件下只用暂存的十份上交所中文文件，回答三个客户咨询。三题相互独立，没有难度分层，评分时各占三分之一。下面逐题说明每题在问什么、正确结论是什么、依据哪一句原文。

题 1：同一 LEI 多券商是否要各自重复报告杠杆信息（q1_multi_broker_reporting）

客户情形：一个香港投资者在同一 LEI（证件号码）下有三个沪股通账户，分属三家券商。问是否必须通过每家券商分别报告 杠杆资金规模。

标准结论：No。依据是《填报说明》（doc_02）和《填报注意事项》（doc_03）里的集中填报规则：同一证件号码在多家联交所参与者开户的机构投资者，可以选取一家参与者按机构维度填写账户资金信息相关字段（含账户资金规模、杠杆资金规模、杠杆率等），其余参与者的账户不再重复填写，只在相应字段填“已在其他联交所参与者报告”。所以杠杆信息不需要每家券商各报一次。

题 2：流量费和撤单费有没有具体金额（q2_hft_cost_calculation）

客户情形：一支日申报超过 20000 笔的高频团队，问按现有规则 流量费 和 撤单费 的具体数额是多少。

标准结论：Unknown。依据是《程序化交易管理实施细则》（doc_08）第三十七条：本所可以对高频交易实施差异化收费，根据申报、撤单的笔数和频率等指标设置收费标准，加收流量费和撤单费等费用，但紧接着写“具体收费标准由本所另行规定”。规则只说明会收这两类费用，没有给出任何具体金额，因此在暂存材料范围内无法确定数额，结论是 Unknown 而不是 Yes 或 No。

题 3：法国公司能否只用外文软件名报告（q3_software_naming）

客户情形：一家法国公司使用自研软件，没有中文名，问能否只用软件的外文原名报告。

标准结论：No。依据是《填报注意事项》（doc_03）的语言要求：对于个别难以确定统一中文表述的字段，例如联交所参与者名称、账户名称、程序化交易软件名称等，可以填写英文。规则允许的是“英文”，不是任意外文。法国公司只用法文原名不在这条许可范围内，需要提供英文名称，所以结论是 No。此题的陷阱在于原文出现“可以填写英文”，容易被误读成“可以用任何外文”，从而错答 Yes。

硬性要求

  • 闭卷。只能用 input/ 下暂存的材料，不得使用外部网络检索或题目材料之外的监管知识。
  • 只写一个 JSON 文件：output/research_answers.json。
  • 三个顶层键必须齐全且与契约一致：q1_multi_broker_reporting、q2_hft_cost_calculation、q3_software_naming。
  • 每题四个字段齐全：conclusion、citation_document、evidence_snippet、answer_text。
  • conclusion 只能是 Yes、No、Unknown 三者之一。
  • citation_document 要写简体中文的来源文件名（用文档清单里认可的引用别名）。
  • evidence_snippet 必须是从暂存原文照抄的简体中文片段，不能改写、不能翻译。
  • answer_text 是一段简短英文解释。

要交什么

写 output/research_answers.json，根是一个对象，含三个顶层键，每个键的值是一个含四字段的对象。结构如下：

{
  "q1_multi_broker_reporting": {
    "conclusion": "No",
    "citation_document": "《上海证券交易所沪股通投资者程序化交易信息报告表》填报说明",
    "evidence_snippet": "……选取一家联交所参与者并按机构维度……不再重复填写上述信息……已在其他联交所参与者报告……",
    "answer_text": "No. Leverage fields can be centralized through one broker for same-ID institutional accounts ..."
  },
  "q2_hft_cost_calculation": {
    "conclusion": "Unknown",
    "citation_document": "上海证券交易所程序化交易管理实施细则",
    "evidence_snippet": "……加收流量费和撤单费等费用。具体收费标准由本所另行规定。",
    "answer_text": "Unknown. The rules mention the fees but give no numeric amounts ..."
  },
  "q3_software_naming": {
    "conclusion": "No",
    "citation_document": "上海证券交易所沪股通投资者程序化交易报告信息填报注意事项",
    "evidence_snippet": "……例如联交所参与者名称、账户名称、程序化交易软件名称等，可以填写英文。",
    "answer_text": "No. English is allowed for the software-name field, but that does not permit any foreign language ..."
  }
}

字段含义与约束：conclusion 归一化后须是 yes/no/unknown 之一；citation_document 要能匹配到该题认可的中文引用别名；evidence_snippet 要包含该题的锚点文本并且是被引文件的精确子串；answer_text 要看起来像一段英文解释。

用什么评测

评分链路在 main.py 的 evaluate()：

  1. 先查 output/research_answers.json 是否存在。不存在直接返回 [0.0]。
  2. 再查三份评测控制文件（answer_key.json、evaluator_documents.json、document_manifest.json）是否都在。缺任何一个会抛 RuntimeError（评测环境异常，不是给分）。
  3. 把提交文件和三份参考文件读进临时目录，调用 score_research_answers.py 的 score_submission()，传入四个参数：提交内容、答案键、评测文档全文、文档清单。
  4. 取返回结果里的 score 字段，转成 float，作为该题的最终分 [score] 返回给 harness。

这是纯程序化打分，对照隐藏参考答案，没有调用任何 LLM 裁判。

整体硬门槛（score_submission 层，任一触发则整份 0.0）：

  • 提交根不是 JSON 对象，返回 {"score": 0.0, "error": "submission root is not a JSON object"}。
  • 三个必需键（以 answer_key 的键为准）有任何一个缺失，返回 {"score": 0.0, "error": "missing required keys: ..."}。整份直接 0 分，不会逐题算。

分值映射：每题在四项检查全过时得 1.0，任一项不过得 0.0，三题求和后除以 3。所以可能的总分只有 0.0、0.333…、0.667…、1.0 四个值。多写了预期外的顶层键不扣分，只会记进 unexpected_keys。

怎么评测

每题由 _score_question() 按顺序做四项检查，前一项不过就提前返回该题 0 分。四项都在归一化后比对。归一化函数 _normalize_text 的动作：去首尾空白、转小写、全角空格转普通空格、：转:、（）转 ASCII 括号、删除 《》、中文弯引号转直引号，最后删掉所有空白字符。所以证据比对忽略空格、书名号和这几类标点差异。

顺序判据阈值 / 条件不满足的后果
0该题的值是对象response 是 dict该题 0 分，记 "question payload is not an object"
1结论合法且正确conclusion 去空白转小写后属于 {yes,no,unknown}，且等于该题 expected_conclusion 的小写。Q1=no，Q2=unknown，Q3=no该题 0 分，记 "conclusion is missing or invalid" 或 "conclusion does not match the canonical answer"
2引用别名被认可citation_document 是非空字符串，归一化后落在该题 accepted_citations 的归一化集合内该题 0 分，记 "citation_document is missing" 或 "citation_document is not an accepted alias"
3证据含锚点且是原文子串evidence_snippet 是非空字符串；归一化后包含该题 evidence_anchors 的每一条；且归一化后是被引文件（doc_ids_to_check）在 evaluator_documents 中全文的子串该题 0 分，记 "does not contain the required anchor text" 或 "is not an exact excerpt from the cited visible source"
4英文解释存在answer_text 去空白后长度 ≥ 20，且匹配到的 ASCII 单词（正则 [A-Za-z]+(?:'[A-Za-z]+)?）≥ 3 个该题 0 分，记 "answer_text is missing or not a short English explanation"

被引文件如何定位（第 3 项的 doc_ids_to_check）：先由文档清单把引用别名映射到 doc_id（cited_doc_ids），再和该题 accepted_doc_ids 取交集。若引用能映射到 doc_id，就用交集；交集为空时退回 accepted_doc_ids。证据只要在这批文件里任一份的全文命中即算通过。

参考答案的目标值

取自 reference/answer_key.json，证据句为参考答案给出的 positive_evidence，可作对表。实际提交只要满足上面四项判据即可，不必与参考句逐字一致，但必须包含各自的锚点且是被引文件的精确子串。

题结论建议引用参考证据句（片段）
q1No《上海证券交易所沪股通投资者程序化交易信息报告表》填报说明（doc_02）“……对于以同一证件号码开立的账户，可以选取一家联交所参与者并按机构维度……填写账户资金信息相关字段（包括账户资金规模……杠杆资金规模……杠杆率）。其以同一证件号码在其他联交所参与者开立的账户，不再重复填写上述信息，并在相应字段填写‘已在其他联交所参与者报告’……”
q2Unknown上海证券交易所程序化交易管理实施细则（doc_08）“本所可以对高频交易实施差异化收费，根据申报、撤单的笔数和频率等指标设置收费标准，加收流量费和撤单费等费用。具体收费标准由本所另行规定。”
q3No上海证券交易所沪股通投资者程序化交易报告信息填报注意事项（doc_03）“对于个别难以确定统一中文表述的字段，例如联交所参与者名称、账户名称、程序化交易软件名称等，可以填写英文。”

参考的英文解释（positive_answer_text）示意：q1 说明同一证件号码的机构账户可集中通过一家券商填报杠杆字段，其余券商标注已在别处报告；q2 说明规则提到两类费用但未给数额，称具体标准另行规定；q3 说明只许英文并不等于许可任意外文原名。

失分的典型形态

  • 结论方向答错。q2 是 Unknown（规则没给具体数额），误答 Yes 或 No 直接该题 0 分。q3 是 No，被“可以填写英文”误导成 Yes。
  • 证据不是原文照抄。自己改写、翻译成英文、或加了原文没有的字，导致归一化后不是被引文件的子串。
  • 证据漏了锚点。比如 q1 只抄了“选取一家联交所参与者”而没带“不再重复填写上述信息”和“已在其他联交所参与者报告”，三个锚点缺一即失败。
  • 引用文件名不在认可别名内。写了文件名的近似说法、英文名、或引用了含相同内容但不在 accepted_doc_ids 的其他文件。
  • 引文件和证据对不上。q3 引用了 doc_02 而不是 doc_03，即便证据句在别处出现，也可能因被引文件定位不到该句而失败。
  • answer_text 太短或不像英文。少于 20 字符或英文单词不足 3 个（例如只写 "No" 或写成中文）该项不过。
  • 顶层键缺失或写错。三键必须齐全，缺一整份 0 分；键名拼写不符也会被判缺失。
  • 输出文件缺失、JSON 非法、根不是对象：触发整体硬门槛，整份 0 分。
