题目做什么

任务提示词给 agent 的定位是：在 Linux 金融基准环境里，只用已经放好的 Zscaler 尽调素材包，为 Zscaler 写一份私募筛选备忘录。这里没有分难度层级，只有一个交付物，但交付物内部有固定的 6 个标题、5 个内容小节。评分实际上是按这 5 个小节 + 全文证据锚点来逐块给分的，所以下面按小节拆开，讲清每块要写什么、写到什么程度才被判定为覆盖到位。判定依据来自打分脚本里的 SECTION_QUESTIONS 和 ANCHOR_QUESTIONS。

第 0 步：读素材、套模板

先读 task_brief.md、memo_template.md、source_manifest.json，再读 5 组素材的 txt 抽取（pdf 是同一内容的原件，可选读）。模板占位标题 # [Company] Screening Memo 要改成 # Zscaler Screening Memo，占位日期 *[Date]* 换成实际日期。备忘录必须是 Markdown，跟着模板的 6 个标题走，只交这一个文件，不能写成 PPT、PDF 或脱离模板的散文。

I. Recommendation（建议，权重 0.15）

给出明确的 Go、No-Go 或 Hold / Needs More Diligence 之一，并说清一两个驱动这个判断的理由。裁判在这一节额外看三件事：是否解释了建议背后的理由；是否说清了什么条件成立会改变建议（比如从 Hold 转 Go 需要看到什么）；是否承认了影响判断的主要顾虑或不确定性。参考答案给的是 Hold，理由是素材足以看出公司质量高，但回答不了市占率、留存队列、产品级毛利等筛选关键问题。

II. Investment Thesis（投资逻辑，权重 0.25）

论证公司为什么(不)值得投，每点都要落到素材里的证据。裁判看 6 个话题是否覆盖：零信任架构如何替代 VPN / 防火墙等传统方案；企业客户基数规模（客户总数、Forbes Global 2000 / Fortune 500 渗透率）；核心平台之外的新产品支柱与其收入走向；land-and-expand 动态（新客获取、老客上销、净留存）；云基础设施规模或网络优势（交换点数量、地理覆盖、遥测数据资产）；竞争格局与竞争定位。

III. Financial Summary（财务概览，权重 0.25）

从素材读出财务画像，不许自己造数或做无依据的估值。裁判看 6 个话题：多期收入及增长轨迹；毛利/利润率并区分 GAAP 与非 GAAP；经营性现金流或自由现金流；前瞻性指标如递延收入、RPO、billings；客户或用量指标如 ARR、按消费档划分的客户数、净留存率；资产负债表项目，或指出可得数据里缺了哪些重要财务指标。

IV. Risks（风险，权重 0.20）

列出重大风险和未决问题，最好对每条说清用什么尽调工作能解决，并区分业务固有风险与当前信息缺口。裁判看 6 个话题：竞争或客户续约/流失风险；渠道伙伴依赖或收入集中；新产品执行风险；股权激励、股份稀释或 GAAP 与非 GAAP 的盈利质量问题；Red Canary 收购或并购整合风险；可得尽调数据的缺口与素材局限。

V. Appendix — Business Overview（业务概述附录，权重 0.15）

纯事实描述公司，不做解读。裁判看 6 个话题：业务模式与核心价值主张；具体产品或解决方案类别；客户群体含企业与政府客户；go-to-market 策略、销售渠道或伙伴生态；地理覆盖或云基础设施规模；关键财务指标或近期公司交易如收购。

全文证据锚点（ANCHOR_QUESTIONS，独立于分节，占总分 0.25）：另有 10 个针对全文的问题，考察备忘录是否落到了 Zscaler 特有的具体证据，比如零信任交换平台、客户渗透率具体数字、新战略支柱、新老客户收入结构、云交换网络规模、多年收入数字、毛利/营业利润率、自由现金流/经营现金流金额、递延收入/RPO/ARR/净留存具体值、Red Canary 收购或可转债。空泛、不带数字的备忘录在这一段会大量丢分。

用什么评测

评分链路：main.py 的 evaluate() 先在 VM 上确认三个文件都存在，即 output/screening_memo.md（候选）、reference/reference_memo.md（隐藏参考）、reference/evaluation_contract.json（评分契约），任一缺失直接返回 [0.0]。然后读入三份文本，调用 score_screening_memo.py 里的 score_screening_memo(candidate, reference, contract_text=...)，拿返回对象的 .score 作为该题唯一分数返回给 harness。

要点：打分函数签名里虽然收了参考备忘录 reference_text，但函数体第一行就 del reference_text 把它丢了。也就是说隐藏参考备忘录并不参与算分，它只是被 evaluate() 要求"必须存在"，存在与否是环境不变量、不是 agent 能左右的。真正被用到的隐藏文件是 evaluation_contract.json，脚本从里面取标题清单和通过阈值。这题的软分完全由候选备忘录自身的结构、覆盖度和证据密度决定，不做与参考答案的逐句相似度比对。

评测性质是 LLM 裁判：脚本用 openai 客户端调 gpt-4o-mini（temperature=0，max_tokens=5），对每个问题让模型回 yes/no，答案以 yes 开头计为覆盖。硬门槛部分则是纯程序化的（标题、词数、建议关键词）。分数是 0.0 到 1.0 的连续值，通过阈值 0.7，但返回给 harness 的是连续分，所以存在部分分。

怎么评测

第一步：三道硬门槛（任一不过直接 0.0）

顺序判定，命中即返回 0.0，不再算软分。

判据条件不满足的后果
必需标题齐全且有序契约 structural_requirements.canonical_headings 的 6 个标题，经归一化后要按顺序在备忘录里被找到（_missing_headings 用游标做子序列匹配）缺任一标题 → 0.0，hard_gate = missing required top-level sections
最少词数全文词数 ≥ MIN_WORD_COUNT = 250（按正则 [A-Za-z0-9][A-Za-z0-9$%.,/-]* 计词）< 250 → 0.0，hard_gate = memo too short
建议显式I. Recommendation 一节文本里，按词边界匹配到 go、no-go、no go、hold、needs more diligence、hold / needs more diligence 之一匹配不到 → 0.0，hard_gate = explicit recommendation missing

标题清单从契约读取；契约里没有 pass_threshold 键，所以阈值回落到默认 0.7。契约给出的 6 个标题里附录用的是全角破折号 ## V. Appendix — Business Overview，归一化后变成半角 ## V. Appendix - Business Overview，与脚本内置默认一致。

第二步：分节覆盖软分（占 0.75）

过了硬门槛后，脚本把备忘录按标题切成小节（level ≤ 2 的标题为父节，其下 level ≥ 3 子节的正文同时计入父节），然后对 5 个小节各自的文本逐问跑裁判。各小节覆盖度 = 命中问题数 / 该节问题总数，再按下表加权。

小节裁判问题数命中/总数说明权重
recommendation3额外送 1 分"建议已显式"的白给分（硬门槛已过），故分母记 4、分子起始 1，满覆盖 4/40.15
investment_thesis6命中数 / 60.25
financial_summary6命中数 / 60.25
risks6命中数 / 60.20
appendix6命中数 / 60.15

加权覆盖 weighted_coverage = 0.15·rec + 0.25·thesis + 0.25·fin + 0.20·risks + 0.15·appendix，五个权重相加为 1.0。各小节的具体裁判问题见上文"题目做什么"里每张卡片列的话题。

第三步：证据锚点软分（占 0.25）

10 个 ANCHOR_QUESTIONS 针对全文（不分节）逐一跑裁判，anchor_score = 命中数 / 10。这 10 问都要求落到 Zscaler 特有的量化证据，见下表。

#锚点问题（是否在全文出现）
1零信任交换平台 / 零信任架构
2企业客户基数量化（客户总数、Fortune 500 / Forbes Global 2000 渗透率）
3新战略支柱（扩展的安全类别、AI 安全、agentic 安全）
4新老客户收入结构，或具体上销 / land-and-expand 指标
5云交换网络规模（交换点数量、覆盖国家数）
6具体多年收入数字，体现增长轨迹
7具体毛利率 / 营业利润率，或营业利润金额
8具体自由现金流 / 经营现金流金额
9递延收入、RPO、ARR 或净留存率的具体数字
10Red Canary 收购或可转债

第四步：合成总分

score = round(0.75 * weighted_coverage + 0.25 * anchor_score, 6)
passed = score >= 0.7   # 阈值来自契约缺省，等于 0.7

全覆盖时 weighted_coverage = 1.0、anchor_score = 1.0，理论满分 1.0。返回给 harness 的是这个连续分，不是 pass/fail 的 0/1，所以覆盖越全、证据越密，分越高。要达到 0.7，粗略说要么各节覆盖都比较全、锚点也命中过半，要么在覆盖和证据两侧都做扎实，缺一侧都容易压不过阈值。

失分的典型形态

  • 直接 0 分没交 output/screening_memo.md，或写到了错误路径（例如照 brief 里的 finance/ 旧路径而非运行时描述给的 business_finance/ 路径）。
  • 直接 0 分缺任一必需标题，或标题文字与归一化后目标对不上、或顺序错乱导致子序列匹配失败。
  • 直接 0 分全文不足 250 词，被判"太短、不算认真尝试"。
  • 直接 0 分Recommendation 一节没写出 Go / No-Go / Hold 等关键词，建议不显式。注意关键词只在这一节里找。
  • 部分分结构齐全但内容空泛：只有定性套话、不带 Zscaler 特有的具体数字（收入、毛利、FCF、ARR、RPO、客户数、渗透率、交换点数），锚点 10 问会大面积判否，直接砍掉那 0.25 的证据分。
  • 部分分某些小节覆盖不全：比如 Financial Summary 只提收入不提 GAAP 与非 GAAP 之别、不提现金流或 ARR/RPO；Risks 漏掉渠道依赖、SBC/盈利质量、Red Canary 整合或尽调缺口；Thesis 不谈竞争格局或新产品支柱。每漏一个话题就少一份分节命中。
  • 部分分把内容写在错误的小节里：裁判是按小节文本判该节问题的，比如财务数字全堆在附录、Financial Summary 一节本身内容单薄，会让 financial_summary 那 0.25 权重的覆盖度偏低。
  • 部分分Recommendation 只给结论、不解释理由、不写"什么条件会改变建议"、不承认顾虑，三个裁判问题命中少，拉低 0.15 权重节的覆盖度。
  • 风险编造素材里没有的数字或做无依据的估值。虽然打分脚本不核对事实真伪（不与参考做逐句比对），但 brief 明令禁止，且不带真实数字的内容也很难让裁判判"覆盖到位"。
