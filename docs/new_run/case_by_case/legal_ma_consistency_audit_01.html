并购申报文件一致性审计

taskId：business_finance/legal_ma_consistency_audit_01

读四份关于同一笔股份协议转让的中文监管申报文件，交叉核对找出四处事实性不一致，写一份英文审计报告，每处附中文原文证据和文档加页码定位；评分脚本用正则和字符串匹配逐条核验，四处必须全召回否则直接 0 分。

题目做什么

同一笔股份协议转让，涉及四份中文文件：一份公告和三份简式权益变动报告书（受让方 1、受让方 2、转让方）。这四份文件对同一交易的若干数据本应一致，但被人为植入了不一致。任务是逐份读取，交叉比对，把这些不一致找出来，写成英文审计报告。

参考答案定死了 4 处目标不一致（target_a 到 target_d），分属四种类别：文字笔误、数值不符、股权结构不符、资金来源逻辑矛盾。评分只认这 4 处。转让方报告书（seller_report，Document 4）是干扰项，不涉及任何目标不一致，也不在打分脚本的文档别名表里。下面逐个拆解。

target_a｜控股股东定义的文字笔误（Clerical）

公告「重要内容提示」段把「控股股东」误写成「空股股东」。这是一处错别字，法律文书里应为「控股股东」。

  • 文档与页码：Document 1（公告），第 1 页。
  • 中文证据：空股股东物美科技集团有限公司。
  • 佐证：同一份公告后文正确用了「控股股东」（例如「不涉及公司控股股东、实际控制人」），说明第 1 页那处是笔误。

target_b｜受让方 2 转让对价数值不符（Numerical）

公告的摘要表把受让方 2（厦门联芯美）的协议转让对价写成 146,660,323.00，比公告详细条款和受让方 2 自己报告书里的 146,660,332.00 少 9 元。三处形成一低两高的矛盾，摘要表那处是错的。

  • Document 1（公告）第 2 页摘要表：协议转让对价 146,660,323.00（错值）。
  • Document 1（公告）第 11 页股份转让协议详情：146,660,332.00 元（正确值）。
  • Document 3（受让方 2 报告书）第 7 页交易价格：146,660,332.00 元（确认正确值）。

target_c｜受让方 1 股权结构不符（Structural）

受让方 1 的主要合伙人「聚源盛业投资（宁波）有限公司」的持股比例，公告写 45%，受让方 1 自己的报告书写 40%。同一主体、同一口径，两份文件数值不同。

  • Document 1（公告）第 4 页受让方 1 基本情况：聚源盛业投资（宁波）有限公司持有 45%合伙份额。
  • Document 2（受让方 1 报告书）第 5 页股东结构：聚源盛业投资（宁波）有限公司持有 40%合伙份额。

target_d｜受让方 1 资金来源逻辑矛盾（Logical）

公告摘要表把受让方 1 的资金来源勾成「自有资金」，但受让方 1 的报告书写明部分资金来自银行借款。自有资金（权益）与借款（债务）是两种性质，构成逻辑矛盾。

  • Document 1（公告）第 2 页摘要表：√自有资金（勾选框）。
  • Document 2（受让方 1 报告书）第 12 页资金来源：本次权益变动资金来源部分来源于信息披露义务人向银行的借款。
四处的层级关系：没有难度分层，四处是并列的独立检查点。但打分对它们不是平权的。召回是硬门，四处任一漏掉整份报告直接 0 分；证据和定位是软扣分，缺一处扣 0.2 或 0.1。所以先保证四处全找到，再逐处补齐中文证据和文档页码。

硬性要求

  • 报告用英文写。
  • 只交一个文件：output/audit_report.md（Markdown）。
  • 报告出能从材料里支撑的每一处实质性不一致；不许编造材料不支持的问题（编造会被当作误报扣分）。
  • 每处发现必须包含四件东西：简短英文标题、冲突的简要说明、能证明问题的中文原文、带文档名和页码的定位标记。
  • 中文证据要用文件里的原文，不能只给英文转述。
  • 报告体量不能超过 200,000 个 UTF-8 字节，否则直接判 0。
  • 要脚本解析材料时，用任务根目录下的 software/python。

要交什么

唯一产物：base/output/audit_report.md。评分脚本按 Markdown 标题切分「发现」小节，因此建议每处发现用一个 ## 标题起头，标题里带能被识别为「发现」的词（见下节）。task_brief 给的建议结构如下，参考答案 gold_findings.md 就是这个格式：

# Share Transfer Disclosure Consistency Review

## Finding 1: <title>
- Documents: ...
- Why it is inconsistent: ...
- Evidence:
  - `Document X, Page Y`: `<Chinese text>`
  - `Document Z, Page W`: `<Chinese text>`

定位标记的写法很关键：文档名和页码要写在同一行、且彼此靠近，例如 `Document 1 (Announcement), Page 2`。脚本按行、按分隔符（; ； |）切段来判定「某文档」与「某页码」是否配对，写得太散会判定不成对。

用什么评测

评分链路：main.py 的 evaluate() 先确认 output/audit_report.md 和参考文件 reference/gold_findings.json 都存在（缺任一返回 [0.0]）。然后把两者读进临时目录，调用 score_report_text(report_text=..., reference_payload=...)，取返回字典里的 score 字段转成 float 作为唯一分数返回。整个过程抛异常也返回 [0.0]。

这是纯程序化打分。score_audit_report.py 只 import 了 argparse、json、re、dataclasses、pathlib、typing，没有任何 LLM、网络或子进程调用。所有判定都是正则匹配和 Python 字符串包含判断。参考答案 gold_findings.json 提供四处目标（required_findings），但脚本并不直接文本比对参考答案，而是把每处目标编码成一组固定的匹配、证据、定位规则，用这些规则去扫 agent 的报告。

分值构成：满分 1.0 起，先过两道硬门，再逐项软扣分。

  • 硬门（任一触发直接 0.0）：报告为空；报告 UTF-8 字节数超过 200,000；四处目标里有任何一处未被召回。
  • 软扣分（召回全过之后）：每个多报的、材料不支持的「发现」小节扣 0.2；每处已召回但缺中文证据的目标扣 0.2；每处已召回但文档页码定位不对的目标扣 0.1。最后 clamp 到 [0.0, 1.0]。

怎么评测

脚本先用 _split_sections 按 Markdown 标题（# 到 ######）把报告切成小节（没有标题就整篇当一节），再对每处目标跑三层判定：召回匹配、证据、定位。文本判定前会做归一化（转小写、全角空格转半角、全角冒号括号引号转半角、折叠连续空白）。中文关键词按原文匹配（大小写归一化不影响中文）。

第一层：召回匹配（match，硬门，四处必须全过）

对每处目标，先在每个小节上试规则，再在整篇上试一次；小节命中或整篇命中即算该处「已召回」。四处里任一未召回，直接返回 0.0，reason 为 missing_required_targets。文档是否被提到，由别名表判定（announcement 认 announcement / document 1 / doc 1 / 公告 等；buyer1_report 认 buyer 1 / document 2 / doc 2 / 受让方1 等；buyer2_report 认 buyer 2 / document 3 / doc 3 / 受让方2 等。转让方无别名）。

目标召回需同时满足
target_a提到公告 且 文本含 空股股东 且（含 控股股东，或归一化文本含 typo / clerical / should read / instead of / error 之一）。
target_b提到公告 且 提到受让方 2 报告 且 命中 146,660,323（可带 .0）且 命中 146,660,332（可带 .0）。数字正则允许中间有空格或逗号。
target_c提到公告 且 提到受让方 1 报告 且 含 45% 且 含 40% 且（含 聚源盛业 或 合伙份额，或归一化含 ownership / shareholder）。
target_d提到公告 且 提到受让方 1 报告 且 含 自有资金 且 含借款语（借款 或 银行，或归一化含 bank loan / loan）。

第二层：证据（evidence，每缺一处扣 0.2）

已召回的目标，若拿不出足够的中文原文证据，扣 0.2。命中判定用命中的小节聚合（任一命中小节的证据 OK 即算 OK）；若只靠整篇命中则在整篇上判。

目标证据需满足不满足后果
target_a文本含 空股股东。该处扣 0.2
target_b同时含 146,660,323 和 146,660,332 且（含 协议转让 或 对价）且（含 元 或 受让方2）。
target_c含 45% 和 40% 且（含 聚源盛业 或 合伙份额）。
target_d含 自有资金 且（含 借款 或 银行）。

第三层：定位（location，每缺一处扣 0.1）

已召回的目标，若文档加页码的配对不对，扣 0.1。判定函数 _doc_has_page_pair 逐行扫描：在一行里找到某文档别名后，以相邻别名和分隔符（; ； |）为边界圈出该别名左右的局部片段，片段里出现的页码若与期望页集合有交集即算配对成功。所以文档名和页码要写在同一行且靠得近。

目标定位需满足（全部配对）不满足后果
target_a公告 + 第 1 页。该处扣 0.1
target_b公告 + 第 2 页 且 公告 + 第 11 页 且 受让方 2 报告 + 第 7 页（三处都要）。
target_c公告 + 第 4 页 且 受让方 1 报告 + 第 5 页。
target_d公告 + 第 2 页 且 受让方 1 报告 + 第 12 页。

第四层：误报（false positive，每处扣 0.2）

召回全过后，脚本用 _split_claim_units 把报告按「像发现的行」切成一个个主张单元。一行被当作发现的开头，需要它看起来像发现标题（以 finding 开头，或含 finding / issue / error / mismatch / contradiction / discrep / clerical / numerical / structural / logical 之一），且不是明显的佐证行（以 documents: / document: / category: / why it is inconsistent: / evidence: / location: / page 等开头的行会被排除）。若某个被识别为「主张」的单元不匹配四处目标里的任何一处，就算一处误报，扣 0.2。识别「主张单元」的条件是：标题像发现，或（含 evidence 且有页码且提到某个别名文档）。

最终计分

score = 1.0
score -= 0.2 * 误报小节数
score -= 0.2 * 缺证据的已召回目标数
score -= 0.1 * 缺定位的已召回目标数
score = clamp(score, 0.0, 1.0)   # 再 round 到 6 位小数

据此可自查：四处全召回、四处都带对中文证据、四处都带对文档页码、且不多报，得 1.0。举例：四处召回但其中一处缺证据、另一处定位错、还多报一处 → 1.0 − 0.2 − 0.1 − 0.2 = 0.5。任一处目标漏召回 → 0.0。

失分的典型形态

  • 0 分 漏掉四处中任一处。这是最常见的归零原因，尤其容易漏 target_b 的三处配对之一，或把某处不一致写得不满足召回规则（比如只写了 40% 没写 45%、只提受让方 1 没提公告）。
  • 0 分 没交 output/audit_report.md、文件为空、或超过 200,000 字节。
  • −0.2 只给英文转述、缺中文原文。例如 target_b 只写了两个数字却没带 协议转让/对价 和 元/受让方2，或 target_c 没带 聚源盛业/合伙份额。
  • −0.1 文档页码配对不对或不成对。常见于把文档名和页码写在不同行、或页码写错（target_b 少了公告第 11 页那一条、target_d 把受让方 1 写成第 2 页而非第 12 页）。
  • −0.2 每处 多报材料不支持的「发现」。典型是对干扰项转让方报告书（Document 4）编造不一致，或把同一处不一致拆成多个带发现标题的小节，多出来的会被算误报。
  • 定位写法踩坑：脚本按行和分隔符切段判配对，若把多处文档页码堆在一大段自由文字里、彼此不靠近，可能判为不成对而扣 0.1。按建议模板每条证据单起一行、文档名紧挨页码最稳妥。
