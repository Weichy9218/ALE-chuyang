SEC 10-K 财报批量解析

taskId：business_finance/sec_10k_financial_parsing

把 100 份 SEC 10-K 年报 PDF 解析成规范化的财务 JSON，同时保存每份 PDF 用到的原始文本证据，回答 3 道跨公司分析题，并对 5 份固定验证子集做一次可复现的二次解析。评分由基准自带的 score_outputs.py 程序化打分，8 个加权分项汇总成 0.0 到 1.0 的连续分。

题目做什么

语料是 10 家美国上市公司（AAPL、BAC、CVX、JNJ、JPM、MSFT、PFE、UNH、WMT、XOM）2015 到 2024 共 10 个财年的 10-K 年报，合计 100 份 PDF。任务分成 5 件产出，可以看成 4 个阶段。评分器对这些产出各自打分再加权汇总。

阶段 1：解析全部 100 份 filing，产出规范化 JSON

对 input/filings/ 里每份 PDF 抽取 5 个元数据字段和 10 个财务字段，按 extraction_schema.json 的结构写成一个 JSON，文件名与 PDF 同名（如 AAPL_10K_2024.json），放到 output/extractions/。

元数据字段：company_name、ticker、cik（补零到 10 位）、filing_date、fiscal_year_end（后两者为 YYYY-MM-DD）。这些在 input/filings/manifest.json 里都能查到，manifest 每条含 ticker、cik、company_name、fiscal_year、filing_date、accession_number、local_path、is_scanned。

财务字段共 10 个：revenue、cost_of_revenue、operating_income、net_income、total_assets、total_liabilities、stockholders_equity、cash_and_equivalents（8 个货币字段，单位为原始美元的整数），以及 eps_basic、eps_diluted（每股收益，浮点，2 位小数）。这些要从 PDF 的财务报表里读出来并按规则规范化。

阶段 2：保存原始文本证据

对每份 filing 另存一个 .txt 到 output/raw_extractions/（同名，如 AAPL_10K_2024.txt），内容是这份 PDF 实际用到的原始抽取文本。评分器把它和隐藏的 raw_text_baselines/*.txt 做 ANLS（近似文本相似度）比对，用来核验财务数字确实来自这份 PDF，而不是编造。基准的 baseline 文本是从 PDF 直接抽出的整篇纯文本（十几万到上百万字符不等），所以用 pdfplumber/pypdf 抽全文本落盘是稳妥做法。

阶段 3：回答 3 道跨公司分析题

题目在 input/questions.json，答案写到 output/qa_answers.json，键为 Q1/Q2/Q3。

  • Q1：哪家公司从最早可得财年到最晚财年的营收百分比增幅最大？报 ticker 和 pct_increase（1 位小数）。
  • Q2：在全部 10 家公司、全部年份里，哪个「公司-年份」的经营利润率（operating_income / revenue）最低？报 ticker、fiscal_year（整数）、operating_margin_pct（百分比，2 位小数）。
  • Q3：只看 2023 财年，把 10 家公司按 stockholders_equity 从高到低排序，报有序的 ticker 列表。

这三题都要基于自己阶段 1 抽出的数据来算，本质是对提取结果的一致性检验。

阶段 4：验证子集的可复现二次解析

input/validation/ 里放了 5 份固定 PDF（AAPL、JPM、MSFT、WMT、XOM 的 2024 年报，与主语料中的 2024 份是同样文件）。要用同一套解析流程再跑一遍，把第二遍结果写到 output/run2_extractions/（同名 JSON）。评分器逐字段比较 output/extractions/{stem}.json 与 output/run2_extractions/{stem}.json 是否完全相等，考的是解析流程的确定性。input/config/determinism_config.py 给了 DETERMINISM_SEED=42 并设 PYTHONHASHSEED，提示要保证两遍输出逐字节一致。

硬性要求

  • 严格遵守 extraction_schema.json 的结构和 normalization_rules.txt 的规范化规则。
  • 货币字段用原始美元整数，不能用「百万」「十亿」为单位。例：报表写 "Revenue: 391,035"、表头 "in millions" → 输出 391035000000。
  • 括号数字表示负数："(1,234)" → -1234。转整数前去掉逗号和货币符号。
  • EPS 保留恰好 2 位小数。
  • 某字段在 filing 里确实没披露时用 null，不能用 0。
  • filing 含多年对比表时，取最近财年的数据。
  • 不得写到 output/ 目录之外；不得修改 input/ 下任何文件。
  • 验证子集的二次解析必须是对同一批可见验证 filing 的第二次确定性解析。
  • runtime 只用基准提供的可见资产：pdfplumber、pypdf、pydantic（原始提交里的 GPU / VLM 设置不作为对 solver 可见的要求）。manifest 标注这批 PDF 均 is_scanned=false，即机器可读、无需 OCR。

用什么评测

评分链路在 main.py 的 evaluate()：先确认 6 个 reference 路径都在（缺任何一个直接返回 [0.0]），把 score_outputs.py 写到 VM 的临时目录，然后用一条命令把 9 个路径参数喂给它：predictions（output/extractions）、ground-truth（reference/ground_truth）、raw-extractions、baselines、qa-predictions、qa-ground-truth、run2-extractions、validation-manifest、cross-validation-expectations。

评分器把结果打成一个 JSON payload 打印到 stdout。evaluate() 用 _extract_json_payload 从 stdout 里抓出这个 JSON，取 payload["score"] 作为最终分。命令返回码非 0、或 stdout 里解析不出合法 JSON，都返回 [0.0]。

这是纯程序化打分：逐字段和隐藏参考答案比对，没有 LLM 裁判，也没有隐藏测试套件。score 是 8 个分项的加权和（连续值 0.0 到 1.0）。payload 里还带 passing_threshold=0.75，但 harness 只取 score，不做阈值判定，也就是说这题拿的是连续分而非 0/1。

8 个分项和权重（合计 1.00）：

分项权重分值怎么来
schema_compliance5%schema 合规的 filing 数 / 100
metadata_accuracy5%元数据字段答对数 / 元数据总字段数
financial_accuracy30%财务字段答对数 / 财务总字段数（本题最大头）
anls_verification10%100 份原始文本 ANLS 相似度的平均
analytical_qa25%Q1/Q2/Q3 三题得分的平均
cross_validation10%会计恒等式判定与参考期望一致的 filing 数 / 100
completeness5%找到的预测文件数 / 100
determinism10%两遍完全一致的验证 filing 数 / 5
关键联动：评分器对每份 filing 先算 ANLS，阈值 ANLS_THRESHOLD=0.6。若某份 filing 的原始文本 ANLS < 0.6（或原始文本 / baseline 缺失），这份 filing 会被标记 zeroed，它在 schema、metadata、financial、cross_validation 四项里的得分全部清零（不进分子，但分母照算）。原始文本这一步做不好，会连带拖垮占 30% 的财务分。ANLS 分项本身仍按真实相似度计入平均。

怎么评测

评分器遍历 100 个 ground_truth 文件，逐份按下列判据打分。想自查得几分，对着这张表核对即可。

判据阈值 / 条件不满足的后果
ANLS 门槛（compute_anls）raw_extractions/{stem}.txt 与 baseline 的 ANLS ≥ 0.6< 0.6 或文件缺失 → 该 filing 记入 anls_failed，其 schema/metadata/financial/cross 四项全清零。
ANLS 分值本身对齐后完全相等记 1.0；一方是另一方子串记「短/长」长度比；否则切 500 字符 chunk（长度≥50，最多前 20 块），子串命中记 1.0，否则在按位置估算的窗口内取归一化 Levenshtein 相似度的最大值，最后取各 chunk 平均文本差异越大分越低，直接拉低 10% 的 anls 分项，并可能跌破 0.6 触发清零。
schema 合规（_schema_valid）顶层键集合恰为 6 个；5 个元数据均为字符串；financials 为 dict 且键集合恰为 10 个；每个货币字段是 int 或 null（不能是 float / 字符串）；EPS 是 int/float 或 null任一条不满足 → 该 filing 不计入 schema_valid。且被 zeroed 的 filing 即使结构正确也不计。
元数据比对（_metadata_score）逐字段：company_name 大小写不敏感相等；ticker/cik/filing_date/fiscal_year_end 去空格后严格字符串相等（cik 必须补零到 10 位，日期必须 YYYY-MM-DD）每份 5 个字段，答对才进分子；被 zeroed 的 filing 分子记 0，分母仍 +5。
财务比对（_financial_score）货币字段：pred 与 gt 都为 null 记对；一方 null 记错；gt=0 时 pred 也须为 0；否则相对误差 abs(pred-gt)/abs(gt) ≤ 0.005（0.5%）。EPS：两数 round(_,2) 相等记对每份 10 个字段。数值超差、单位没换成原始美元、该 null 却填了数或该填数却给 null，都判错。被 zeroed 的 filing 分子记 0，分母仍 +10。
交叉验证（_cross_validation_ok 对比期望）用 pred 的 total_assets、total_liabilities、stockholders_equity 算会计恒等式：三者非空、assets≠0 且 abs(assets-liab-equity)/abs(assets) ≤ 0.001 记「通过」。把这个布尔值与 cross_validation_expectations[stem].check_passed 比较，相等才得分注意不是「恒等式必须成立」，而是「pred 的判定要与参考期望一致」。参考里 80 份期望 True、20 份期望 False（10 份 UNH 因少数股东权益缺口使差额非零，10 份 WMT 因 total_liabilities 为 null）。这 20 份要求 pred 也判「不通过」。被 zeroed 的 filing 记 0。
完整性成功读到并能 JSON 解析的 output/extractions/{stem}.json 数 / 100文件缺失或不是合法 JSON → 不计入 found_predictions，且该份的 metadata/financial 分母照加（等于白丢那份的 4 项分）。
QA-Q1（_qa_score）ticker 大写相等 且 abs(pred_pct - gt_pct) ≤ 0.15 → 1.0，否则 0.0ticker 错或增幅超差 → 该题 0 分。
QA-Q2ticker 大写相等 且 fiscal_year 整数相等 且 abs(pred_margin - gt_margin) ≤ 0.05 → 1.0，否则 0.0三者有一不满足 → 该题 0 分。
QA-Q3对两个 ticker 排名列表算归一化 Kendall's tau：(tau+1)/2，落在 0 到 1顺序错得越多分越低；共同元素少于 2 个记 0。
确定性（_determinism_score）对 validation_manifest 里 5 个 stem，output/extractions/{stem}.json 与 output/run2_extractions/{stem}.json 都存在且 dict 完全相等记 1，得分 = 命中数 / 5run2 缺文件、或两遍任一字段不一致 → 该份不计。checked 恒为 5。

汇总：aggregate = 0.05·schema + 0.05·metadata + 0.30·financial + 0.10·anls + 0.25·qa + 0.10·cross + 0.05·completeness + 0.10·determinism，四舍五入 4 位小数。完全正确的端到端产出得 1.0；仓库里committed的负样本（一份貌似合理但错误的提交）在当前评分器下得 0.0005。

参考答案的目标值

reference 是隐藏的，agent 看不到，只用于打分。核心目标值如下，供对表。

  • QA 目标（qa_ground_truth.json）：Q1 = {ticker: MSFT, pct_increase: 161.9}；Q2 = {ticker: WMT, fiscal_year: 2023, operating_margin_pct: 3.37}；Q3 排名 = [JPM, BAC, XOM, MSFT, CVX, UNH, PFE, WMT, JNJ, AAPL]。
  • ground_truth 示例（AAPL_10K_2024.json）：revenue 391035000000、net_income 93736000000、total_assets 364980000000、total_liabilities 308030000000、stockholders_equity 56950000000、eps_basic 6.11、eps_diluted 6.08。
  • null 不是异常而是正解：跨 100 份 ground_truth，operating_income 有 60 份为 null、cost_of_revenue 33 份、cash_and_equivalents 18 份、total_liabilities 10 份（全部 WMT）。该 null 的字段填了数字会判错。
  • 交叉验证期望（cross_validation_expectations.json，100 条）：80 条 check_passed=true，20 条 false。false 的 20 条是 10 份 UNH（assets 与 liab+equity 差 14 亿到 49 亿美元，占比超 0.1%）和 10 份 WMT（total_liabilities 为 null，导致 liab+equity 无法计算）。
  • 验证子集（validation_manifest.json）：validation_filing_stems = [AAPL_10K_2024, JPM_10K_2024, MSFT_10K_2024, WMT_10K_2024, XOM_10K_2024]。
  • raw_text_baselines：100 个 .txt，是从各 PDF 抽出的整篇纯文本，长度约 15 万到 130 万字符。agent 的原始文本只需与之达到 ANLS ≥ 0.6，不必逐字相同。

失分的典型形态

  • 高危 原始文本质量差导致 ANLS < 0.6：该 filing 的 schema、metadata、financial、cross 四项被整份清零。财务占 30%，一旦大面积触发清零，总分会崩。忘了写 output/raw_extractions/*.txt 同样触发。
  • 高危 货币单位没换成原始美元：报表以「in millions」列示时直接抄 391035 而不是 391035000000，相对误差远超 0.5%，8 个货币字段全错。
  • 易错 货币字段写成 float 或字符串：schema 要求货币是 int，写成 391035000000.0 或 "391035000000" 会导致 schema 不合规。
  • 易错 该 null 的字段填 0 或估算值：规则明确「没披露用 null 不用 0」，且 60 份的 operating_income、33 份的 cost_of_revenue 等本就是 null，填了数字会判错。反之该有数却填 null 也判错。
  • 易错 误解交叉验证：以为让每份都满足会计恒等式就对。实际 UNH 和 WMT 共 20 份期望「不通过」，如果强行「修平」这些数字反而与期望不一致，丢分。要如实抽取，让判定自然匹配。
  • 易错 cik 未补零到 10 位、日期非 YYYY-MM-DD、company_name 之外的字段大小写/空格不符：metadata 严格字符串相等，逐字段丢分。
  • 易错 多年对比表取错年份：规则要求取最近财年，取成上一年整份财务数据全偏。
  • 易错 二次解析不确定：run2 与首遍任一字段不一致（如浮点格式、键顺序影响 dict 相等、时间戳混入），determinism 每份 0.2 分丢掉。run2 缺文件同样丢分。
  • 易错 QA 算错：Q1 取错「最早/最晚可得财年」的营收基准、Q2 漏扫某公司-年份、Q3 排名顺序错，都会丢对应分项（Q1/Q2 是 0/1，Q3 按 Kendall's tau 部分给分）。
  • 高危 少交文件：output/extractions/ 缺某份 → completeness 掉分，且该份 metadata/financial 分母照算等于净丢。reference 路径缺失或评分器命令非 0 退出、stdout 无合法 JSON → 直接 0.0。
