题目做什么

一句话说清背景：这是一个个性化邮件主题行的 A/B 测试。对照组用通用主题行，实验组用带客户名字和最近浏览品类的个性化主题行。假设个性化能把邮件打开率提升至少 3 个百分点。要做的是拿到实验原始数据，完成随机化健康度检查、逐指标的两比例推断加多重比较校正、以及一份带最终 ship 或 hold 结论的报告。

数据与关键约定

核心数据文件是 experiment_results_raw.csv，8818 行，每行一个客户，列为 customer_id, variant, delivered, opened, clicked, converted, unsubscribed。variant 取 control 或 treatment，后五列是 0/1 事件标记。

主要指标是打开率 opened_rate（opens / delivered）。三个次要指标是点击率 clicked_rate、转化率 converted_rate、退订率 unsubscribed_rate，都以 delivered 邮件为分母。护栏是退订率提升不超过 0.5 个百分点。

最容易踩的约定：task_description 反复强调所有评分计算都用 raw 文件的全部行，不要按 exclusion_rules.yaml 过滤人群。exclusion_rules.yaml、eligible_population.csv、active_experiment_customers.csv 是背景干扰文件。如果 agent 用这些规则去剔除人群再算，得到的计数和率会和参考不一致，直接失分。指标率只在 delivered == 1 的行上算（本数据里所有行 delivered 都是 1，两种口径数值相同，但方法上要按 delivered 过滤）。

产物一：randomization_assignment.csv（随机化健康度 / SRM）

两列 metric,value，六行，每行一个指标：n_control、n_treatment、ratio（treatment/control 比值）、srm_chi2、srm_pvalue、srm_pass。

要在 raw 全体人群（不过滤 exclusion、不过滤 delivered）上做样本比例失配（SRM，sample ratio mismatch）卡方检验，原假设是两臂 50/50 均分。卡方统计量 chi2 = Σ(观测 − 期望)² / 期望，自由度 1，p 值取卡方分布右尾。本数据两臂各 4409 人，完全均衡，因此 ratio = 1.0、srm_chi2 = 0.0、srm_pvalue = 1.0、srm_pass = True。

产物二：experiment_results.tsv（两比例推断 + BH 校正）

制表符分隔，正好 4 行，每行一个指标。14 列：metric, is_primary, control_rate, treatment_rate, absolute_lift, relative_lift_pct, ci_lower_95, ci_upper_95, z_statistic, p_value_raw, significant_at_05, bh_rank, bh_threshold, bh_significant。

逐指标的两比例推断方法（按 variant 分组、只在 delivered 行上算率）：

  • 率 p_c = x_c / n_c，p_t = x_t / n_t，其中 x 是事件数、n 是该臂 delivered 行数。
  • 绝对提升 absolute_lift = p_t − p_c。相对提升 relative_lift_pct = diff / p_c × 100，当 p_c 为 0 时特判为 0。
  • 95% 置信区间用非合并标准误：SE = sqrt(p_c(1−p_c)/n_c + p_t(1−p_t)/n_t)，区间 diff ± 1.959964 × SE，这里 1.959964 是 NormalDist().inv_cdf(0.975)。
  • z 统计量用合并标准误：pooled = (x_c + x_t)/(n_c + n_t)，SE_pooled = sqrt(pooled(1−pooled)(1/n_c + 1/n_t))，z = diff / SE_pooled。当 pooled 等于 0 或 1 时 SE 记 0、z 记 0。
  • 原始 p 值双尾 p_value_raw = 2(1 − Φ(|z|))，显著性 significant_at_05 = p_value_raw < 0.05。

置信区间用非合并标准误、z 统计量用合并标准误，两处标准误口径不同，这是本题一个容易搞混的技术点。

Benjamini-Hochberg（BH）多重比较校正只对三个次要指标做，主要指标那三列留空。把三个次要指标的原始 p 值升序排名（m = 3），阈值 bh_threshold = rank / m × 0.05，显著性 bh_significant = (p ≤ bh_threshold)。

产物三：experiment_report.md（功效分析 + 决策）

Markdown 报告，脚本会检查三件事必须出现：每臂所需样本量、含 ship 或 hold 的 Recommendation 小节、主要指标观测到的绝对提升。

样本量来自对 historical_metrics.csv 的功效分析。基线打开率取该文件 open_rate 列的均值（52 周，约 0.21857）。参数 MDE = 0.03、alpha = 0.05、power = 0.80。两比例样本量公式：

p1 = baseline,  p2 = baseline + 0.03,  p_bar = (p1 + p2)/2
z_alpha = inv_cdf(0.975),  z_beta = inv_cdf(0.80)
n = ( z_alpha·sqrt(2·p_bar(1−p_bar)) + z_beta·sqrt(p1(1−p1)+p2(1−p2)) )² / 0.03²
n = ceil(n) = 3122

决策规则：当且仅当主要指标显著（p < 0.05）且护栏通过（退订率绝对提升 < 0.5 个百分点）时给 ship，否则 hold。本数据主要指标 p = 0.000182 显著，退订率提升 0.272 个百分点小于 0.5，因此正确结论是 ship。

硬性要求

  • 只在 output/ 下写这三个文件，文件名精确，不多不少。缺任何一个直接 0 分。
  • 所有指标计算用 experiment_results_raw.csv 的全部行，不按 exclusion_rules.yaml 过滤，也不引用 eligible_population.csv 或 active_experiment_customers.csv 去剔人。
  • SRM 检验用 raw 全体人群，不按 delivered 过滤；指标率用 delivered == 1 的行。
  • TSV 必须制表符分隔、正好 4 行、四个指标齐全，BH 三列只在次要指标行填，主要指标行留空。
  • assignment CSV 的六个 metric 键必须与规定集合完全一致。
  • 报告须含样本量数字、字符串 3.4、recommendation 一词以及 ship 或 hold。
  • 软件依赖装在 input/runtime_env 下并用 uv 隔离，不要依赖全局 VM 包（software/README.md 的说明）。

用什么评测

main.py 的 evaluate() 把 verify_ab_test_outputs.py 写到 VM 的 /tmp/agenthle_eval/<task>/ 下，运行 python3 verify_ab_test_outputs.py --input-dir <input> --reference-dir <reference> --output-dir <output>。脚本把一个 JSON 打到标准输出，harness 解析后取 payload["score"]，返回 [float(score)]。命令返回码非 0，或 JSON 解析失败，都返回 [0.0]。

脚本内部流程：先检查三个产物文件是否都存在，缺任一个则 score = 0.0 直接返回。齐全后，从 input/ 的原始数据重算 expected_stats（逐指标统计量）和 required_n（样本量），再跑三个校验函数 validate_assignment_csv、validate_results_tsv、validate_report_md。score = 1.0 当且仅当三者都返回 True。

评分是对照重算，不是逐字对照参考文件。脚本里有个 reference_match 会把三份产物和 reference/ 下同名文件做去空白后的整段字符串比对，但这个结果只写进 JSON 记录、不进 score。所以数值只要落在容差内、格式对，就算过，字面不必和参考完全一致。

失分的典型形态

  • 按 exclusion_rules.yaml、eligible_population.csv 或 active_experiment_customers.csv 过滤人群再算，计数和率整体偏离，assignment 与 results 同时失分。这是本题最主要的陷阱。
  • 置信区间用了合并标准误、或 z 统计量用了非合并标准误，把两处标准误口径搞反，导致 ci 或 z 超容差。
  • BH 校正错误：把 BH 三列填进主要指标行、对四个指标（含主要）一起做 BH、排名或阈值算错、m 取成 4 而非 3。
  • TSV 用逗号分隔而不是制表符、行数不是 4、缺列或列名不符。
  • SRM 用了 delivered 子集或某指标口径而非 raw 全体人群（本数据两者恰好相同，但方法错在别处会翻车），或 srm_pass 写成 False。
  • ratio 或 srm_pvalue 卡在边界：ratio 必须落在 1.0 附近 0.001 内，srm_pvalue 必须严格大于 0.01。
  • 报告漏样本量数字、样本量算出超出 [3120, 3122]、漏字符串 3.4、决策写成 hold、漏 recommendation 或漏 ship/hold 词。
  • 只交两份文件、文件名拼错或放错目录，缺文件直接判 0。
