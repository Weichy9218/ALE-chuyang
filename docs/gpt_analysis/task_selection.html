ALE 题目盘点与选题：pi × gpt_claw 研究批次

先把 ALE 全量题库数清楚，按约束筛出能在本地跑的题，再挑出适合做 harness 研究和攒训练数据的批次，最后用已有的 25 题结果对新批次做预判。
题库来源 agents-last-exam（ALE） 模型 gpt-5.6-sol harness pi 与 gpt_claw 日期 2026-07-13
题目来源已核对。全部题目爬自 ALE 官方题库，GitHub 源仓库 git@github.com:rdi-berkeley/agents-last-exam.git（本地 origin 远端就是它），以及 HuggingFace 数据集族 huggingface.co/agents-last-exam（题卡、输入文件、参考答案三个配套数据集）。本地仓库的任务卡、输入、参考答案与这两处一致。
两套 harness 是什么，一句话区分。pi 是约 700 行的薄包装，把 agent 主循环交给外部 pi 编码 CLI，只在 Linux 容器里用 bash 和读写文件这几个工具，不带图形界面，薄而快、轨迹干净，适合产训练数据。gpt_claw 是仓库自带的重型框架（从 OpenClaw 改写）跑 gpt-5.6-sol，本轮起关掉全部图形界面工具，只留 exec/read/write/edit，和 pi 站在同一条无界面起跑线上比；它多带记忆、子 agent、上下文压缩，但无界面题上这些用不上。

一分钟结论

  • 全量多少题？ ALE 已发布 165 道。按运行环境分，109 道能在本地 Linux Docker 跑（cpu-free-ubuntu），其余要 Windows 桌面、GPU 或授权软件。
  • 按你的约束能挑多少？ 从 109 道 Linux 题里去掉整个 computing_math、去掉需要图形界面软件的题，剩 77 道合格题，覆盖 10 个类别。这就是选题的池子。
  • 推荐哪些？ 从 77 道里挑出 36 道 P1 研究批次，按三种研究价值分组：确定性解析审计、CLI 工具链流水线、调试修复。这三类的判分都可精确验证、轨迹干净、有提分空间，正好服务于攒数据、积累 harness、刷分。剩下 41 道归为 P2 覆盖池。
  • 大概能拿多少分？ 用已跑完的 25 题结果外推：确定性解析审计类多半中到高分（刷分和数据产出最好），调试修复类低到中分（harness 钩子提升空间最大），重型仿真复现类大概率 0 分（卡在环境和算力，不是 harness）。

四、基于已有结果的预判

上一轮 25 题（computing_math + engineering，pi 均分 0.404、gpt_claw 均分 0.399，详见 对比页）给了一个可外推的规律：分数由题型决定，不由 harness 决定。有确定性算法、依赖能装上、判分明确的题拿高分；要跑重型仿真栈或从图像重建结构的题几乎全 0。据此对新批次预判如下。

组对标的已测题（得分）预判分档研究价值
A1 解析/审计k8s_payment 0.90、data_pipeline 0.83、cost_opt 0.86、paper_repro 0.80中到高 0.5–0.9刷分和高质量轨迹产出最好，优先跑
A2 工具链纯算法：branch_bound/ising/k3 均 1.0；重工具链偏低分化：算法高、大流水线中低纯算法题稳拿分，大工具链题考验依赖和长程
A3 调试/修复recsys 0.50、synthetic_causal 0.28、ranking_node 0、sumo 0低到中 0–0.5harness 钩子提升空间最大，是 harness 研究主战场
P2 重型仿真对标 10 道全 0 题（particle_filter、humanoid、mpc、sumo 等）多为 0卡环境和算力，先修环境再谈 harness
怎么把预判用起来。想快速看到分数和攒可用轨迹，先跑 A1；想验证 harness 干预有没有用，重点跑 A3，因为那里基线低、头顶空间大，pi 的预算止损和事实反射钩子最可能把分数从 0 抬到正数；A2 的纯算法题用来确认接线正常（应该稳定高分）。跑一轮先不加钩子拿基线，再加钩子看每题增量，才能把「harness 起没起作用」和「题本身能不能做」分开。这一点在上一轮已经吃过亏：曾把并发和容器修复的收益误记成关图形界面工具的功劳。

五、怎么跑

gpt_claw（无图形界面）跑 P1 批次，配置沿用上一轮全量跑那套已修好、零框架失败的无界面配置：

cd /home/dataset-local/zmh/ALE_TEST/agents-last-exam
# 把实验 yaml 的 tasks 指向 selected_tasks/research_batch_p1.txt
.venv/bin/python -m ale_run run <experiment>.yaml            # gpt_claw
# 对跑：agent 换成 configs/agents/pi_gpt56.yaml，任务集不变，再跑一遍   # pi

并发 4、每题墙钟上限 2400 秒。36 道一轮是数小时量级的 Docker 评测，建议先跑 A1 的 14 道看基线，再决定是否全量。
