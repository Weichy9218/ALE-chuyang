pi 与 gpt_claw 对比：用 gpt-5.6-sol 跑 ALE 25 题（Linux 无界面）

同一个模型、同一批题、同一套环境，两套 agent harness 全量对跑，25 道 Linux 无界面题（18 计算 + 7 工程）。本页先给结论，再给可复核的原始数据和取数脚本。
模型 gpt-5.6-sol 环境 本地 Docker（ale-ubuntu22-docker） 题目 25 道 computing_math + engineering 数据日期 2026-07-12
两套 harness，一句话分清。pi 是约 700 行的薄包装，把 agent 主循环交给外部 pi 编码 CLI，只在 Linux 容器里用 bash 和读写文件，不带图形界面。gpt_claw 是仓库自带的重型框架（从 OpenClaw 改写）跑 gpt-5.6-sol，本轮起在无界面题上关掉全部图形界面工具，只留 exec/read/write/edit，和 pi 站同一条起跑线。pi 薄、快、可复现；gpt_claw 重、带记忆和子 agent，但这些在无界面题上用不上。

一分钟结论

  • 差距大不大？ 得分分不出高下。pi 均分 0.404，gpt_claw 均分 0.399，只差 0.005。而 gpt_claw 把同一批题重复跑，单题得分能差到 0.34。0.005 远小于这个跑间抖动，谁的解题能力更强这批数据回答不了。
  • 分数由什么决定？ 由题目决定，不由 harness 决定。25 题里 18 题两者得分完全相同（10 题都 0，8 题同分），只有 7 题分高低，pi 赢 4、gpt_claw 赢 3，接近抛硬币。
  • 两者什么特点？ pi 输入 token 少、跑得快，但有 5 道题超时；gpt_claw token 和步数更重，但 25 题全部跑完不超时。
  • 测了多少题、怎么分布？ 25 道，18 计算 + 7 工程，全是 Linux 无界面题。两套跑里都有 10 道全 0，卡在环境和难度；有 4 道被跑出满分。
  • 结论靠谱吗？ 成本结论靠谱（pi 更省更快，可复现）；能力排名不靠谱（题只有 25 道，pi 只跑一次，单题方差盖过均分差）。
  • 下一步和怎么协作？ 选题和预判见选题页；哪些东西你能直接拿去用、哪些需要你搭把手，见本页给队友和老师。

「pi 输入 token 少 4 倍」这个说法要小心。pi 的新输入 token 中位只有 22.6k，但它靠大量 prompt 缓存，缓存读取中位 135k，是 gpt_claw（61k）的两倍多。把上下文挪进缓存桶不等于不处理它，两者每题处理的总 token 量其实接近。pi 真正省在缓存 token 更便宜、墙钟更快（503 秒对 687 秒），不是发得少。另一面，pi 有 5 道题跑到超时被判 0，gpt_claw 这 25 题全部在时限内跑完。
gpt_claw 为什么之后一律不带图形工具。核对轨迹后，图形界面工具在无界面题上 25 题里总共只调用 7 次，集中在 3 道题，其中两道无论关不关都是 0 分。它们对无界面题基本是死重量，每次请求还多占约 2.5KB 的工具说明，关掉后输入 token 降约 9%、对得分没有可测影响。真正带来稳定性的是并发从 6 降到 4、以及提高容器就绪超时加重试，这让 25 题从「首轮 5 道崩在容器启动」变成零崩溃、零超时，跟图形工具无关。

结论的可靠性与局限

结论可靠性为什么
无界面 Linux 上 pi 与 gpt_claw 得分打平较可靠18/25 题结果相同，均分差 0.005 远小于 0.16 的跑间抖动均值。
pi 更省、更快较可靠墙钟、步数、token 三个独立指标一致，不受单次得分抖动影响。
某个 harness 解题能力更强不可得题只有 25 道，pi 只跑 1 次，单题方差最大 0.34，样本量和重复数都不够支撑排名。
关图形界面工具提升了得分不成立图形界面工具全程只调用 7 次，关掉只省 token、不改分数。

两处不对称，读数时要记住。一是 pi 只做了一次全量跑，gpt_claw 有 5 道题崩在容器启动后补跑过，所以偏差方向是低估 pi。二是 pi 那 5 道超时题没有第二次机会，gpt_claw 的失败题有。两点都不改变「打平」的结论，只说明这份数据对 pi 略微不利，不是有利。

  • 25 题基线数据和取数脚本。原始 run.json / trajectory.json 路径和一段能复算本页所有数字的脚本见如何自己复核，可以直接拿去比对或接着算。
  • 下一批的选题清单和预判。从 165 道里筛出的 77 道合格题、36 道 P1 研究批次和分组预判在选题页，清单文件 selected_tasks/research_batch_p1.txt。

需要搭把手的

  • 一台带 /dev/kvm 的机器跑 Windows VM。那 4 道 network security 题的官方评测要 Windows 桌面（Ghidra、Wireshark），本地 Docker 起不了。谁有带 KVM 的机器，可以配 Windows VM 加带图形界面的 gpt_claw 跑出官方分数，我这边算法和答案已经现成。
  • 算力或人手把每题重复跑几次。现在单题方差到 0.34，单次跑的均分差被淹没。要真比出 harness 高下，得每题重复 3 到 5 次取均值。谁能分担几轮重复跑，就能把「差异」从「噪声」里分出来。
  • 修那 10 道全 0 题的环境。先从可修的入手，比如 dit_pipeline 是容器缺 DiTTransformer2DModel。补齐环境比调 harness 更能抬整体分数。谁熟某个仿真栈（EnergyPlus、SUMO、mjlab、量子纠错），欢迎认领对应的题。
  • 一起看 harness 干预有没有用。P1 里的 A3 调试修复类基线低、头顶空间大，最适合验证 harness 钩子。跑法建议先不加钩子拿基线、再加钩子看每题增量，才能把 harness 的作用和题本身的难度分开（选题页第四节有展开）。

插曲：gpt_claw 最初 6 题全 0，是一行接线 bug（修复细节）

最早 gpt_claw 6 题全 0，每题 30 轮只发 0 到 1 次工具调用，不停说要做然后道歉。根因是模型循环路由：gpt-5.6-sol 匹配不到专用循环，掉进兜底的 generic_vlm（为 Qwen3-VL 写的循环），该循环把工具塞进 Qwen 的 <tools> XML 而不是发原生 tools 数组，而 gpt-5.6-sol 只会读 tool_calls，于是空说话、不调工具。修复是在 harness/model/unified_loop.py:529 的注册正则里加上 .*gpt-5\.6.*，一行改完它才成了 pi 的正经对手。记这条是因为它说明：评估两套 harness，先排除模型和 harness 的工程性不兼容，否则会把接线 bug 误判成能力差距。

日志根目录 /home/dataset-local/zmh/ALE_TEST/agents-last-exam/.logs/ale/。每题路径形如 <域__题名>/v0/<时间戳>/run.json，取最新时间戳那次。下面这段能复算本页所有均分、中位数和逐题得分。

import json, glob, statistics, os
BASE = "/home/dataset-local/zmh/ALE_TEST/agents-last-exam/.logs/ale"
def latest(root, t):
    c = sorted(glob.glob(f"{root}/{t}/v0/*/run.json")); return c[-1] if c else None
def load(root):
    out = {}
    for td in glob.glob(root + "/*"):
        if not os.path.isdir(td): continue
        rj = latest(root, os.path.basename(td))
        if rj:
            d = json.load(open(rj)); u = d.get("usage", {})
            out[os.path.basename(td)] = {"score": d.get("score"), "status": d.get("status"),
                "in": u.get("total_input_tokens", 0), "dur": d.get("timings", {}).get("duration_s", 0)}
    return out
pi = load(BASE + "/gpt56_full_pi/pi/gpt-5-6-sol")
gpt_claw = load(BASE + "/gpt56_full_aleclaw_v2/ale_claw/openai-gpt-5-6-sol")
print("pi mean", statistics.mean(r["score"] for r in pi.values()))
print("gpt_claw mean", statistics.mean(r["score"] for r in gpt_claw.values()))
