一、这道题怎么评分

读三份 AI 治理文件的缓存全文，按立法性质、技术范围、生命周期三套分类法打标，每个判 TRUE 的标签要配一句能在原文里逐字找到的引文，再产出一个跨文档矩阵和一段 150 到 300 词的缺口分析。交付物是单个 output/agent_output.json。

评分对照两名人类评审的共识标签算 F1。有两个结构性的杠杆：

机制规则后果
矩阵封顶隐藏评分器要求 cross_document_matrix.legislative_status 的形状是 {"Hard Law": {文档号: 布尔}}，不合格则 matrix_valid=false总分被 REQUIRED_ARTIFACT_CAP 封在 0.69
引文闸门单个文档的引文逐字命中率达到 0.8 给 1.0，否则给 0.5，这个系数同时乘到该文档的立法性质、技术范围、生命周期三项上一份文件的引文质量能撬动它的全部得分

base 在这两处都失手：矩阵写成了 {文档号: "Soft Law"} 这样的字符串映射，两次 base 运行都是 matrix_valid=false；2047 号文件判成 Other（参考是 Hard Law），配的引文只有几个词，压在闸门下面。

两次改动的价值差一个数量级。把第三十步那次改回去、其余不动，重跑评分器得 0.4995，回到 base 水平；也就是说这次没人要求的复核值 +0.185。而按反馈重构矩阵那一次，在这一轮甚至没能解除封顶，因为 verifier 允许的 hard_law 蛇形键名不是评分器要的 "Hard Law"。

四、第三轮：verifier 什么都没测出来，agent 照样改

第三轮的六条检查全部执行失败。agent 在第 36 步调用 verify，第 37 步收到的是六条执行错误加三条覆盖缺口，正文里明确写着：

EXECUTION ERRORS (the Verifier could not produce a verdict; not scored) … Execution errors and coverage gaps require no action.
— trajectory.json，步 37 的反馈正文

第 38 步 agent 立刻把矩阵重写成按标签分组的布尔行，并且这次用的是精确显示名 "Hard Law"，正好是评分器要的形状；同时对所有引文做了一遍逐字断言。把这次改动还原回去重跑评分器，分数从 0.7059 掉到 0.69，正好落在封顶线上。这次改动值 +0.0159。

这是「零信息量的 verify 调用本身也改变行为」的直接证据。verifier 没有给出任何有效测量，只是让 agent 知道有人在测量，agent 就自己回去复核了产物形状。

六、这道题说明什么

提分的不是被指出的那个问题。第一轮里，按 verifier 反馈修好的矩阵值 +0.016，而 agent 在全部通过之后自发做的标签复核值 +0.185。第三轮里 verifier 一条有效测量都没有，分数反而最高。三轮合起来看，起作用的是「有人会检查我的产物」这个预期，不是检查的具体内容。

verifier 的判读和隐藏评分器只是部分重叠。第一轮 verifier 明确允许蛇形键名，评分器要的是显示名，agent 照 verifier 的话做，矩阵仍然不合格。冻结检查建立在对公开材料的阅读上，而评分口径有一部分只存在于隐藏参考里，两者的重叠区就是 verifier 能帮上忙的全部范围。

这题的效应大，是因为它有杠杆。矩阵形状是封顶开关，引文闸门是乘数，两个都是全局性的。改对一处，分数动 0.2。多数题没有这种结构，所以不能把这题的幅度推广到 26 题平均。
