一、这道题怎么评分

交一个 output/submission.csv，53 个辖区各四个预测跨度，共 212 行，每行给点预测和 95% 区间。评分是把加权区间分数折算成 0 到 1：score = 1 − 平均WIS / 389.80，分母是朴素基线的成绩。

这是五道题里唯一一道分数连续的题，没有台阶，改动多少就反映多少。WIS 同时惩罚点预测偏差和区间宽度：区间太窄，真值落在外面要重罚；区间太宽，本身也要罚。base 长期的问题是区间偏窄，95% 区间的实际覆盖率只有 0.6875。

五、这道题说明什么

一份全绿的报告也会改变行为。六条检查没有提供任何新信息，agent 却在收到报告后立刻做了一件它在 base 臂里从没做过的事：跑留出回测。base 臂写完 CSV 后只做了一次结构自查就结束了。

这类增益无法归因于测量内容。如果价值来自「知道会被测量」而不是「测量说了什么」，那么一句提交前自查的提示可能拿到同样的效果，而不需要构建和冻结整套测试。配置里的 writer_self_review_hint 就是为验证这一点准备的对照臂。

连续分数的题更容易看清效应。这题没有台阶，所以 +0.034 和 +0.022 的拆分是可信的。台阶式的题上，同样大小的行为改变可能完全不反映在分数上，也可能被放大成 0.2。
