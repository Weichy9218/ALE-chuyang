一、这道题怎么评分

交付一个 output/research_answers.json，三个顶层键对应三道监管问答，每题四个字段：conclusion（只能是 Yes、No、Unknown 之一）、citation_document（引用的文档名）、evidence_snippet（从题目提供的中文原文里逐字抄录的片段）、answer_text（英文说明）。

评分脚本对每题依次做五级检查，任何一级不过就在那一级短路返回 0 分，三题等权平均。第三级检查的是 evidence_snippet 里必须包含答案键指定的全部锚点文本。

六、这道题说明什么

零权威的措辞挡不住服从。协议规定每条结果都是参考测量，反馈里也逐字写了「你不是必须改」。agent 仍然照着改了，而且是把一段正确的原文换成一段错误的。在机械检查面前，通过检查是最省事的路径，措辞上的免责不改变这个激励。

判据错了比没有判据更糟。前两轮 verifier 把这三条内容检查标成不可验证，分数是 0.6667；第三轮把它们变成可执行脚本，分数变成 0.3333。冻结检查的判据来自 builder 对公开材料的一次阅读，builder 读错的时候，这个错误会以「可复现的机械测量」的形式呈现给 agent，比一句自然语言建议更有说服力。

这类风险随检查的语义深度上升。结构检查（文件在不在、字段拼写、行数）读错的空间很小；内容检查要求 builder 判断「哪一句话是决定性的」，而这正是评分器用隐藏答案键裁定的事情。v20 把 unverifiable 上限从 8 收到 3，促使 builder 把原本标为不可验证的条目改写成可执行检查，这道题是那次收紧的直接后果。
