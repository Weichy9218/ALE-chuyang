Harness Analysis — prep 与 verifier 实验总览

base agent = ale-claw · 模型 openai/gpt-5.6-sol · 26 题 (research_batch_wcy) · 更新 2026-07-23

一句话在 base agent 上加了两个可选增强——prep(解题前先跑通运行时、跑一遍核心步骤、补外部事实) 和 verifier(对产出做一次基于公开材料的机械检查)。本页汇总:它们怎么做的、我跑了哪些实验、26 题上的结果、以及现在的瓶颈。

三条结论 ① 消费轮发现两个倒扣 bug(verifier 过度对冲、prep 锚定),已修复并在 13 题上验证——先前所有负向题都回到 base 或以上。 ② 修复只到"去掉害"为止:prep/verifier 净分都 ≈ base,"高于 base"在这套题上测不出。 ③ 真正的瓶颈是评测:得分由逐字原文抄录 + 有时写错的 label + 二值门槛决定,而这三样恰是 prep/verifier 够不着的面。

怎么读这页下面依次是:实验时间线 → prep/verifier 最新实现 → 26 题完整统计 → 价值案例研究 → 关键发现 → 评测层问题(为什么净≈base) → 深入入口 → 附加实验。 逐题深挖走 verifier/、prep/,或 task_analysis/(每题 base 失分归因)。

2 · prep 与 verifier 最新是怎么做的

prep 解题前

一个看不到 writer 的子 agent,在 writer 开跑前做三件事(按价值排序):

  • 跑通运行时:装依赖、起服务、找对入口,把 sandbox 留在可用状态。
  • 跑一遍核心步骤:把这题的机械核心(解析/建模/转换)在真输入上跑一次,报告哪里崩(原始报错)。
  • 补外部事实:公开材料没给、writer 推不出的官方映射/规则,附来源引原文;优先给可调用的 artifact 而非散文。

硬边界:不产出交付物、不定 label/值/格式、不检查 output。闭卷纯文本题 → not_needed 不注入。

verifier 解题中/后

一个独立 agent 从公开材料冻结一组可执行检查;writer 可调 verify 跑,提交后再跑一轮。

  • 每条结果是 pass / fail / unverifiable(公开材料无法测)+ 原始输出,无否决权,writer 自行决定改不改。
  • unverifiable 单列进中性段,明写"不是存疑信号、别因此改答案"(这是本次修复的核心)。
  • 机械层能测:契约/格式/逐字引用一致性;测不了:预测精度、评语措辞、标签口径(公开材料无判准)。

设计文档:PREP.md · VERIFIER.md

4 · 找价值案例:一个诚实的负面结果

本想挑几道题证明 prep/verifier 的价值。结果是:消费轮里看着像"价值"的题,换一次抽样(最新代码 clean3)基本都塌了。这本身是最有说服力的发现。

消费轮的"价值"没能复现(都是 n=1):
题base消费轮最新一抽(clean3)
AGORA(曾当作 prep 价值样本)0.525prep 0.621prep 0.359(跌破 base)
TCGA(曾当作 verifier +0.16)0.840verif 1.000verif 0.840(=base)
SEC 10-K(曾当作 verifier +0.06)0.686verif 0.745verif 0.682(≈base)

诚实的结论:

  • prep:没有可复现的、高于 base 的价值。 唯一看着像的 AGORA(消费轮 0.62),复现抽样掉到 0.36(base 带 0.48–0.69,抖动本就极大)。prep 在 variant/flusight/pe 上的"正"其实是修复把锚定倒扣去掉、拉回 base,不是超过 base。——所以不硬说 prep 有价值:这套题上测不出。
  • verifier:有一点、但很小、且未坐实。 净 +0.01;AGORA 是唯一两抽都高于 base 的题(0.71 / 0.65 vs base 0.53)——可能是真效应(机械层抓契约/证据一致性),但幅度小、n=1 无法确认。
  • 唯一稳的价值是"别帮倒忙": verifier 修复后不再把 sse 答对的 q3 改错(0.333→0.667,轨迹确认);prep 修复后不再用锚定 note 把 variant 带进坑(0.794→0.999)。这类"去掉倒扣"是确定的;"加分"不是。
为什么会这样(§6 详):台阶式分数 + n=1 + 巨大 base 抖动,让单题效应基本是"落在哪一档"的抽样。得分又由逐字抄录 + label + 二值门槛决定,恰是 prep/verifier 够不着的面。所以净≈base 不是"刚好抵消",而是"这套评测分辨不出 prep/verifier 的真实效应"。

5 · 关键发现

  • 两个倒扣 bug 都真实且机制清楚。 verifier 在 sse 把答对的 q3(No)因 unverifiable 信号改成 Unknown → 0.667 掉到 0.333;prep 在 variant 把没解决的断点标成"头号难题"锚定 writer → 0.930 掉到 0.794。
  • 修复生效(fixval13)。 先前所有负向题回到 base 或以上;两个 headline 在轨迹里确认(verifier 出现中性 NOT TESTABLE 段、不再改 q3;prep 无锚定 note 送达)。
  • 但只到"去掉害"。 修复后 prep/verifier 净分 ≈ base。prep 唯一稳定加分的存在证明是 agora(findings 恰好命中评分维度),靠碰巧不是机制。
  • 已收回的旧 insight。 早期"verifier 总分 +0.099 增益"是测试集校准出来的,三轮独立复现把它压回噪声(约 +0.009);"prep 效应"一度其实只是"报告有没有送达"的二值 bug,已修。

6 · 为什么"有没有用"测不出来——评测层的问题

不是协议不行,是这套题的信噪比太低,且得分面与 prep/verifier 的作用面几乎不重叠:

  1. 逐字原文抄录打分:证据题要求一字不差粘上带指定 anchor 短语的中文原文,每题分数变成"这次抄没抄全"的硬币,压过推理质量。(sse 的 prep 0.333 就是抄漏一句 anchor,与修复无关。)
  2. label 与题面/键错配:sse q2 金标准 Unknown、题面像是非问句、模型恒答 No → 永久失分,base 十次全错。这是任务缺陷,不是模型能力。
  3. 二值全或无门槛:5 道零分题都是差一点就归零(缺一项检查 / SSIM 0.61<0.95 / R 版本 RNG 差一行)。几乎无部分分,消费层增强跨不过。
  4. n=1:一次 0.333↔0.667 就是一次伯努利抽样;台阶式分数让单题 delta 是"落在哪档"而非"改进多少"。
  5. 干预面 ≠ 测量面:prep/verifier 作用于运行时/断点/反馈,分数由 label+逐字抄录+格式决定,两个面几乎不重叠——所以实验主要能测出有没有害,测不出有没有用。

要往下走先修评测:证据打分改 anchor/语义命中而非逐字全文、二值题给部分分、修 q2 类 label 错配、关键题上 k 重复。

端点与 thinking summary(基建)

  • boyue 带 thinking 跑不了这个 agent:其 gpt-5.6-sol 在 /v1/chat/completions 上不支持"工具+思考"(要 /v1/responses),而 harness 主循环走 chat completions。要用 boyue 带 thinking,需把主循环接到 Responses API(CUA 已有 loops/openai.py,中等改动)。
  • 顺手修好一个隐藏 bug:主循环原发 Responses 风格 reasoning={...} 却跑在 chat 上,haoxiang 因此一直不回 reasoning_content、thinking summary 被静默丢弃。改成 reasoning_effort(thinking.py)后 summary 被正常捕获并跨轮重放(已验证)。净改进,已保留。
