prep 消除了 base 的一个真实失败模式，同时又制造了一个小的新失分，净效应为正。这是唯一一道 prep 的收益能追到具体领域判断的题。

一、base 的失败模式

按简报圈定受众，交三个文件。评分权重最大的是名单本身（35%）和资格标记（20%）。

简报说，跨渠道推广要排除 email_opt_out = 1 的客户，前提是推广内容涉及邮件；而治理配置说这些客户不进邮件渠道，短信和推送各有自己的开关。推广创意的具体内容题目没给。

这个条件句有两种读法。base 七次运行里有四次读成了无条件排除，名单从 449 人变成 427 人，代码注释里写得很清楚：

# …cross-channel campaign, so honor the
# brief's exclusion of email opt-outs from messaging referencing email.
& profiles["email_opt_out"].eq(0)
— base 臂某次运行的第 16 步

这四次的分数是 0.7245：受众统计整项判零，名单准确率掉到 0.951，重叠计数掉到 0.5。

二、prep 说了什么

Observation：The brief excludes email_opt_out = 1 from cross-channel messaging only when that messaging references email content. The YAML independently says such customers are excluded from email channels, while SMS and push exclusions are based on their own opt-in fields.
Do not infer：Email opt-out alone is not stated as an unconditional SMS or push opt-out.
— task_prep_meta.json，第三轮 findings 第 4 条

清单第 6 条同样点名了这件事，并写明「不要把它悄悄重新解释成无条件的短信与推送排除」。

writer 读了报告（第 1 步就读），第 7 步一次执行就把两个数都算了出来：符合条件的 449 人、扣掉 email_opt_out 后的 427 人，然后选了 449。prep 臂七次运行里有六次拿到受众统计满分和名单满分，base 七次里只有三次。

三、prep 同时制造的新失分

writer 把这个条件性假设写进了 segment_definition.json 的 suppression_rules 字段：

{"field": "email_opt_out", "operator": "=", "value": 1,
"reason": "Conditional: suppress from cross-channel messaging only when creative references email content; this SMS/push roster assumes the creative does not reference email."}
— prep 第三轮的 output/segment_definition.json

问题在于评分器对这个字段做的是集合相等比较，参考答案里只有一条抑制规则。多写一条就不相等，这一维从 3/4 掉到 2/4，扣 0.0375。名单本身没受影响，仍然是正确的 449 人，所以这纯粹是元数据与产物不一致。

prep 让 writer 把「我做了一个假设」显式写下来，这在工程上是好习惯，在这个评分器面前是失分项。清单没有说明哪些字段会被逐项比对。

相对同期 base 的那一次（0.9042，恰好是 base 做对的那次）prep 是 −0.0375；相对 base 七次的历史均值 0.8117，prep 是 +0.055。两个方向都对，取决于拿哪个 base 比。这道题的 base 是双峰的，用单次运行做对照会得出相反的结论。

还有一处所有臂都失分：filter_predicates 的运算符，参考答案写 ==，所有 agent 都写 =。prep 的清单第 3 条把这个条件复述成 email_opens_30d = 0，等于把错误写法固化了下来。

五、这道题说明什么

prep 在这里做了它设计上该做的事。它读出了简报里的条件句，指出了两种读法的分歧，给了理由，并声明了边界。这消除了 base 一半运行里出现的真实错误。

但它同时把 writer 推向了一个评分器不喜欢的表达方式。把假设写进产物元数据是合理的工程习惯，而评分器做的是集合相等比较。清单能点名「要写什么」，点不出「哪些字段多写会扣分」。

base 双峰意味着单次对照不可靠。这道题拿哪一次 base 做基准，结论就是相反的。用多次运行的均值才能看出 prep 是把成功率从 3/7 提到 6/7。
