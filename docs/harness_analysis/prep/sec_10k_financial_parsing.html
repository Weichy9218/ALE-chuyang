一、base 丢的这 25% 和内容无关

这题要处理 100 份 10-K：每份抽一个归一化 JSON 和一份原始文本证据，再回答三道分析题，最后对 5 份做第二遍抽取验证确定性。分析题这一项权重 25%。

base 的三道分析题答案本身几乎全对：Q1 的股票代码和涨幅与参考一致，Q2 差 0.03 落在容差内，Q3 的排序与后来拿高分的那一版完全相同。它拿 0 分的原因只有一个，外层容器写成了列表：

base 的 qa_answers.json0.0

  • [ {"id":"Q1", "answer":{…}}, … ]
  • 照着输入文件 questions.json 的样子写，那个文件本身就是列表
  • 评分器用 predictions.get("Q1") 取值，列表取不到，三题全判 0

prep 臂的 qa_answers.json0.9926

  • {"Q1":{…}, "Q2":{…}, "Q3":{…}}
  • 以问题编号为键的对象
  • 三题全部命中

题面从未规定这个外层容器。输入文件是列表，评分器要对象，两个信号互相矛盾，而只有后者算分。

二、prep 说了什么

第二轮 prep 的第四条 finding 直接点在这里：

Observation：questions.json defines IDs and answer object formats, but neither it nor the prompt defines whether qa_answers.json is an object keyed by ID or a list of records.
Writer action：Choose one clear, consistent representation preserving Q1/Q2/Q3; an object keyed by those IDs is the least ambiguous.
— task_prep_meta.json，第二轮 findings[3]

其余三轮都没有这条 finding。它们只在清单条目的备注里两边放行，例如第三轮写的是「self-check 接受以 Q1/Q2/Q3 为键的对象，也接受带 id 的记录列表」。self-check 脚本的源码确实两种都放行，所以起作用的不是脚本，是这句建议。

环境这一维 prep 的边际价值是零。prep 花力气跑通了带锁定依赖的 Python 3.10 环境并写进报告，而 base 从没调用过那个包装脚本，直接用 pdftotext -layout 批量抽文本；prep 臂虽然按建议用 pdfplumber 起步，但嫌慢也杀掉进程换回了同一条命令，最终两臂抽出来的文本逐字节相同。

五、这道题说明什么

prep 在这里的作用是替 writer 押了一注，而不是提供了知识。题面对容器形状没有规定，两种写法都说得通，base 选了输入文件的样子，prep 建议选另一种，隐藏评分器认后者。押对了就是 +0.25。

同一份报告里，这条建议和那些扎实的领域条目长得一样。它有来源、有 writer_action、有边界声明，格式与「八个货币字段必须是原始美元整数」这类真正从题面推得出来的条目没有区别。writer 无法从形式上分辨哪条是推论、哪条是猜测。

这也是为什么这道题的 +0.26 不能当成 prep 的一般收益。换一道题、换一个没规定的点，同样的机制可能反向，变异注释那题就是反向的例子。
