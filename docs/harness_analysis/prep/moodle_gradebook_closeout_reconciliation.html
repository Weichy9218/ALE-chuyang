这道题看上去有一个可复现的 prep 伤害：两轮都是 −0.0487。实际上 prep 什么也没做。两臂的产物在语义上逐字节相同，分差全部来自 241 个回车符，而这个差异 base 自己也会时有时无。

一、先看结论：产物没有语义差异

这题要交 13 个文件，其中两个藏在打包文件内部，评分器对它们做的是read_bytes() 逐字节比较，不一致各扣 4 分和 2.5 分。

文件参考baseprep 第一、二轮prep 第三轮
integration/id_map.csv7972 字节，LF 换行8213 字节，CRLF8213 字节，CRLF7972 字节，LF
gradebook/final_grade_flags.csv3183 字节，LF3424 字节，CRLF3424 字节，CRLF3183 字节，LF

把回车符归一化之后，四个臂与参考答案全部逐字节相同。也就是说所有臂的内容修复都是完全正确的，差别只有 241 个 \r。

原因是 Python 的 csv.DictWriter 默认用 \r\n 结尾。拿到 0.95 的那些运行显式写了 lineterminator='\n'，拿到 0.885 的没写。这是一个与 prep 无关的写法习惯。

二、那 −0.0487 是怎么来的

配对统计用的 base 是历史多次运行的均值 0.9337，而这道题的 base 只有两个可能取值：0.885 和 0.95。均值 0.9337 由 {0.95, 0.885, 0.95, 0.95} 混出来，本身不对应任何一次真实运行。

所以「两轮完全相同的可复现伤害」这个读数是真的，可复现的东西也是真的，只不过可复现的是 csv.DictWriter 的默认行为，不是 prep 的作用。同期 base 与前两轮 prep 分数完全一样，配对差是零。

三、第三轮拿最高分时，报告没送到

第三轮 prep 的分数是这道题所有臂里最高的 0.95。而这一轮注入给 writer 的提示块结尾写着：

The full report could not be staged as a file, so only the runtime state above is available.
— 第三轮 writer 的首轮提示

整个运行的轨迹里，PREP_REPORT 出现 0 次，task_prep 出现 0 次。writer 只用到了 prep 建好的运行时环境，17 条清单和 self-check 一条都没收到。

这不能证明清单有害，因为 0.95 的来源是那一行 lineterminator。它能说明的是：清单在这道题上的边际贡献不为正。

报告送不到是一个 staging 缺陷：报告目录过去只在写 artifact 时才创建，没有 artifact 时目录不存在，写报告直接失败，而 prep 仍被记为成功完成。缺陷已修复并加了回归测试。

四、prep 的清单点名了正确的文件，但没点到要害

三轮清单都点名了这两个文件。第一轮第 3 条写着「打包文件内部只有policy.json、section_cutoffs.json、final_grade_flags.csv、id_map.csv 可以不同」，第 7 条还给了一条断言命令用来核对映射内容。

但三轮清单里没有任何一条提到行尾字符或字节级一致性。清单说的是「哪些行、哪些值」，评分器比的是字节。这与 AGORA 那题是同一类盲区：清单覆盖了公开材料能推出的部分，而失分点在推不出来的那部分。

五、这道题说明什么

用历史均值做基准会把台阶式的分数读成组件效应。这题只有两档分数，均值落在两档之间，于是任何一次落在低档的运行都会显示成「相对 base 下降 0.0487」，无论那一臂做了什么。同期单次对照能立刻看出配对差是零。

可复现不等于有因果。两轮完全相同的负值很有说服力，但它复现的是一个与实验变量无关的默认行为。判断组件效应需要看产物差异，不能只看分数。

这也是把这道题放进这组的理由。它是一个反面样本：如果只看分数表，会得出「prep 在 Moodle 上稳定有害」的结论，而实际上 prep 在这道题上既没帮忙也没添乱。
