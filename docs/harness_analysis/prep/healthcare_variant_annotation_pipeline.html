一、这道题怎么评分

把一份 VEP 注释快照变成可报告变异表，交四个文件，其中 annotated_variants.tsv 50 行、reportable_variants.tsv 参考是 3 行。

评分按项累加，其中两项是这次分差的落点：

评分项满分判定
max_population_af10逐行 0.2 分，50 行
reportable20全有或全无：可报告表要逐行相等，且 50 个可报告标志全对

可报告的规则写在可见的 input/source_manifest.json 里：「对提交的 ALT 等位基因，取所有可用频率来源中的最大数值」，以及「最大群体频率缺失或低于 0.01」。

二、prep 说了什么

第一轮 prep 的第五条 finding，标题是「删除变异的频率等位基因归一化」：

Observation：For three deletion records — chr1_979034_CGAA_C、chr1_1387763_CCT_C、chr1_1629572_TG_T — the colocated frequency mappings use '-' as the alternate allele key rather than the literal submitted ALT.
Writer action：Resolve the VEP-normalized alternate allele for indels before collecting frequency values; a literal frequencies[submitted_alt] lookup would incorrectly treat available data as missing.
— 第一轮 PREP_REPORT.md 的 findings 第 5 条

这条断言听起来完全合理，还点名了三个具体的变异编号，并且附了边界声明「这条归一化事实不决定最终的频率取值或可报告标签」。第三轮换了个例子（插入变异 allele_string '-/C'）说同一件事。

第二轮的 finding 恰好说了相反的话，而且是对的：「Match the submitted ALT from variants_to_annotate.tsv … For frequencies, inspect only frequencies[ALT]」。第二轮的报告没送到 writer 手里，所以这条正确的建议没起作用，分数是 0.999。

三、base 自己做对了

base 的 pipeline.py 在这一点上是有意识地区分的，代码里还写了注释：

# Frequency/ClinVar rules are explicitly keyed to the submitted ALT
# from the staged variant list (rather than to other alleles present
# in a multiallelic colocated record).
af, clinvar = population_af_and_clinvar(response, alt) # 用原始 TSV 的 alt
— base 臂 output/pipeline.py

同一份代码里，base 在选转录本时用的是归一化等位基因，取频率时用的是原始 ALT。这正是参考答案要的做法。prep 的建议是把两处统一成归一化等位基因。

顺带一提，这道题历史上被认为需要 prep 补充的那条外部事实（Ensembl 的 consequence 严重度排序）四轮都交付了，而 consequence 这一项在包括 base 在内的所有臂上都是 50/50 满分。base 自己就写出了完整的官方排序表。这条 finding 的实测边际价值是零。

错的三行正是 prep 那条 finding 点名的三个删除变异。参考答案里它们的频率是 NA，按 prep 的规则查出来分别是 0.01059、0.8255、0.4747。

五、self-check 给了假信心

第一轮交付了 self-check 脚本，writer 跑了，全部通过。脚本的 covers 字段自己写明了测不了什么：

It explicitly cannot determine annotation correctness, submitted-allele matching correctness, consequence/ClinVar priority correctness, reportability-rule correctness…
— 第三轮 task_prep_meta.json 的 self_check.covers

更值得注意的是 writer 之后做的事：它自己写了一段断言，确认「输出的 AF 等于按归一化等位基因查到的最大值」。这段自检验证的是它有没有忠实执行 prep 那条错误指令，执行得越忠实，断言越通过，分数越低。

六、这道题说明什么

prep 报告里的断言，写得越具体越危险。这条 finding 点名了三个变异编号、解释了机制、还附了边界声明，形式上比一句泛泛的提醒可信得多，而它是错的。writer 没有理由怀疑它，因为报告里所有条目看起来都一样可靠。

base 在这道题上不需要帮助。它自己写出了官方严重度排序，也自己做对了归一化等位基因与原始 ALT 的区分，拿 0.999。prep 的介入把一个已经做对的地方改错了。这是 prep 边际价值为负的干净例子。

同一份报告的两轮给出了相反的建议。第一轮和第三轮说用归一化等位基因，第二轮说只查原始 ALT。prep 每轮独立读一遍公开材料，在没有判准的地方，它的结论本身就是随机的。
