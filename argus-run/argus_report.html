四、系统架构与执行流程

Argus 本身不持有模型,它编排四个角色,每个角色是一次 codex exec 子进程。整套 harness 装进评测 VM 内运行,所以题目要求的精确输出路径就是本地真实路径。ALE 评测框架把它当一个普通 agent 调用:

ALE 评测框架 ale_run run exp.yaml
按配置解析 harness "argus" → ArgusDeployer;executor 固定为 sandbox(in-VM)
▼ 起评测 VM(Docker)· ship ale_run 源码 + argus wheel 进沙箱
ArgusDeployer.install(VM 内)
装 pinned codex CLI + argus_skill wheel + cua MCP 桥;断言 ale_last_exam vertical 可加载
▼ 把 ALE 题面写进 prompt,拉起 launcher 子进程
_launcher → LifeSupervisor(VM 内)
题面播种为 mission objective,进入四角色循环,受 max_missions 约束
▼
四角色循环 —— 每个角色 = 一次 codex exec,共享 128k context 预算
Manager
定 vertical、划分执行 stage、把关能否推进
→
Planner
拆解目标为任务、判定完成门(Goal Gate)
→
Engineer
用 codex shell 读输入、写代码、跑、把产物落到精确路径
→
Reviewer
独立核验产物是否满足题面每条要求,不过则回退重来
▼ 产物落 output/
回收与评分
角色事件日志 → trajectory.json;evaluate() 读 output/ + 隐藏 reference → 分数 → run.json
相对单角色 agent,Argus 多出的是 Engineer 写完后由 Reviewer 独立复核、以及 Manager/Planner 的分阶段把关。 代价是每题约 8 倍的 token(多角色编排的固有开销)。

五、结果分析

  • 强项: 物理科学 0.74、交通安全 0.82、商业金融 0.62、计算数学 0.58 —— 数值计算、数据处理、金融重构类任务完成度高,28 题满分集中在有明确可验证产物的题目。
  • 弱项: 工程 0.24、心理神经 0.19 —— 需要重型工具链或长流程的题(如 ASIC 布局布线、控制器综合、影像分割)常跑完整流程仍拿不到分,是能力边界,不是执行故障。
  • 零分构成: 31 个零分中,绝大多数是跑完整循环、产物不达标的真实 0(能力结果);少数是重型任务在评测时限内没能产出交付物。
  • 成本: 全程输入约 5.5 亿 / 输出约 850 万 token,人均约 550 万 / 8.4 万。

  • 模型 gpt-5.6-sol,四角色 reasoning effort 全 high/xhigh,context 预算 128k。
